# E6o — длинная книга: все главы + проверяемая RPG

## Границы версии 0.3.0a18

Этап сохраняет ответственность: ChatGPT Skill — автор художественных решений; Python — индекс, приватная очередь, проверка цитат и компилятор; Dart — **единственный** исполнитель правил и SQLite, Flutter — один из клиентов. `main`, PR #133 и native packages не изменяются. В текущем BookWorld v4 предел 1024 сцены, 32 акта (2–128 событий на акт), 512 решений в проверяемом маршруте. Поэтому первая честная зона поддержки — **193–384 главы** в одной игре. Книги длиннее 384 главы не обрезаются; выдаётся код `long_book_requires_volumes`. Отдельное деление на переносимые тома требует следующей архитектурной приёмки.

## Одно авторство вместо гигантского запроса

1. Все главы FB2 разбиваются индексатором на проверяемые части и сохраняются приватными checkpoint. Если одна глава не имеет ни одного NARRATED свидетельства, генератор не подделывает событие — отклоняет такой источник для полного покрытия.
2. Для каждой последовательной группы **8 глав** ChatGPT получает локальное отдельное задание `chapter_outline_wXXXX_YYYY`. Оно включает исходные проверенные утверждения, точные цитаты, неопределённости. Ответ обязан разобрать ВСЕ главы и явно распределить КАЖДОЕ NARRATED-событие на `featured_assertion_ids` (1–3 лучших факта/главу, предназначены для реальных игровых сцен) или `deferred_assertion_ids` (явно отложены с обоснованием). Никакие события не теряются молча. Каждый ответ и exact hash исходного окна закреплён в приватном `chapter_outline_*.json`, переживает перезапуск и включается в `snapshot-private`.
3. Из компактных литературных сводок навык составляет **полноценно играбельный каркас StoryPlan v1** из не более 192 сцен с прямыми SOURCE_PASSAGE-переходами между узлами не более чем через 96 глав. Обязательны реальные, не выдуманные цитаты из *своих* глав для опор первого и последнего эпизода и две разные достижимые концовки. Этот каркас **не объявляется полной игрой**.
4. Навык разрабатывает reviewed `v4_acts` внутри исходных переходов. Каждый пропущенный номер главы получает SOURCE_PASSAGE-событие, каждая отобранная цитата обязана присутствовать в нативном BookWorld, каждый акт имеет проверяемые причинные последствия и реальный выбор. NPC Social v5, knowledge и item custody сохраняют действующий source-locked контракт, но для длинного тома пока ограничены выбранным проверенным базовым составом персонажей: полнота всех второстепенных NPC не сертифицирована.
5. Dart importer/LocalRpgGameApi/SQLite и E6n gate проверяют реальные игровые маршруты, подтверждают достижимость хотя бы одной SOURCE_PASSAGE-сцены из **каждой** главы в объединении маршрутов, два различных финала и переносимое сохранение. На случай очень сложного графа превышение лимита BFS означает НЕТ ДОКАЗАТЕЛЬСТВА, не PASS.
6. Отложенные `deferred_assertion_ids` остаются в приватной литературной матрице; в `WORKDIR/long_event_coverage.json` явно указывается их количество. Нельзя утверждать «адаптированы все события» при ненулевом количестве отложенных фактов. Даже ноль не гарантирует художественной полноты, пока независимый читатель не сравнил оригинал и игру.

## Единая функциональная приёмка

Оригинальная синтетическая FB2 с **201 главой** и **197 добавленными событиями в 3 актах**. 201 отдельных анализа + 26 проверяемых окон + база из 5 сцен + NPC abstention + typed-правила + native v4 compiler + Dart importer/LocalRpgGameApi + поиск двух финалов + SQLite. В автоматических тестах — отказы на пропущенной главе, подмене авторства цитат, изменённой опоре, скрытом исходном событии и подмене сохранённого ревью. **Synthetic fake author не является настоящим ChatGPT литературным E2E.** Приёмку не объявлять до SUCCESS обоих заданий GitHub Actions на одном точном SHA.

Открытые задачи: настоящие две разные русские FB2 и независимый литературный разбор, многотомная архитектура книг >384 глав, публичный общий API передать коллекцию томов без потери NPC-истории, реальные физические Win/Android игровые проходы. Не отправлять частные исходники в GitHub Actions.

**Уточнение по плотным исходникам:** 8 глав — максимальный размер окна. Если 8 глав вместе превышают проверяемый бюджет JSON задачи, автор автоматически сокращает окно до 7…1 главы, сохраняя все цитаты и исходный порядок. При переполнении одной главы возвращает `long_book_single_chapter_over_budget` и требует отдельный проход по частям главы; никаких скрытых обрезаний. При числе глав >384 отказ происходит до дорогой очереди анализа, чтобы не тратить ответы ChatGPT на неподдерживаемый единый мир.
