# AI Story RPG — единый авторский процесс из всей книги

**9 ноября 2026 · одна цельная поставка после принятого E6k/complete-game · внешний генератор**

## Что теперь делает программа

CLI `author-book` объединяет до сих пор разрозненные шаги:
1. Читает приватный FB2/TXT, индексирует всю книгу и продолжает существующий проект,
   не повторяя уже принятые фрагменты. Не переписывает исходники/контрольные точки.
2. Отправляет каждый фрагмент выбранной модели **только с явным разрешением**
   либо принимает приватные ответы от ChatGPT через JSON inbox без сети.
   Любая модельная цитата обязана совпадать с точной подстрокой исходника;
   UTF-16 координаты и assertion_id создаёт сама проверяющая программа.
3. На основе подтверждённых глав предлагает StoryPlan с двумя финалами,
   русское оформление Героя/Предметов/Знаний/Действий и v4-многоактовые события.
   Каждый слой подтверждается EXISTING валидаторами; ошибочные ответы
   запрашиваются повторно, не становятся игровыми фактами.
4. Реальный standalone Dart `story_authoring` собирает private .bworld v4.
   Новый headless Dart-клиент `discover_routes.dart` действительно открывает
   состояние игры через `LocalRpgGameApi`, исследует доступные решения
   и находит ДВА различных достижимых игровых терминала без Python-копии движка.
5. Независимый литературный проход проверяет все сцены, последствия,
   шесть видов согласованности и оба найденных нативным API маршрута.
   Подписанные SHA цитат и происхождение SOURCE_PASSAGE/EXPLICIT_ADAPTATION
   не берутся из ответов модели: их копируют только из проверенного BookWorld.
6. Уже принятая `finalize_extended_campaign` повторно проходит оба маршрута
   с настоящими правилами, проверяет SQLite и переносимые сохранения.
   Лишь после SUCCESS записывает `.bworld`, `.attribution`, `.readiness`.

Никакие правила предметов, квестов, причинности, памяти NPC и сохранений
не переносились в Python, Flutter и основной PR #133 не редактировались.

## Пример единого запуска с Z.ai

Для облачного ИИ нужно использовать **свой приватный ключ**:

```bash
export ZAI_API_KEY='ключ_только_в_окружении'
python3 -m tools.rpg_author author-book \
  --book /private/novel.fb2 \
  --project /private/novel-project \
  --workdir /private/novel-author \
  --output /private/novel-game.bworld \
  --provider zai \
  --model glm-4.7-flash \
  --allow-cloud-book \
  --delegate-review
```

Опция `--allow-cloud-book` означает разрешение отправлять фрагменты
частной книги на Z.ai. Без неё запрос не отправляется. Модель по умолчанию
`glm-4.7-flash`, адрес *обычного API*, не Coding Plan:
`https://api.z.ai/api/paas/v4/chat/completions`.
При 429, 408 или временных 5xx выполнится ограниченное автоматическое
повторение без подтверждения; ошибки и результаты не содержат API-ключ.
Наличие бесплатного тарифа и лимиты зависят от самого провайдера.

`--delegate-review` — явное поручение автору принимать отдельную
машинную редакторскую проверку, **не доказательство литературного канона**
и не утверждение, что человек лично прочитал каждую сцену.
Результат остаётся `user_ready=false`, `literary_truth_attested=false`,
`device_playtest_completed=false`, пока не проведена настоящая проверка.
Без флага программа сохраняет подтверждённые цитаты и сценарный черновик
и возвращает `needs_explicit_act_review` или
`needs_independent_editorial_review`, не притворяясь готовой игрой.

## Полностью офлайн: ответы ChatGPT из приватной папки

```bash
python3 -m tools.rpg_author author-book \
  --book /private/novel.fb2 \
  --project /private/novel-project \
  --workdir /private/novel-author \
  --output /private/novel-game.bworld \
  --provider private-json \
  --response-dir /private/ai-responses
```

Файлы `analysis_<chunk_id>.json`, `story.json`, `enrichment.json`,
`extension.json`, `literary_review.json` размещаются только в
приватном каталоге. В исходниках/CI их нет. При следующем запуске
уже принятые анализы и стадии не отправляются повторно.
Для автоматического финиша требуется отдельное явное
`--delegate-review`, либо вручную подтверждённая редакторская запись.

## Фактическая модель — отдельная приватная атрибуция

Нативный BookWorld сохраняет неизменный исторический
`model_provenance` ради совместимости импортёра. Поэтому его
поле `provider` само по себе **не свидетельствует**, какая
модель реально готовила историю. Внешняя программа записывает
отдельный приватный `authoring_provenance.json` с declared
`zai / glm-4.7-flash` либо
`private_json_unknown_model / null`, хешем готового мира и
прямым `model_id_status=declared_not_cryptographically_attested`.
В файле нет ключа, текста книги или сырого промпта.
Это отчёт о реально выбранном канале авторства, не литературная
или криптографическая сертификация.
## Инварианты и проверка

- Не публиковать книги и модельные ответы в GitHub. Всё сохраняется
  только по приватным путям, никакой телеметрии и ключей на диске.
- Модель НЕ может выдать цитату без точной сверки и НЕ может
  подменить источник, акт, свидетельство, переход или игровой API.
- Нет молчаливого превращения короткой игры в полноценную.
  Каждая физическая глава должна иметь подтверждённую исходную сцену,
  а native game API — найти два разных исполнимых окончания.
- Сложная книга может быть отвергнута из-за предела 192 базовых сцен,
  1024 итоговых сцен, бюджета контекста модели, 3000 проверяемых
  состояний или отсутствия двух реальных концовок; неполный результат
  не объявляется готовым.
- Новые unit-тесты используют только авторскую синтетическую
  трёхглавую FB2 и фальшивый ответ API; Dart parity — настоящие
  `LocalRpgGameApi` и SQLite. Нет реального теста с приватным романом,
  API-ключом пользователя или физическим Android/Windows-клиентом.

## Что пока НЕ автоматизировано полностью

Автоматическое создание новых многоперсонажных NPC dossiers и NPC Social v5
по произвольному произведению (существующую приватную проверенную
карточку NPC можно передать через `--npc-review`), проверка качества художественного текста
человеком, аудиодиалоги/портреты и полномасштабный Win/Android E2E.
В этой версии полную NPC-систему можно передать через ранее проверенные
ручные source-locked интерфейсы; не заявлять, что она создаётся
автоматически. Ответы GLM в CI только имитируются, сетевой запрос
на настоящий аккаунт пользователя не выполнялся.

Принцип дальнейшей работы: одно крупное функциональное завершение
всех оставшихся генеративных слоёв и реальные FB2 E2E, без
micro-PR по полю, кнопке или классу.
