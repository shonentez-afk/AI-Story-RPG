# ЖИВАЯ КНИГА — генератор как навык ChatGPT (не отдельная ИИ-модель)

**Актуальная архитектура · 9 ноября 2026 · внешняя ветка генератора**

## Правильное разделение

1. **Навык ChatGPT** — читает всю FB2/TXT, проверяет источники, пишет
   StoryPlan, многоактовый сюжет, диалоги, NPC-досье, отдельный
   литературный review и принимает творческие решения.
2. **Python `tools/rpg_author/`** — локальный индексационный и
   проверяющий компилятор. Не вызывает модели, не делает HTTP
   запросов к Z.ai/GLM, не имеет API ключей и не принимает решения
   за автора. Сохраняет checkpoints и обменивается приватными JSON
   заданиями/ответами с навыком.
3. **Dart native (`story_authoring`, `rpg_api`, `story_core`,
   `campaign_manager`)** — собирает private `.bworld v4`,
   проверяет причинность, доступность игровых действий и
   восстановление переносимых SQLite-сохранений.
4. **Flutter** и будущие клиенты — отображение и прохождение.
   Свободный ИИ-GM во время игры — отдельный runtime режим, не
   нужен для генерации книги в RPG.

## Один пользовательский запрос → много внутренних проверок

Пользователь прикрепляет книгу и просит сделать RPG. Вызов навыка
означает, что **именно ChatGPT** выполняет смысловую работу.
Нет вопроса о провайдере, модели, Z.ai, API ключе или тарифах.

Навык сам готовит проверенную версию внешней Python/Dart программы
по точному коммиту, указанному в своём `references/compatibility.md`.
Исходник и ответы хранятся строго вне публичного Git checkout.
Далее ChatGPT/навык выполняет на одном приватном проекте:

`python3 -m tools.rpg_author author-book`

```bash
python3 -m tools.rpg_author author-book \
  --book /private/my-book.fb2 \
  --project /private/my-project \
  --workdir /private/my-author \
  --output /private/my-game.bworld \
  --delegate-review
```

При первом запуске программа сохранит индекс и выдаст
`status=needs_skill_response`, код завершения `3`, **не ошибку**.
Появится `/private/my-author/skill-responses/requests/` c
`analysis_<chunk_id>.request.json` — только проверенный private
фрагмент книги и инструкции. Навык читает запрос, сам составляет
`analysis_<chunk_id>.json` в родительской папке
`/private/my-author/skill-responses/` и повторяет команду.
Программа проверяет точность цитат и сохранит принятые главы, затем
аналогично подготовит задания `story`, `enrichment`, `extension`,
`literary_review`. Для пользовательского опыта это ОДИН запуск
навыка, хотя внутри он повторяет проверку столько раз, сколько
нужно; не создаёт микро-PR и не спрашивает о модели.

Если ответ навыка нарушает источник/схему, программа подготовит
новый запрос с `validation_feedback` и вернёт
`skill_revision_required`, код `3`; навык исправляет JSON
до повторного исполнения. Неверная цитата не превращается в
принятую фактическую запись. При новом чате используются
сохранённые приватные project/checkpoints/snapshot, а не
повторное чтение книги с нуля.

После полного review программа доверяет **только** реальному
`LocalRpgGameApi`: нативный поиск двух различных достижимых
финалов, проигрывание обоих маршрутов, восстановление SQLite
и private `.bworld v4` + sidecar/отчёт.

`--delegate-review` означает, что пользователь поручил навыку
отдельный критический литературный проход, а не то, что человек
сам подтвердил канон произведения. Каноничность и качество
не доказываются наличием цитат или успехом тестов.

## Безопасность и происхождение

- `author-book` намеренно не содержит `--provider`, `--model`,
  `--allow-cloud-book`, ссылок на модельные API и обработки `ZAI_API_KEY`.
- Приватные JSON задания не отправляются автоматически в сеть.
- Результат `authoring_provenance.json` указывает
  `authoring_provider=chatgpt_skill`, `authoring_model_id=null` и
  `model_id_status=not_attested`. Фактическая работа навыка
  не доказывается криптографически.
- Нативные writer/importer, core API и Flutter **не меняются**.
  Объём изменений только `tools/rpg_author` и `tests/rpg_author`.
