# AI Story RPG — единый генеральный документ: книга → полностью готовая игра .bworld

**Дата и редакция:** 6 ноября 2026 года · редакция 1 (архитектурное ТЗ, не отчёт о реализации).
**Статус:** единственный актуальный сводный технический план для внешнего навыка ChatGPT, генератора, подготовки всех NPC, встроенного редактора, процедурной графики, анимации, AI-диалогов и связи с основным приложением. Прежние E6f/E6g/MASTER-документы — история исследования; при расхождениях целей ориентироваться на этот документ.
**Аудит основного main:** `959c8134f4ef20cd00dd4039d8d131638f502f60`. **Действующий pinned внешний генератор:** E6d `9849c22d18e2761b49766b0c213b4a3fb3fe053b`, версия `0.3.0a2`. Эти номера — срез на дату анализа, не гарантия состояния будущих PR.

## 0. Основное требование пользователя — БЕЗ обязательного редактора

> Пользователь передаёт книгу в ChatGPT. **Установленный навык ai-story-book-to-rpg должен создать целиком завершённую и проверенную игру и выдать ОДИН готовый к импорту файл game.bworld.** Пользователь открывает файл в AI Story RPG на Windows или Android и сразу играет. Редактор внутри приложения используется исключительно по желанию.

Игра создаётся **не частично**: навык обязан подготовить по всей выбранной книге персонажей, их характеры и мотивы, отношения, пределы знаний, офлайн-диалоги, предметы, характеристики, журнал, полные сюжетные переходы, условия, последствия, концовки, карты сцены и процедурные визуальные инструкции, а также правила допустимых свободных AI-взаимодействий. **Никаких действий «заполните профиль NPC», «дорисуйте фон», «допишите финал» после импорта.**

Отдельные рабочие файлы (source index, report, project_snapshot.zip, attribution) могут передаваться *дополнительно* для прозрачности и продолжения разработки. Для **обычного запуска** они не должны требоваться. Файл .bworld не содержит API-ключей или обязательной ссылки на облако.

**Offline-first:** всю сюжетную игру можно пройти без интернета и ИИ: заранее подготовленные тексты/диалоги, сюжетные выборы, интерфейс «Герой», «Предметы», «Журнал», сохранение, процедурная графика и лёгкая анимация работают локально. **Свободные новые реплики NPC через API** — дополнительное обогащение. Их нельзя гарантировать без подключения, согласия и поддерживаемого поставщика.

**Жёсткая формулировка готовности:** структурно верный ZIP ещё не «законченная игра». Нужны реальные завершённые маршруты, литературная и механическая проверка, проверяемые NPC/диалоги, соответствие изображения доступным знаниям, совместимость Python/Dart и фактические испытания. Если критические проверки провалены — не объявлять результат готовым.

## 1. Цели и независимые режимы

| Измерение | Варианты | Правило |
|---|---|---|
| **Сюжет** | CANON (авторский путь, исходный финал), ALTER_FATE (достоверные причинные альтернативы) | Не требовать искусственно 2 концовки от канона с одним исходным финалом. Для ALTER_FATE требовать действительно разные проходимые результаты |
| **Ввод** | CLASSIC_OFFLINE, AI_ASSISTED, AI_CONVERSATION | Один и тот же game state. ИИ интерпретирует речь и генерирует *речь*, но не создаёт незаконные игровые эффекты |
| **Оформление** | text, pixels_static, pixels_animated | Один и тот же сюжет, предметы, сохранения и события. Пиксели рисуются кодом, без обязательных PNG/ИИ-картинок |

Эти названия — будущие UX-режимы; не притворяться, что все они поддерживаются нынешним `.bworld v3`. В интерфейсе показывать только реально реализованные capability.

## 2. Единая техническая схема

    Файл книги FB2 / TXT (позже EPUB по отдельному этапу)
        |
        v
    [Навык ChatGPT + закреплённый Python tools/rpg_author из нашего GitHub]
        | A. Полный source-index (главы, UTF-16, SHA, точные цитаты)
        | B. Проверенный BookEvidenceGraph (события, сущности, знания, время)
        | C. GameScenarioGraph (герой, сцены, выборы, эффекты, финалы)
        | D. Профили всех важных NPC (голос, характер, мотивы, знания)
        | E. Полные сценарные диалоги и офлайн ответы
        | F. AI policies: SAY / LOOK / DO / INTERACT, допустимые действия
        | G. Visual Director: программные локации, персонажи, cues, анимация
        | H. Литературный + gameplay + NPC + dialogue + visual QA
        v
    [Версионированный компилятор + Python verifier + Dart importer]
        |
        v
      GAME.BWORLD   ← ОДИН самодостаточный игровой файл
        |
        v
    [Основное приложение AI Story RPG]
        | существующие story_engine + story_core + SQLite + gateway
        | Flutter диалоги, герой, вещи, журнал, сохранения
        | новый procedural pixel renderer, лёгкий scheduler анимаций
        | optional API разговоры через verified NPC knowledge
        | НЕОБЯЗАТЕЛЬНЫЙ встроенный редактор на Windows и Android

**Один источник фактов:** BookEvidenceGraph описывает, что доказано из книги; GameScenarioGraph — игровые факты и допустимые переходы; Visual/AI — их отображение и речевую форму. Событие внешнего ИИ или визуальной анимации не имеет права само создавать предметы, знания или записи игрового журнала.

## 3. Что уже работает в нашем репозитории — НЕ переписывать

| Компонент | Проверенный факт на main | Что используем |
|---|---|---|
| `tools/rpg_author/source_adapter.py`, `apps/story_reader/lib/book_source_index.dart` | Исходный индекс и цитатная привязка к книге | База для единого графа, без нового несовместимого парсера |
| `narrative_book_model.dart`, `source_character_dossiers.dart`, evidence/chronology | События и утверждения с происхождением, группировка упоминаний | Перенести в общий контракт. Группа упоминаний ещё не доказывает мировую идентичность NPC |
| `draft_scene_graph_overview.dart` / panel | Обзор переходов/циклов/недостижимых сцен | Развить в будущий редактор, не терять прежнюю проверку |
| `story_engine` / `story_core` / `story_runtime_adapter` | Навигация + единственные правила/эффекты + проверяемый replay | **Не создавать новый игровой движок** |
| `campaign_manager` / SQLite | Транзакционные подтверждённые события и переносимые сохранения | Оставить authority здесь, не сохранять «эмоцию» как игровой факт |
| `WorldGameView` / `WorldPlayPage` | Игровая сцена, choices, stats, inventory, flags, knowledge, journal | Точка подключения виджета визуализации и AI-NPC |
| `scene_dialogue_stage.dart` | Поочерёдные атрибутированные реплики, восстановление UI позиции | Расширить структурными speaker_id/turn_id и cue callbacks |
| `free_text_action_gate.dart` / `free_text_world_gateway_port.dart` | Проверка произвольного ввода по доступным choice, повторная проверка revision | Продолжить использовать как безопасный слой действий |
| `zai_gameplay_choice_advisor.dart` | Z.ai предлагает **только существующий разрешённый choice_id** | Не путать с полноценным разговором NPC |
| `ai_connection.dart` | GLM-4.7-Flash, opt-in, BYOK, HTTPS, secure storage | Сохранить инфраструктуру, расширять только по новому информированному согласию |
| `npc_knowledge_rulebook.dart` / NPC bridge | Source/approval-bound эффекты NPC knowledge | Переиспользовать точные семантические границы знаний |
| `tools/bookworld/private_rich_bookworld.py` + Dart importer | Строгая упаковка и импорт rich-v3 | Создать **новую явную версию** для дополнительных разделов; текущую не ломать |

**Факт о текущем формате:** .bworld v3 — ровно четыре ZIP_STORED записи: `manifest.json`, `scenario/blueprint.json`, `source/provenance.json`, `world.sqlite`. Строго проверяются пути, поля, хеши, SQLite. Нельзя незаметно добавить в v3 папку visuals/characters/AI: архив перестанет импортироваться. Поэтому **цель «один файл со всем» требует согласованного нового format_version, условно v4, с writer + Python verifier + Dart importer.**

**Разделение релизов:** пока новая версия не создана, установленный E6d может собирать проверенную **текстовую** rich v3, но нельзя обещать, что она автоматически содержит пиксельные сцены и свободные AI-NPC. Временные внешние JSON допустимы лишь для dev/QA, **не как окончательный обязательный пользовательский импорт**.

## 5. Обязанности НАВЫКА и ChatGPT: выпустить полный мир самому

Навык ai-story-book-to-rpg — **главный автор/координатор**, а не инструкции пользователю «сделайте персонажей». Он получает проверенную версию Python генератора **из нашего GitHub** и пишет структурированные данные по строгим схемам. Вся выдумка, маркировка адаптаций, QA и финальная компиляция проходят здесь **до** импорта в приложение.

### Полный pipeline будущей версии навыка

1. **Приём книги и настроек.** FB2/TXT сейчас; EPUB позже после реализации. Выбрать сюжет CANON/ALTER_FATE, героя, язык, визуальный режим. Если необязательные параметры не заданы, явно записать разумные defaults. Для облачного анализа книги нужно отдельное информированное согласие; частные книги никогда не публиковать.
2. **Версионированный bootstrap.** Навык загружает проверенный commit Python tools/rpg_author из нашего GitHub, сверяет SHA/doctor/contract. Приватные исходники, проекты, отчёты лежат вне публичного checkout. Без рабочей среды **не заявлять**, что файл собран.
3. **Прочитать ВСЮ книгу небольшими отрезками.** Сохранить original block/chapter/chunk, точные UTF-16 цитаты и source_fingerprint. Отделить факт повествования NARRATED, чью-то реплику REPORTED и вывод INFERRED.
4. **Единый литературный каталог.** Создать source-linked события, утверждения, действующих лиц, псевдонимы, места, предметы, цели, обещания, владение и знания; различать текстовый порядок и реальную хронологию. Никакого слияния NPC по одинаковому имени без подтверждённой связи.
5. **Независимый BookEvidenceGraph.** Узлы и связи: source quotes, happens_before, verified_causes, candidate_causes, knows_after, owns_after, located_at. У каждой спорной связи evidence/uncertainty. Сверить с уже имеющимися Dart narrative/evidence types.
6. **Цельная игра по всей книге.** Сцены, акты, выбор героя, задачи, предметы, знания, журнальные описания, условия, последствия, концовки. CANON не заменять искусственными развилками; ALTER_FATE создавать с реально разными маршрутами и пометками EXPLICIT_ADAPTATION. Завершённость сцены обязательна.
7. **Записать ВСЕ нужные NPC-карточки** (см. §6): identity, характер, цели, мотивация, отношения, эмоциональные состояния, манера речи, цитаты, knowledge_by_act/scene/state, неизвестное и запрет спойлеров, что NPC видел, визуальная идентичность, реакция на выборы. Для второстепенных персонажей допускаются краткие, но честные карточки.
8. **Выписать все обязательные диалоги.** Структурированные speaker_id и turn_id, оригинал/адаптация, текст реплики, допустимые ответы/вопросы, эмоции, действия и последствия. Создать полноценный offline fallback: API не нужен, чтобы завершить игру.
9. **Подготовить AI interaction affordances.** Для каждой сцены описать, кто виден/доступен, о чём можно говорить, что можно осмотреть и с чем взаимодействовать, какие естественные фразы относятся к **разрешённым** choice_id. Не превращать свободный текст в произвольный код/эффект.
10. **Автоматически спланировать пиксельные сцены.** Для всех важных мест/персонажей определить кодовый archetype, style/palette, seeded appearance, планы сцены, позиции, предметы, gestures и лёгкие animation cues; от неизвестных объектов требовать честный TEXT_ONLY/PARTIAL fallback, не выдумывать достоверный вид.
11. **Независимые проверки и исправления.** Пройти вторым отдельным литературным критиком мотивацию/хронологию/знания/логические последствия. Исполнить reachability/replay/диалоговые one-shot/предварительное знание, проверку NPC spoilers, visual coverage/unknown renderer opcode, prompt injection/privacy, consistency source/story/visual IDs. При правке инвалидация зависимых SHA/gates, повтор QA.
12. **Собрать ОДИН .bworld.** Писать только через проверенный writer поддерживаемой версии, архив, манифест, graph/NPC/dialogue/interaction/visual данные и QA fingerprints связаны хешами. Независимо проверить Python и Dart import, восстановить реальное прохождение по маршрутам и сохранения.
13. **Отдать пользователю.** Главный результат game.bworld; указать supported_app_min_version и status. Отдельно по желанию — project_snapshot.zip для продолжения другого чата и короткие отчёты с SHA. Редактор для завершения работы не требуется.

**Инструкция для будущего обновления навыка:** стадии 4–10 становятся обязательными при построении самодостаточной визуальной версии. В skill закрепить, какие входные и выходные schemas читает ИИ, требования к полноте, проверку синтаксиса/источников, независимую литературную оценку, автоматическую сборку/verify/replay, stop conditions и сохранение проектов. Не менять работающий pinned E6d до полной реализации новой pipeline и тестового acceptance gate.

### Статусы готовности различать обязательно

- **STRUCTURE_PASS**: архив, точные SHA/типы/трассируемые ссылки, SQLite, replay.
- **LITERARY_REVIEW_PASS**: полное покрытие выбранной книги, проверка смысла, идентичности, знаний и мотивов; литературная оценка не является математическим доказательством.
- **RUNTIME_PASS**: настоящий Dart importer, воспроизведение ветвей, диалогов и кадров, сохранения, тесты на Windows/Android.
- **USER_READY**: все применимые ворота закрыты, ограничения честно заявлены. Зелёный CI с фиктивной сказкой не доказывает реальную книгу; если физический E2E на устройстве не выполнен — это явно обозначенный остаточный риск, не заявленный PASS.
