# Задание GigaCode Desktop: полный Windows QA AI Story RPG

Работай именно через MCP `ai-story-rpg-windows-qa`, не через Cline и не через отвязанные от процесса mouse/keyboard инструменты. Ты проверяешь **реально запущенный** Windows `ai_story_reader.exe`; не изменяй исходники и не выдавай результаты анализа кода за результаты GUI.

1. `qa_status` → `qa_begin(name="pr133-real-windows")` → `qa_attach` (если игра запущена) или `qa_launch`. Проверь окно игры через `qa_tree` и `qa_screenshot("home")`. Если Windows Session не интерактивна, останови проверку с честным статусом BLOCKED.
2. Проверь домашний экран, библиотеку, импорт двух заранее предоставленных **тестовых** FB2 (Гримм «Король-лягушонок», Афанасьев), переход к экрану единого создания RPG. На каждом важном этапе сохрани скриншот и `qa_assert` там, где текст виден через UIA. Никаких поддельных подтверждений по screenshot.
3. Проверь каждый маршрут создания: «Полная проверенная RPG» для предварительно проверенного `.bworld`, «Буквальный CANON», «Офлайн-проба», «Подготовить с ИИ» — последний только при отдельном согласии пользователя и действующей настройке модели. Не называй офлайн-пробу полной адаптацией.
4. В запущенной кампании проверь Герой/Предметы/Журнал, кнопки NPC и портреты, диалог и пропуск/завершение реплик, доступные и заблокированные решения, журнал. Проверяй доступность не только внешний вид.
5. Для подтверждённого `.bworld` сравни шаги из журнала с текущими выборами и показаниями Герой/Предметы/NPC. Проверь переданный предмет на отсутствие у героя и появление у NPC **только при наличии реального проверенного выбора**. При отсутствии сценария запиши BLOCKED, не симулируй.
6. Проверь CANON и ALTER_FATE отдельно: текст книги не должен маскироваться под ответ ИИ; альтернативная история должна иметь маркировку. Свободное действие **сначала preview, потом явное подтверждение**, без запроса к платному API без разрешения.
7. Проверь сохранение/закрытие через `qa_close`/повторный `qa_launch` и продолжение той же кампании. Не удаляй личные сохранения. Если приложение не позволяет корректно завершить сеанс через GUI, не используй принудительное завершение другого процесса.
8. Для недоступных проверок вызови `qa_note` со статусом BLOCKED/INCONCLUSIVE/SKIPPED; не подделывай PASS. Вызови `qa_report`. Отчёт должен содержать реальные PASS/FAIL/INCONCLUSIVE, список неиспытанных сценариев и скриншоты; приложи относительные шаги воспроизведения для каждой ошибки. **Не объединяй PR #133**, пока пользователь не просмотрел фактические результаты.

При пустом или усечённом UIA-дереве сначала используй `qa_screenshot` и ограниченный `qa_click_xy`, координаты **по размеру изображения из результата инструмента**, а не всего рабочего стола. Не называй визуальное наблюдение доказательством фактического внутреннего состояния RPG Engine; для него нужны проверки автономного API и журнал решений.
