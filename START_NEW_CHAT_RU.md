## Сделано в этом пакете

Принятый `UnifiedBookStoryDraft` больше не теряет цель и мотивы при переходе в существующий общий редактор. `ReviewedStoryNarrative` оборачивает тот же проверенный MultiActStoryPlanDraft, не создаёт нового runtime и не превращает мотивы в знания. Панель связывает его с точной сохранённой записью общего сюжета и текущими карточками; эта проверка живёт после навигации, но не передаётся через data-only compute.

`NpcWritingCatalog` и отдельный адрес сохранения реплик включают reviewDigest общего сюжета. Изменение только мотива (при тех же правилах) создаёт другую авторскую редакцию и отзывает старое согласие; прежние ручные тексты не удаляются. Старый per-act путь без принятого narrative сохраняет прежние адреса/схему.

Каждый реальный показанный запрос содержит общую цель/конфликт как авторский замысел, назначение первого/ответного акта, условные связи и только релевантный мотив собеседника с точными source refs. Условие раннего исхода не выдано за уже совершённое действие. Мотив, основанный на более позднем текстовом событии, целиком удерживается. Порядок текста не объявлен временем мира. Никаких карточных секретов, чужих мотивов или автоматических NPC-фактов.

Существующий ZaiNpcCampaignWriting проверяет общий checkpoint перед каждым POST/429-повтором, после ответа и внутри writing-lock перед записью. Сохраняются прежние проверки героя, инвентаря и ручных правок. Конечное авторское согласие связывает narrative digest отдельно от стабильного wire-review; строгий writer получает прежний формат. Перед/после общей сборки проверяется та же живая редакция; устаревший сюжет не возвращает архив для установки. Существующие `.bworld` и кампании не мигрируются.

## Общая приёмка

Девять новых тестов в unified_story_npc_writing_test.dart плюс два исправленных прежних теста. Цель/мотивы → те же показанные payload bytes → настоящий инвентарный отчёт → одинаковый 429 retry → сохранённая часть → resume только оставшейся встречи → human review → strict .bworld → ключ, два NPC, исходный финал → SQLite close/reopen с предметом и совпадение stateHash. Негативные случаи: отсутствие согласия/guard, смена narrative при backoff или запоздавшем ответе, отозванные карточки, чужие motives, будущая textual basis, модельные effects, сохранность ручной строки, запрет старого install approval при новой истории. ## Ограничения и следующий результат

Это интеграция содержательного замысла в текущую подготовку диалогов, а не доказательство истинности мотивов. Промпт/JSON не обеспечивают литературную согласованность всех реплик; авторское одобрение сохраняется. Текстовая граница мотивов не гарантирует отсутствие любых смысловых спойлеров в общей цели/описании акта. Нет атомарной транзакции над несколькими файлами и нет отмены уже отправленного запроса.

CANON, произвольная художественная структура вне текущих agreement/exchange/disclosure, текст всех сцен, две реальные приватные русские FB2 с живым GLM и физический Windows/Android QA не завершены. Следующий крупный результат — общая содержательная приёмка на реальных книгах и устранение конкретных разрывов сценария, а не новые мелкие подсистемы. #118/весь PR не закрывать по синтетике.
