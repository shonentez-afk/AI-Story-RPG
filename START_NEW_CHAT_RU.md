## Ближайшие укрупнённые этапы P0 (только по очереди, максимум один функциональный PR за раз)

1. **NPC и реальные игровые знания/отношения по событиям.** Для каждого подтверждённого источником события учитывать порядок появления, открытие факта персонажу, допустимые знания, адресата отношения, условия и игровые изменения после выбора. Сохранять постоянные `character_id` без вычисления из имени/цитат. Внешние литературные сведения и редакторские заметки нельзя автоматически объявлять фактами мира. Нужны позитивные и негативные тесты (спойлеры, двойные имена, подмена ID, иной порядок сцен, SAVE/REPLAY).
2. **Цельная игра по книге.** Соединить существующие индекс книги, StoryPlan, GLM-акты, литературный аудит/допустимые правки, игровые эффекты, NPC и диалоги в один проверяемый `.bworld`; не создавать параллельную систему. Сделать честную отчётность по пропущенным событиям и неопределённости.
3. **CANON/ALTER_FATE и выбор героя.** Режим CANON следует подтверждённым событиям и не обязан иметь искусственную вторую концовку; ALTER_FATE требует двух причинно связанных маршрутов; недоступные роли/режимы нельзя выдавать за работающие.
4. **Упростить мастер и завершить реальный E2E.** 2 структурно разных русских FB2 (включая «Король-лягушонок» с проверкой прав на конкретный перевод), настоящий GLM (не mock), согласия/расходы, игра и офлайн-перезапуск на реальных Windows и Android. Подтвердить APK/ZIP и SHA256 на точном main.

## Обязательное архитектурное правило: движок отделяем, но не выносим сейчас

- Приложение «Живая книга» — **клиент** двигателя. Источник правил и игровых последствий — `packages/story_core` (без Flutter/SQLite/IO/ИИ).
- `packages/story_runtime_adapter` — интерфейс сцен/выборов и адаптация `story_engine`, без прямого изменения авторитетного состояния; `packages/bookworld_format` — только формат/проверка архивов и происхождения; `packages/campaign_manager` — кампании/SQLite/save/replay, не владелец правил.
- UI, GLM, приватный литературный редактор и изображения — клиенты/адаптеры, не код ядра. Никакого импорта из `apps/` в `packages/`; проверка `tools/ci_check_engine_boundaries.py` в CI обязательна.
- Любое игровое правило знания, отношения и последствия реализовывать в `story_core`, а авторский source-locked сбор/решения — отдельно. Для расширений `.bworld` нужен явный контракт версий, writer/importer Dart и Python parity, проверка подмены. Не менять v3 молча.
- Не дублировать движок и не создавать отдельный репозиторий сейчас; пакеты пока `publish_to: none`, API не объявлен стабильным. Самостоятельный пример `packages/campaign_manager/example/standalone_rpg.dart` и проверка save/replay — обязательный регрессионный gate.
