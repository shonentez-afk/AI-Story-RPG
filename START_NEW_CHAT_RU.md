## Функциональный пакет

NpcCampaignConsequenceStore сохраняет выбранные игровые эффекты и пояснения отдельно для точной книги/плана/героя/базового архива. Герой и NPC-тексты используют прежние хранилища. Загрузка заново строит manifest и запускает прежний строгий source/reachability preview. Запись не содержит исходных глав/цитат, ZIP, API-ключа или разрешений.

Автор восстанавливает работу → нажимает «Проверить сохранённые эффекты» → заново подтверждает локальный просмотр → проверяет весь NPC-пакет → начинает новую игру. Повторно выбирать предметы или запрашивать ИИ не надо. Отмена не теряет выбор и не принимает эффекты. Разрешения на облако/применение/установку не восстанавливаются автоматически.

Точная версия записи защищает от конфликтующих окон; failed write не публикует ложное сохранение. Удаление оставляет tombstone с новым write_id, scoped reset требует подтверждения и проверки токена. Перед итоговой приёмкой/установкой повторно сверяются герой, реплики/карточки и эффекты. Это не межпроцессная блокировка и не атомарная многофайловая транзакция.

Пять новых тестов находятся в npc_campaign_author_revision_test.dart: реальный диск и переоткрытие авторской работы → новая общая .bworld → ключ/два NPC → SQLite restart; конкурентные записи; пересчитанные подделки; scoped reset; телефонный UI отмены/согласий и отказ установки после изменения другим редактором. Четыре не-виджетных теста уже проходили в #976–978; телефонный должен быть принят на новом exact HEAD, не по предположению.
