## Активная разработка M2h7c4

Ветка feature/m2h7c4-batched-prose-consent-20261105. Цель — не заставлять пользователя подтверждать КАЖДЫЙ исходящий GLM-запрос при подготовке десятков черновиков. Реализованы ZaiProseBatchConsentManifest (полное отображение до 8 source-locked сцен и точных данных, digest редакции/StoryPlan/порядка/лимита), SourceLockedProseBatchService (foreground, не более выбранного числа новых сцен, каждая модельная попытка ограничена базовым Z.ai сервисом до 3 повторов, отмена, checkpoint по каждой сцене, повторное открытие пропускает готовые), отдельный UI SourceLockedProseBatchPage. UI доступен из многоактовой подготовки. Никакого HTTP POST без отдельного согласия, никакой фоновой генерации. Полный FB2, отдельные поля названия/автора, ключи и сохранения в запросы не добавляются; само название или имена могут присутствовать в показываемых цитатах и сценарных формулировках.

ЧЕРНОВИКИ batch НЕ ОДОБРЯЮТСЯ автоматически для игры и не считаются CANON. Для включения в BookWorld пока требуется явный приём текста конкретной сцены через существующий M2h7c3. Новый batch не изменяет rules, choices, storage schemas или старые кампании. Добавлены синтетические tests на запрещённый запрос, чужую редакцию, изменённый consent, лимиты, cancellation, остановку на повреждённой сцене, восстановление и UI без скрытого POST. Не объявлять готовым до exact-head CI/M0, merge и post-merge QA.

Документ: docs/M2H7C4_BATCH_PROSE_CONSENT_RU_2026-11-05.md.

## Что осталось до полноценной RPG

1. Автоматическое (не десятки ручных кликов) применение литературно проверенных сцен ко ВСЕМ нужным актам, независимая оценка сюжетной согласованности, персонажей, предметов, обещаний, флешбеков и обоих маршрутов.
2. Полноценные CANON и ALTER_FATE, разные содержательные концовки, реальное достижение полного охвата исходных событий, не только выборочных цитат.
3. Простой UX «Добавить книгу → режим и герой → подготовить → играть», правдивый прогресс и ограничения расходов/таймаута.
4. Настоящий GLM E2E (с разрешения пользователя) на «Короле-лягушонке» и ВТОРОЙ книге + Windows и Android device QA, восстановление сохранений, офлайн-прохождение.
5. История происхождения моделей: текущий private .bworld v2 принимает model_provenance none/null; это только техническая совместимость и НЕ означает, что AI не участвовал. Расширение формата требует сохранения обратной совместимости.

Запрещено передавать частные книги или API-ключи в публичный CI; mock-тесты только с синтетическими данными. Никакой смены формата .bworld/схемы SQLite до совместимой приёмки.
