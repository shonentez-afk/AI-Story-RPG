## Новый единый пакет

В существующем BookActDraftPage появился вход в один общий сценарий ВСЕЙ найденной карты, а не несвязанные запросы по отдельным главам. UnifiedBookStoryContext передаёт все mapped events и source-reviewed NPC IDs/имена, точно показывает данные до POST, не включает название/тайны/сейвы. ZaiUnifiedBookStory получает общую цель/конфликт, гипотезы мотивов всех показанных NPC, роль каждого акта и его развилку, связи с ранними исходами. Пропущенные акты, выдуманные source/actor IDs, ложный канон и модельные effects не принимаются.

Ответ сохраняется как неутверждённый proposal в отдельном локальном scope. Открытие/восстановление не вызывает API и не восстанавливает разрешения. Перед каждой попыткой/повтором и сохранением сверяются context, карточки, отмена и запись; одновременно разрешён один запрос этой редакции. Lock держится до завершения durable save. Модель может отказаться от всего предложения, не подменяя пробелы выдумкой.

После двух отдельных авторских подтверждений UnifiedBookStoryDraft.accept применяет прежний CrossActConsequenceGate: позднее accept_offer зависит от выбранного раннего исхода, поздний refuse_offer остаётся доступным. Результат — тот же тип MultiActStoryPlanDraft с реальным causal audit, переданный в существующий WholeBookNpcCampaignPage. Герой, source encounters, предметы, несколько NPC, строгий импортёр и SQLite используются без нового исполнения или .bworld-схемы.

[Отчёт и восемь новых тестов](docs/P0_UNIFIED_BOOK_STORY_RU.md). Главное E2E: 12 событий / 3 акта → выбранный герой → получение и расходование ключа → два NPC → ранний отказ блокирует позднее зависимое согласие, но не самостоятельный путь → разные финалы → SQLite reopen с ключом и проверка итогового stateHash. Новый UI и фальсификация входов/согласий проверяются отдельно. Фактический PASS этих новых тестов ещё нужно подтвердить CI.

## Чего этот пакет не доказывает

Запрос охватывает все найденные события, не полный текст и не гарантированно каждое существенное событие оригинала. Он использует прежние шаблоны agreement/exchange/disclosure, не универсальный сценарный язык. Мотивы сейчас показываются автору и учитываются в общем сценарном предложении; они НЕ автоматически добавлены в runtime-знания NPC или во все последующие prompts диалогов. Выбор героя выполняется в прежнем общем редакторе после принятия общей структуры.

Лимиты: 2–12 актов, минимум два события/акт, shown context 160 KiB, answer 56 KiB, прежние пределы сценария/обхода. Переполнение блокируется без усечения. Поддерживается частное предложение ALTER_FATE; полный CANON, произвольное художественное ветвление, доказанная хронология/мотивация, живой GLM, две разные реальные русские FB2 и физические устройства не объявлены выполненными. Доступный здесь поиск Project/Library не вернул нужные приватные FB2; не публиковать книги или придумывать факт их испытания. Текущие новые тесты synthetic + fake transport.

После приёмки — связать одобренную общую цель/мотивы с контекстом сцен и NPC без новой библиотеки и повторного построения ядра, затем выполнить реальную книжную приёмку. #118 и PR не закрывать синтетическим PASS. [Статус](docs/CURRENT_STATUS_RU.md).
