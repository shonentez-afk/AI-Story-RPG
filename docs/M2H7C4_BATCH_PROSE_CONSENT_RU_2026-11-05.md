# M2h7c4 — групповой художественный предпросмотр и контроль затрат

Статус: в рабочей ветке, NOT ACCEPTED до exact-head CI (Python/Dart/Flutter/Windows/Android), M0, merge и post-merge release target QA.

## Цель

Убрать необходимость вручную запускать GLM для каждой сцены, сохранив явное информированное согласие на точный список данных. Пока это генерация только ПРИВАТНЫХ ЧЕРНОВИКОВ; литературный смысл не доказан, автоматическое включение в CANON не разрешено.

## Реализация

- Пользователь вручную открывает экран «Художественные сцены по частям» внутри необязательного раздела подготовки частной многоактовой RPG.
- Группы до 8 сцен, ограничение НОВЫХ запросов за одно согласие (1–8). UI показывает точные имена ситуаций, весь цитируемый отрывок при наличии, goal/conflict, действия и правила, число сцен, приблизительный объём передаваемого контекста, верхнюю границу повторных запросов (до 3 попыток на новую сцену), отдельное предупреждение о возможной оплате.
- Manifest digest однозначно привязан к исходной редакции, полному StoryPlan, порядку выбранных сцен, полному составу отправляемых user-контекстов, модели и верхнему пределу количества новых сцен. Изменение хотя бы одной позиции требует нового разрешения.
- Отправка начинается ТОЛЬКО после нажатия пользователем кнопки и отдельного установленного флажка. Сервис повторно проверяет manifest до первой отправки.
- Перед платным запросом проверяется локальное частное хранилище ВСЕХ выбранных сцен. Повреждённый checkpoint блокирует новый запрос; готовые сцены пропускаются. Каждое полученное и проверенное предложение сохраняется перед запуском следующего, отмена прекращает дальнейшие запросы.
- 429/обрывы/временные ошибки обрабатываются уже проверенным one-scene Z.ai сервисом, не более 3 попыток, с тем же payload. Одна ошибка останавливает batch; продолжение требует НОВОГО согласия на тот же отображаемый набор.
- Текст не автоматически подтверждается и не интегрируется в BookWorld или SQLite. Для этого отдельно работает M2h7c3 с обязательным явным review текста.

## Проверки

Синтетические источники: отсутствие/ложный digest согласия -> ноль POST; другая редакция/scene/order/cap -> новый digest или запрет; контроль не более N новых сцен; HTTP отправляет только exact per-scene user-context без title/author/sourceFingerprint/API key; отказ второй сцены оставляет checkpoint первой; повторный запуск не тратит запрос на первую; cancellation после первой останавливает вторую; UI на открытии не отправляет ничего. Реальный GLM E2E и литературное качество отдельно, после явного разрешения владельца API.

## Следующий этап

Нужны литературная/веточная валидация, разумные автоматические одобрения и полный сценарий, иначе групповой сервис — лишь ускоренная подготовка отдельных черновиков, НЕ выполнение цели «загрузил книгу и играю».
