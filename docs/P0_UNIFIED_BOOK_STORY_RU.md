# P0 — один связный сценарий из полной карты книги

## Цель пакета

Перестать получать несвязанные предложения по одной главе. На основе всей доступной карты показать общую цель, центральный конфликт, мотивы подтверждённых персонажей, роль каждого акта в общей истории и реальные последствия ранних исходов для поздних решений. Всё проходит прежний компилятор, авторский редактор, strict .bworld и автономный story_core/SQLite.

## Один контекст и инертное предложение

`UnifiedBookStoryContext` требует завершённый анализ и полную карту без пропущенных глав: 2–12 актов, каждый минимум с двумя событиями. Каждая mapped citation повторно сверяется по исходной книге, fingerprint, exact quote, chunk и UTF-16 range. Показаны ВСЕ события этих актов, не восемь выбранных цитат. Превышение 160 KiB или возможностей карты даёт явный отказ, а не усечение.

Передаются actor IDs/names только из существующих проверенных карточек, а ссылки мотива — только события, в чьих цитатах есть проверенное упоминание этого actor. Тайны/заметки карточек, API-ключи, название книги, сейвы и исходный файл не добавляются. Совпадение имени не создаёт новую идентичность. Один и тот же показанный JSON используется в пользовательском message. Source/role binding относится к точной редакции, согласие не переносится на другую.

`ZaiUnifiedBookStory` использует прежние AiCloudPreferences/vault/transport/ZaiModel. Один request, до трёх одинаковых попыток при временных ошибках. Неверные credentials/квота не повторяются; Retry-After нельзя обогнать. До каждой попытки и после ответа повторно читаются карточки/состояние хранилища, настройки и отмена. Параллельная генерация этой же редакции блокируется до завершения durable save. API-ответ не логируется. Сохранённый complete или отказной результат не приводит к новому POST при открытии.

Ответ строго ограничен схемой общей цели/конфликта, всех актов, мотивов всех показанных акторов и forward links. Отказ модели `{applicable:false,reason:...}` допустим; неполный успешный набор актов, поддельные источники/акторы, новые effects, утверждение canon_verified, неизвестные outcome или обратные связи отвергаются. Текст должен быть русским и ограниченным. Это структурная проверка, НЕ доказательство истинности мотивов.

## Игровые связи исполняются, а не только показываются

Для каждой части после первой требуется ровно один predecessor из более ранних частей. После двух новых авторских подтверждений модельные данные заново парсятся; обычный BookwideStoryPlanComposer строит прежние typed dilemmas. Существующий CrossActConsequenceGate добавляет к позднему accept_offer условие выбранного original/alternative исхода раннего акта. Поздний refuse_offer не ограничивается этим пакетом. Гейт обязан доказать и допустимые, и закрытые состояния, проверить источники и отсутствие формальных противоречий.

Проверенный составной draft реализует прежний интерфейс MultiActStoryPlanDraft и несёт тот же план, части, bridges, coverage и причинный audit. Дальше его потребляет WholeBookNpcSourcePlan → MultiActTrialCompiler, поэтому герой, source encounters, предметы, несколько NPC и журнал не получают отдельного исполнения. Полный strict importer и campaign causal gate остаются обязательными. Условия не подменяются надписями.

## UI и восстановление

В существующем BookActDraftPage одна кнопка AppBar «Связный сюжет всей карты книги». Она открывает локальную панель. Открытие не передаёт текст и не устанавливает игру. Панель показывает общую цель/конфликт, мотивы с source refs, содержание каждого акта и все новые ограничения. Автор отдельно проверяет исходный текст/историю и одобряет вымышленные игровые зависимости. Затем возвращается обычный draft, и при наличии worldGateway открывается прежний WholeBookNpcCampaignPage.

Старые per-act approvals и checkpoints остаются. Новый checkpoint содержит только неутверждённый ответ, привязку контекста и checksum, но не исходные цитаты, ключ или разрешения. CAS по точным предыдущим байтам не позволяет позднему сохранению затереть новую редакцию. Ошибка записи не показывает ложного успеха; повреждённый файл не сбрасывается молча. Межпроцессная многофайловая транзакция не заявляется.

## Написанная общая приёмка (проверить CI)

1. Все 12 событий / три акта присутствуют в exact shown context; порядок входных карточек не меняет digest.
2. Одна модельная структура → реальный CrossActConsequenceGate → выбранный герой → grant/consume source key → два NPC → strict rich-v3 → реальный оригинальный маршрут и самостоятельный маршрут с закрытым поздним согласием → разные финалы → SQLite restart с ключом и совпадение stateHash.
3. Неполные акты, поддельные личности/события, fake canon/effects, обратные связи, недостающие мотивы и отсутствующее авторское согласие отклоняются.
4. Идентичные bytes при 429, локальное восстановление без повторного POST и без разрешения на игру.
5. Отсутствие точного согласия, отключённый аккаунт, отсутствующий ключ — ноль POST.
6. Отозванная карточка во время backoff, отмена, malformed response — без дальнейших POST/сохранённого прогресса.
7. Параллельный request, ошибка записи, stale CAS и пересчитанная подделка checkpoint — без потери результата.
8. Телефонная панель восстанавливает proposal локально, не переносит approvals и возвращает plan только после двух реальных согласий.

Тестовый источник и API synthetic, живой GLM здесь не вызывался. В среде чата Dart/Flutter отсутствуют; новые тесты выполняет CI, не объявлять локальный PASS. Предыдущая регрессия ошибки защищённого сохранения исправлена отдельно в 5d33b2c и прошла весь Flutter job CI #984.

## Неприкрытые ограничения

Этот пакет ещё использует прежние три формы agreement/exchange/disclosure и два игровых исхода. Он делает их общим причинным сценарием, но не создаёт произвольную художественную структуру для любого романа. Все найденные события не означают, что модель первоначального анализа обнаружила каждое важное событие. Дополнительные source encounters сохраняют прежний формат, а мотивы пока не становятся автоматическими NPC-целями или знаниями в runtime.

Поддерживается предложение PRIVATE ALTER_FATE; полноценный CANON не открывается новой надписью. Также не выполнены авторская доказанность литературной причинности/хронологии, готовый текст всех сцен, живой GLM, две разные реальные русские FB2 и физические Android/Windows тесты. Эти пункты требуют следующей общей приёмки, а не ложного статуса 1.0. Main/E6d не менять; PR #133 Draft и issue #118 остаются открытыми.
