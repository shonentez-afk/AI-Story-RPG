# M2h8 — единый целевой BookWorld и настоящие игровые вкладки

Статус: работа в отдельной проверяемой ветке; до успешных CI и физической проверки Windows/Android это НЕ готовый MVP.

## Решение
Продукт ещё не выпускался с пользовательскими кампаниями. Исторические original_demo v1 и private v2 остаются только временными фикстурами разработки. Не создавать миграционные мастера ради несуществующих пользователей. Номер rich v3 — внутренний номер контракта, пользователю не придётся выбирать версии.

## Реализовано в этой ветке
- Перенесён E4 source-bound private rich импортёр из экспериментальной ветки на актуальный main с GLM и защищённой инфраструктурой SQLite.
- Проверяемый архив содержит игровые каталоги, выбранного героя, описания, русские названия предметов/характеристик/знаний/сцен и метаданные происхождения исходного текста. ZIP и SQLite не принимаются без строгой проверки.
- Импортёр и движок исполняют настоящие grant_item, consume_item, has_item, stat_delta, learn_fact наряду с flags и запретами выбора. При отсутствии предмета условие остаётся закрытым.
- Вкладки Герой/Предметы/Журнал читают авторитетное состояние SQLite и journal из подтверждённых replay-событий. После расходования вещь исчезает. Получение знания отображается только после действия.
- Встроенный внешний Python author compiler может собрать source-bound rich .bworld с настоящими данными, а не имитацией предметов через прозу.
- В CI создан реальный тестовый архив из ОРИГИНАЛЬНОГО синтетического текста о Лене и верёвке. Сквозной Flutter+SQLite тест проверяет обе разные ветви, получение и расход, характеристики, знания и перенос сохранения.
- Текст книги и реальные ключи не копируются в репозиторий; тест использует только фикстуру.

## Осталось до первой полной RPG из книги
1. Доделать CI для SQLite source (PR #95), проверить ПОЛНЫЙ exact-head CI на текущей ветке, включить импортер и UI в main, опубликовать Windows/Android на точном SHA.
2. ЕДИНЫЙ встроенный compiler: преобразовать GLM semantic extraction и StoryPlan в rich сцены, типизированные эффекты, реальные каталоги/наименования и начальное состояние героя; не требовать от обычного пользователя ручного enrichment JSON.
3. Честно записывать реальное происхождение встроенных GLM/z.ai сцен и внешней ChatGPT-сборки. Нельзя использовать none для реально применённой модели; не выдумывать model-id.
4. Проверять причинную и литературную согласованность ВСЕХ сюжетных актов и маршрутов: время, NPC знания, предметы, обещания, причины. Исправлять неверные сцены через GLM с отдельным согласием и верхней границей запросов.
5. Сформировать и испытать CANON и ALTER_FATE с действительно различающимися художественными концовками; UX «Добавить книгу -> герой/режим -> подготовить -> играть».
6. Провести настоящие согласованные GLM E2E на легально используемой короткой сказке и другой книге; проверить Android/Windows, офлайн, восстановление новой кампании и перенос сохранений.

До подтверждения пунктов выше демонстрационная rich сборка не объявляется готовой полноценной игрой.
