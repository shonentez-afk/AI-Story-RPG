## Объём проверки и честные границы

Проверен **весь пользовательский маршрут**, а не только главный экран: библиотека/импорт → входы в подготовку → локальное индексирование → разрешения и checkpoint Z.ai → карта актов → единый сюжет → подтверждённый герой/роль → предметы/NPC/реплики → художественный текст всех сцен → строгий `.bworld` → сохранённое офлайн-прохождение, Hero/Items/Journal/NPC и продолжение. Сверены назначение и входы ключевых экранов с независимым `story_core`, формальным `isFullBookRpg`, форматными ограничениями, issue #118 и актуальными widget/integration тестами. Инвентаризованы 171 файл в `apps/story_reader/lib` и 132 тестовых файла; критические маршруты и их тесты изучены по исходникам. Это **полный маршрутный/функциональный UX-аудит по коду и CI**, но **не визуальная проверка всех кадров**, не проведённое юзабилити-тестирование на людях и не физический QA TalkBack/Narrator, Windows и Android. Видео/скриншоты реального устройства не получены.

**Вердикт:** для **управляемой тестовой частной адаптации** подходящей книги механика собрана и автоматические проверки зелёные. Для обещания **«передал произвольную книгу → выбрал персонажа и CANON/ALTER_FATE → получил законченную литературно связную игру без технических шагов» — НЕ ГОТОВО**. Успешный CI не закрывает функциональные блокеры ниже.

## Подтверждённые блокеры и дефекты

### P0 — устранить до заявления о готовности процесса книга→игра

**UX-P0-01 — непроходимость общего сценарного пути без подходящего NPC.** `WholeBookNpcCampaignPage._prepare` отклоняет пустой `BookwideNpcCampaignAuthoring.discover` («Нужны другие подтверждённые NPC с упоминаниями в двух включённых событиях»). Далее `_review` требует `_edits.isNotEmpty`, а компиляция NPC-пакета также отклоняет пустую выборку. При книге с одним действующим лицом, слабым распознаванием имён или эпизодическими NPC **нельзя продолжить именно единый сюжет→текст всей игры**, хотя само ядро способно работать без NPC. **Исправление:** опциональный NPC-шаг, пропуск с проверенным базовым миром, отдельный полноценный путь на финальный prose/install; при наличии подходящих NPC строгие знания/память не ослаблять. **Приёмка:** 0 / 1 / 2 NPC и восстановление каждого варианта.

**UX-P0-02 — источниковые ограничения несовместимы с обещанием «любой подходящий роман».** `UnifiedBookStoryContext.create` требует `book.analysisComplete`, отсутствия source gaps, 2–12 актов, ≥2 события в каждом акте, ≤15 подтверждённых ролей, максимум 160 KiB показанной карты за один запрос. `BookwideSourceEncounters` ограничивает дополнительные события 24 на акт и общую карту 192 сценами. Это честные fail-closed ограничения, но при отказе нет предсказуемой инструкции и штатного механизма «исправить пробелы → вернуться сюда» в одном мастере. **Исправление:** до дорогих запросов показать готовность и доступный режим, разбить/постранично обработать большую книгу без молчаливой потери значимых событий, осмысленно объяснить, что исправить. Не повышать лимиты без bounded CI.

**UX-P0-03 — полноценный CANON не реализован и полный статус сознательно false.** `_ReviewedUnifiedDraft.isFullBookRpg == false`, `hasConfirmedLiteraryMeaning/WorldChronology/ActorKnowledge/SourceProvenCausalBridges == false`. Быстрая игра может называться «Сохранить сюжет», но это **не** документированный литературный CANON. В полном пути пока PRIVATE_ALTER_FATE proposal; «две развязки» автоматически не эквивалентны исходному финалу книги. **Исправление:** показать режимы заранее, неподдерживаемый CANON оставить недоступным с пояснением; перед финальной приёмкой реализовать source-reviewed каноническую линию без обязательной выдуманной второй концовки. Ни один UI не должен выдавать trial за полный канон.

**UX-P0-04 — литературная и реальная книжная приёмка не пройдена.** Автоматические 11 тестов нового prose-потока, сравнение правил, hero/inventory/NPC и SQLite теперь PASS в #987; они используют синтетические события и mock transport. Публичный Grimm (62 сказки, английский текст) проверяет **индекс/локальный checkpoint**, а не completed rich-v3 с сюжетом этих 62 сказок. Приватный Andersen RU smoke в публичном CI SKIP и тоже заканчивается source checkpoint, не игрой. Для утверждения о готовом продукте необходимы две разные настоящие RU FB2, реальный GLM 4.7 Flash и физический Win/Android QA с каноном/альтернативой и двумя прохождениями. Структурная причинность ≠ литературная причинность.

### P1 — устранить до beta-UX «передал книгу → получил игру»

**UX-P1-01 — разветвлённая и скрытая навигация.** В `LibraryPage` «Играть по книге» открывает `BookRpgStartPage`, «Подготовить к RPG» открывает `SourceIndexPreviewPage`; последний отображает «Полная RPG по всей книге ... пока не реализована» и прячет ИИ в расширенных разделах. В длинном пути `BookActDraftPage` основной «Связный сюжет» — **только AppBar IconButton**, а `MultiActTrialPage` открывает NPC через `Stack/Positioned` иконку. Требуется **один видимый основной CTA**, шаги/назад/возобновить, сохранение доступа к расширенным редакторам без давления на новичка.

**UX-P1-02 — противоречивые подсказки о роли и назначении кнопок.** `BookRpgStartPage` пишет «используется герой по умолчанию. Выбор любого героя книги ещё не реализован», тогда как глубже можно выбрать `ReviewedHeroRole` по permanent ID. Правильно: «после проверки персонажей можно выбрать подтверждённого героя; произвольные роли не гарантируются». Названия «Играть», «Подготовить», «Создать RPG», «План по частям» и «Пробная игра» нужно развести по результату: подготовка/проба/готовая игра.

**UX-P1-03 — нет единого сквозного экрана готовности и бюджета.** Отдельные экраны показывают окна Z.ai, согласия и число запросов, но не объединяют «главы проиндексированы → события подтверждены → карта готова → герой доступен → NPC опциональны → предметы → сюжет → проза → архив». Из-за этого disabled CTA/ошибка получает техническую причину, но не действие «Исправить». Добавить видимый stepper, status готово/требует решения/не поддержано, оценку **максимальных запросов по всем стадиям** и повторную проверку при смене книги/роли/редакции; без автоматического облачного согласия.

**UX-P1-04 — карточки NPC и герой слишком поздно.** `ReviewedHeroRoleCatalog` зависит от заранее подтверждённых упоминаний/карточек из отдельного сложного редактора. На основном пути нет контекстной команды «Не хватает NPC/героя — подтвердить кандидатов и вернуться без потери результатов». Один герой/одна глава или несопоставимые aliases дают ошибку глубоко после предыдущих запросов. Нужен ранний preflight и необязательный guided fix.

**UX-P1-05 — длинные редакторы не адаптированы как мастер.** `source_index_preview_page.dart` 1183 строки, `multi_act_trial_editor.dart` 1253, `whole_book_npc_campaign_page.dart` 786 с ~34 callback-контролами, а финальный prose показывает до 192 `ExpansionTile` в обычном `ListView`. Риск непонимания последовательности, долгой прокрутки, потери основной CTA. Нужны компактные шаги, группировка, нижний progress/action, виртуализированный список для больших кампаний и тесты реальных keyboard/resize/focus. Это **риск по структуре**, не утверждение, что обнаружен RenderFlex overflow на устройстве.

**UX-P1-06 — художественный текст содержит технический исходник.** `ReviewedCampaignProseWriter` добавляет новый narrator paragraph перед старым телом, не удаляя технические пометки и не делая редактуру исходных структурированных сцен. В `WorldPlayPage` текст сцены выводится напрямую, если нет структурного диалога. Следовательно игровой экран может выглядеть как лабораторная проба, хотя все правила исполняются. Нужен отдельный проверяемый **пользовательский presentation layer**, не изменение исходной цитаты/условий/подписанных NPC turns. Сравнить скриншоты до/после.

**UX-P1-07 — реальное восстановление длинной задачи на мобильном не доказано.** Сохранение после пакетов и отмена следующих запросов имеются; экран анализа прямо предупреждает, что приложение должно оставаться открытым. Переход Android в фон, принудительное завершение, потеря связи, повторный вход с домашнего экрана и аппаратный FilePicker не проверены. Не гарантировать фоновые вычисления; показать «безопасно закрыть после сохранённого пакета» и «Продолжить подготовку» из библиотеки.

**UX-P1-08 — недостаточная приёмка новых экранов на доступность.** Старые home/library/world имеют тесты 320dp/200% text, новые unified NPC/prose — главным образом 360dp и mock UI. Не проведены TalkBack/Narrator, desktop Tab/Shift+Tab, high-contrast, фокус после закрытия dialog, проверка клавиатурных сочетаний во всех новых длинных формах, screenshot QA на устройствах.

### P2 — качество текста/профессиональный UX

**UX-P2-01 — служебные ID в пользовательском содержимом.** `UnifiedBookStoryPanel` показывает `fromActId → toActId`, `sourceEventIds.join(', ')`; точный JSON payload нужен для прозрачности облака, но не должен быть единственным объяснением мотивов/последствий. Показать понятные номера глав и названия эпизодов, технические IDs оставить в «Подробностях».

**UX-P2-02 — несогласованное сообщение об ограничении.** `BookwideSourceEncounters.maxReviewedEventsPerAct = 24`, а одно сообщение о превышении всё ещё говорит «не более восьми». Исправить текст/тест, не меняя контракт.

**UX-P2-03 — позднее обнаружение неготового ИИ.** Включение облака/ключа и проверка соединения живут в настройках; начальный экран не показывает статус подключения до прохождения индексирования. До выбора длинного режима показать «Z.ai: готов/нужно настроить» и ручной переход в настройки без новой библиотеки или отправки книги.

## Что уже работает и НЕ надо переписывать

- Одна библиотека книг и `.bworld`, раздельные сохранения/кампании, импорт TXT/FB2/FB2.ZIP, сохранённые позиции чтения, темы, оглавление, изображения; целевой BookWorld `.bwsave`/SQLite offline replay и резервные копии.
- Source-index, SHA/цитаты/постраничные checkpoints, локальные графы фактов, отдельное согласие перед облачными пакетами, ограниченные 429 retries и защита новых ручных правок.
- Существующий `story_core` независим от Flutter/ИИ; условия, владение, NPC memory/knowledge и причинный обход подтверждены тестами; игра не обращается к ИИ на ход.
- `WorldPlayPage`: диалоговые реплики по очереди, локальные портреты (опционально), Hero/Items/Journal/NPC (после встреч), интерактивные условия выбора, режимы экрана и чтения; восстановление SQLite после restart.
- Полностью успешный точный CI #987, Android/Windows binaries; эта гарантия не распространяется на физические устройства, живой облачный аккаунт или литературную истинность.

## Рекомендуемый порядок внутри того же PR #133

**Пакет A — UX целого маршрута (P0/P1):** единый видимый мастер и переход «Продолжить», ранний диагностический preflight, раздельные demo / private ALTER_FATE / недоступный CANON; возможность собрать **базовый мир без NPC** и затем опционально усложнить его. Устранить скрытую AppBar/overlay-навигацию без удаления расширенного редактора. Вместе — 0/1/2 NPC и failure/retry/resume тесты.

**Пакет B — работа с объёмом/контентом:** диагностировать лимиты до затратных запросов, поддержать полный маршрут книги с >12 актами/15 ролями без обрезки либо честно ограничить поддерживаемый класс книг; удобная проверка мотиваций/пробелов и переработка presentation-текста без изменения механики. CANON отдельно как функциональный gate, но **в том же большом PR**, не по микро-PR.

**Пакет C — окончательная UX и литературная приёмка:** 320dp, 360dp, 200% text, Windows resize/keyboard, screenreader, Android background/restart, крупная FB2; затем две разные реальные RU FB2 с живым GLM и ручная смысловая проверка двух маршрутов, .bworld/.bwsave/SQLite restart. Точный CI/привязанный SHA на каждом пакете. E6d отдельно и отложен.

## Критерий «готово создавать игру по книге» без ложного обещания

До первого реального книжного испытания желательно закрыть **UX-P0-01**, дать видимую прямую дорогу к unified/story и диагностировать **UX-P0-02**, чтобы пользователь не обнаруживал проблему только в конце долгой обработки. Настоящую литературную приёмку **UX-P0-03/04** нельзя подменить этим аудитом. **Сейчас можно запускать ограниченную тестовую адаптацию подходящей книги с ручной редактурой; общий продукт 1.0 и полностью автоматическое создание литературной RPG пока не готовы.**

Не объединять PR #133 и не закрывать issue #118 по одному успешному CI. Не менять E6d и не повторять завершённую очистку.
