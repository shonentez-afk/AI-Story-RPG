На существующем экране анализа книги показываются части и неохваченные события, а не дополнительный экран редактора. Черновик **не является игрой**. Старый CI #555 на предыдущем HEAD прошёл Python, Dart, Flutter, M1.7 и начал платформенные сборки; после синхронизации PR с main нужен новый exact-head SUCCESS перед слиянием.

## Следующая реальная задача по продукту

1. Закончить M2h1 и доказать, что события произвольной книги (в том числе главы без находок) не теряются на пути к сценарному плану.
2. M2h2: построить из ВСЕЙ карты актов источнико-специфичные многоходовые сюжетные переходы с семантическим обоснованием, а не механически протягивать главы текста. Контракт нескольких актов, знания NPC, условия предметов и обязательств.
3. M2h3: отдельно проверять литературный смысл и художественные сцены, тайны и причинность; настоящие CANON/ALTER_FATE; использовать существующий компилятор и SQLite без изменения старых сохранений.
4. Полная RPG по одной публичной сказке «Король-лягушонок»: загрузка FB2/ZIP → явное согласие → ограниченный реальный GLM-прогон → полный сценарий → две законченные ветки → сохранение и офлайн-прохождение Android/Windows. Затем вторая книга без специальных правил по её названию.
5. Упростить основной UX до «Загрузить книгу → Выбрать режим → Подготовить → Играть» и оформить честный отчёт готовности.

**Ещё не готово:** полноценная литературная RPG из произвольной FB2, реальный оценённый GLM-прогон на полной сказке, литературный аудит, полноценный CANON, автоматика художественных сцен, испытания устройств. Зелёный CI = правильность проверенных программных контрактов, не подтверждение качества сюжета. Не отправлять тексты и ключи в публичные CI, не отправлять цитаты без отдельного согласия.
