## Реализованный пользовательский поток

В существующей кнопке подготовки диалогов: точный принятый .bworld с предметами → строгая проверка источника/героя/сцен/выходов → реальный маршрутный аудит в data-only isolate → полный показываемый контекст → новое согласие → охраняемые HTTP-запросы/повторы → сохранение только актуального ответа. Предметы различаются как гарантированные, зависящие от ветви и отсутствующие; получение в одном пути не выдаётся за уже выполненное действие на всех путях.

Область — базовые маршруты до социальных NPC-ветвей, не текущий сейв и не знание собеседника. Отчёт связан с archive/blueprint/source/plan/hero/conversation hashes. Неизменяемый тип создаётся из strict import, не из JSON модели. Все отправляемые поля входят в показываемые данные и согласие; скрытого дополнения после подтверждения нет.

Перед каждой попыткой (также 429/обрыв/timeout), после ответа и внутри writing-lock сверяются авторские версии. Свои сохранённые пакеты двигают ожидаемую ревизию; чужие предметы/герой/реплики прекращают отправку и не должны быть затёрты. SnapshotDigest дополняет числовой revision без миграции checkpoint. Выключение облака и отмена останавливают новые запросы. Готовые и ручные реплики не пересылаются.

Десять новых test/testWidgets охватывают реальную compiled книгу с выбранным героем и двумя NPC, два варианта ключа, точные payload, отсутствие согласия/guard, 429/resume, чужие правки, отмену/failed-write, запрет модельных эффектов, повреждённый архив/область, SQLite restart/replay и 360dp диалог согласия. Транспорт подставной; живой GLM не вызывался.
