## Что пользователь получает

Один завершающий этап в прежнем процессе: финальный сюжет/герой/предметы/NPC → текст всех сцен и двух развязок → новое полное одобрение → прежняя установка автономной игры. Вариант оставить старый текст не делает облачных запросов. Готовые и ручные сцены сохраняются, новый запрос охватывает лишь отсутствующие; каждый пакет записывается до следующего. Старая редакция, ручная правка, отмена или ошибка записи останавливают дальнейшие запросы/применение.

В exact shown payload используются финальный маршрутный инвентарь, цель сцены/акта и общий авторский замысел. Подписанные скрытые реплики и NPC-секреты не включаются. Модель не подаёт игровые правила. При применении один narrator paragraph добавляется перед неизменным исходным телом сцены; source words и NPC dialogue сохраняются. Knowledge guards корректируются только по проверенному сдвигу позиции реплики. Механика сравнивается целиком; независимый v3 importer и полный runtime causal audit обязательны.

## Приёмка и ограничения

11 новых тестов включают полный fake-API/durable storage/restart/strict ZIP/две развязки/SQLite путь с ключом и двумя NPC, сравнение всех механик, скрытие неразрешённой реплики, 429/отмену/возобновление, ручной текст, подделки/failed-write и телефон 360dp. Результат этих тестов нужно получить из CI, а не выводить из наличия кода. Локальный Dart/Flutter отсутствует, живой GLM и физические устройства не запускались.

Новый абзац НЕ удаляет старые технические пометки и не доказывает литературное качество. Это следующий рабочий этап общего сценария, а не готовый CANON любого романа. Две разные реальные приватные RU FB2 и живой API остаются отдельной необходимой приёмкой. #118 и PR не закрываются.
