# M2h8f5 — двухэтапная приёмка предметов и знаний по всем пакетам книги

Дата 2026-11-06. Статус: отдельная PR-ветка, основана на M2h8f4; до полного CI не включена в main.

## Что добавлено в программу

В многоактовом мастере после явного разрешения пользователь открывает «Предложения по всему сюжету (пакетная обработка)». Экран M2h8f2 уже сохраняет промежуточные результаты и показывает точные отправляемые фрагменты. Теперь **после завершения всех пакетов** он также позволяет выбрать отдельные кандидатные предметы и знания.

- Каждая предлагаемая операция видна вместе с названием, scene/choice и замечанием об неопределённости. Можно не выбирать ни одной операции и начать обычную пробную RPG.
- До шести кандидатов можно отметить для следующей игры. Читатель ОБЯЗАН написать для каждого отдельную заметку (18–350 символов) и поставить галочку, что разрешает только **частную игровую выдумку**. Так не создаётся ложное утверждение о владении, мотивации или каноне оригинального автора.
- Для выделенного подмножества вызывается единый графовый анализ M2h8f3: если есть противоречие в передаче/расходе вещей между пакетами, экран показывает код и фактическую цепочку действий. Исправление выполняется выбором другого подмножества, а не автоматическим изменением книги.
- Возврат выбранного набора в многоактовую подготовку **НЕ** создаёт кампанию и не выполняет сетевого запроса. В подготовке виден счётчик, можно удалить выбор. Короткий однооконный режим и многооконный режим взаимоисключаются, равно как дополнительное правило, меняющее проверенный план.
- При нажатии «Создать и начать пробную RPG» программа сначала компилирует базовый проверенный частный rich v3. Затем M2h8f4 проверяет исходный manifest/цитаты/план/состояния и формирует хешированную редакторскую приёмку. Пользователь видит **второе отдельное подтверждение** всех выбранных эффектов. Только после него компилируется новый rich v3 с реальными typed `grant_item`, `consume_item`, `learn_fact`, и установка/новая SQLite-кампания.
- Старые игры, архивы, подтверждения других редакций и сохранения остаются неизменными. Ни один экран не отправляет скрытый запрос в GLM. Ключ API не попадает в игровые архивы.
- Widget regression: сохранённый локальный результат открывается без повторного запроса, пользователь выбирает одну вещь/знание и пишет пояснение, возвращается в подготовку, а исходные записи checkpoint сохраняются.

## Ограничения на пути к конечной цели

Это ещё не гарантированное создание полноценной игры по любой книге. Сейчас нет независимой литературной проверки мотивации и владения, полноценного выбора героя и режимов CANON/ALTER_FATE; модель читает только события, привязанные к решениям StoryPlan. Первый принятый комплект ограничен шестью typed эффектами по строгим Dart/Python контрактам — необходимо расширять лимит синхронно и не выдумывать предметы для книг, где их нет.

Для приёмки PR обязательны Flutter/Dart/Python/SQLite/Windows/Android CI, затем реальные FB2-испытания двух различающихся книг на устройствах с явно разрешённым Z.ai API. Никаких фиктивных старых пользовательских сохранений и миграций.
