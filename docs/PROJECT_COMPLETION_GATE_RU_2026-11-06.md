## Готовность P0: чеклист

- [ ] **Источник игрового знания.** Все NPC знания, права на реплики и изменения отношений проверяемы относительно главы/события, устойчивого `character_id`, результатов действий и редакторских подтверждений. Нельзя предвосхищать события или угадывать личность по имени. Прогнать tamper/alternate paths/restart.
- [ ] **Полный сценарий.** Пройти путь индексация всей книги → StoryPlan → согласованные GLM акты → независимая литературная проверка/ограниченные исправления → игровой `.bworld`; автоматические ограничения причинности, логики предметов и пропусков. Значимые решения и последствия.
- [ ] **Режимы и герой.** CANON не нарушает подтверждённые события; ALTER_FATE имеет минимум две осмысленные последовательные ветви; выбор героя только из реально поддерживаемых персонажей. Никаких ложных обещаний режима.
- [ ] **Простой UX.** Один понятный мастер FB2 → герой/режим → прозрачный бюджет и точное согласие на GLM → прогресс/возобновление → игра офлайн. Экспертные редакторы — опциональны.
- [ ] **Содержательные диалоги.** Структурированные реплики с подтверждённой идентичностью и доступными в этот момент знаниями; UI поочерёдных реплик, локальные портреты, герой/предметы/журнал доступны; никакие реплики не меняют состояние тайно.
- [ ] **Два реальных E2E.** Два разных русских FB2 (в т.ч. «Король-лягушонок» с проверкой прав на конкретный перевод), настоящий GLM 4.7 Flash, прозрачные согласия/расходы; оба типа сюжета, restart/replay/offline на реальных Windows и Android; ошибки 429, отмена, повторы и битые миры.
- [ ] **Финальная приёмка релиза.** Действительные CI на точном PR HEAD + post-merge main: Python/Dart/schema/SQLite, Flutter, независимый CLI-Dart, `ci_check_engine_boundaries.py`, Windows portable, Android APK, M0 и SHA256 артефактов. Ручной UX-аудит на реальных устройствах. Согласованная документация и отчёт 1.0.

## Архитектурный стоп-кран

Целевой движок **не создаётся заново** и **не выносится в отдельный репозиторий сейчас**. `story_core` владеет правилами и последствиями; `story_runtime_adapter` — интерфейсом сцен/вариантов; `bookworld_format` — строгими контрактами `.bworld`; `campaign_manager` — кампанией/SQLite/save/replay. Flutter/UI/GLM — внешние клиенты. Любое расширение NPC/диалогов/отношений, которое должно путешествовать в `.bworld`, обязано быть явно версионировано и проверено двумя импортёрами (Dart/Python). Запрещены зависимости `packages` → `apps` и отключение CI для приёмки. См. [архитектуру](ENGINE_STANDALONE_OPEN_SOURCE_ARCHITECTURE_RU_2026-11-06.md).
