# AI Story RPG — путь до готовой версии 1.0

**Дата актуализации:** 2026-11-06. **Текущая функциональная база:** main `a19f7ea5851a60a1ab174d2b0f7939c89cbe9708` после PR #121/#122. **Это критерии выпуска, не утверждение о готовности 1.0.** Актуальные SHA, Actions и releases проверять заново. Текущий чеклист: [GitHub Issue #118](https://github.com/shonentez-afk/AI-Story-RPG/issues/118).

## Целевой путь обычного пользователя

**«Загрузил FB2 → выбрал действительно поддерживаемого героя/режим → понял стоимость и явно согласился на GLM → программа самостоятельно сделала проверенный сюжет, реплики, действия и последствия → получил .bworld v3/v4 → начал играть офлайн → продолжил с того же места».** Расширенные редакторы должны быть дополнительными, а не обязательными.

## После версии 1.0 (P1/P2, без блокировки первого полноценного выпуска)

- AI-портреты с эмоциями и иллюстрации сцен только из разрешённых источников с отдельным согласием. Поддержка WebP и перенос назначенных пользователем картинок между устройствами с приватностью.
- EPUB и масштабирование больших романов: акты, бюджет запросов, расширенные проверки пропущенных персонажей и событий.
- Роли нескольких героев, расширение отношений NPC, голоса/TTS и звуки при наличии реального спроса и доступности на телефоне.
- Полноценный свободный AI_FREEFORM с формальным контролем действий и ценой, новый офлайн LLM провайдер при ограничениях мобильного устройства.
- Необязательная синхронизация между устройствами и публичный каталог игр только после проверки авторских прав, приватности и совместимости форматов.

## Стоп-факторы и источники

1. Зелёный CI с синтетическими ответами **не равен** корректному литературному пониманию реального GLM.
2. Текущий `.bworld v3` НЕ имеет встроенных подписанных фото персонажей, переносимых между устройствами. Локальные пользовательские портреты PR #117 — временный UX-мост, а не формат персонажей.
3. Не отправлять приватный FB2, текст перевода, токен Z.ai или картинки пользователя в публичный GitHub; авторское право на перевод проверять отдельно от статуса оригинальной сказки.
4. Никаких прежних пользовательских кампаний или старых архивов, требующих миграции, нет.
5. При каждом merge обновлять [START_NEW_CHAT_RU.md](../START_NEW_CHAT_RU.md), этот документ и Issue #118 по подтверждённым результатам.
