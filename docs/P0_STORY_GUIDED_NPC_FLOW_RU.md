# P0 — цель всей истории, мотивы, реплики и автономная игра

## Один путь, не новый движок

UnifiedBookStoryPanel теперь передаёт в прежний редактор ReviewedStoryNarrative — обычный интерфейс MultiActStoryPlanDraft с теми же исполнимыми cross-act условиями и отдельным неизменяемым narrative review. Мотивы не превращаются в story_core facts, flags, secrets или новые правила. Runtime story_core/rich-v3/SQLite, wire-схемы, E6d и main не изменяются.

Авторский callback проверяет exact saved record hash и исходные карточки после навигации. В него не захватывается Flutter State/context. Облачные/компиляторные workers получают только прежние data-only inputs. Открытие/восстановление панели не вызывает сеть и не устанавливает игру.

## Видимый контекст

NpcWritingRequest автоматически включает accepted_story_context только для действительно принятого narrative. Общая цель/конфликт обозначены AUTHOR_APPROVED_PRIVATE_FICTION_NOT_ACTOR_KNOWLEDGE. Для каждого разговора переданы назначение его актов, conditional links и собственный мотив собеседника. Ссылка на ранний исход имеет prior_outcome_has_occurred=UNKNOWN_FOR_THIS_DIALOGUE. Ни обещание, ни обладание вещью не объявляются совершёнными только потому, что условие существует.

Основание мотива сверено прежним parser по постоянному character_id и его проверенным source_event_ids. Для передачи все основания должны лежать не позже первого события разговора в тексте; иначе мотив целиком WITHHELD_FUTURE_SOURCE_BASIS и слова мотивировки не отправляются. Это консервативная граница текстового контекста, не доказательство хронологии или осведомлённости. Общая цель/act purpose остаются планом автора и могут содержать будущие намерения — полной семантической защиты от спойлеров не заявляем.

Другие мотивы, заметки/тайны карточек, имя файла, полный книжный текст и сохранения не добавлены. Дополнительные source quotes конкретного мотива видны в том же JSON, входят в batch ID и consent digest. Размер пакета ограничен; при переполнении создаётся больше показываемых запросов либо явный отказ. Данные не отбрасываются молча.

## Ревизии, запись и сборка

Одна только смена goal/reason может не изменить план игровых состояний. Поэтому narrative.reviewDigest отдельно включён в writing catalog digest, адрес его черновика и финальное авторское согласие. Прежний текст остаётся по своему адресу, не автоматически стирается и не становится одобренным для другой истории. Старые per-act drafts без narrative сохраняют прежнюю форму payload и storage key.

ZaiNpcCampaignWriting требует общий guard для narrative request даже без inventory context; точная версия checkpoint дополнительно перечитывается автоматически перед каждой попыткой/повтором и после ответа, в том числе внутри writing-lock. Отмена, чужие правки и отозванные карточки не разрешают позднему ответу затереть ручную редакцию. Собственные сохранённые пакеты допускают resume только пустых строк.

BookwideNpcCampaignAuthoring.review связывает окончательное одобрение с narrative digest. `.compile` сверяет его с source и проверяет live checkpoint до и после worker. Worker получает только существующий strict reviewed JSON и его writer digest, а не текстовую мотивацию как исполняемое правило. Одобренные реплики попадают в обычную .bworld, журнал и SQLite; сеть при прохождении не требуется. Если поменялась только авторская заметка, а реальные правила и реплики идентичны, wire-архив может быть идентичен; это не перезапись сохранений.

Отдельные файлы не становятся межпроцессной транзакцией. Отправленный HTTP-запрос не отзывается. Формальная проверка/промпт не доказывают литературную истинность сказанного.

## Тесты пакета (проверить новый CI)

Исправлены два прежних regression test ошибки #985 без изменения runtime: альтернативный путь теперь выполняет end_alternative; негативные JSON-мутации реально доходят до parser.

Девять новых проверок:
1. Общая цель и конкретный мотив присутствуют в показанных bytes; чужие мотивы отсутствуют; prior outcome не объявлен фактом.
2. Редакция мотива при тех же mechanics меняет digest/storage, сохраняет ручную строку, отзывает старое install approval.
3. Позднее textual evidence скрывает весь мотив, а не маскирует часть его оснований.
4. Legacy per-act адрес/форма payload не меняются.
5. Никаких POST без точного согласия и author guard.
6. Изменение истории при 429 и после ответа; отзыв карточки; точные writing bytes сохранены.
7. Реальный compiled вариант с ключом → narrative+inventory request → одинаковые retry bytes → отмена после одного сохранённого пакета → resume остальных → human review → strict .bworld → два NPC → финал → SQLite restart с ключом/stateHash.
8. Model effects отвергаются, ручная строка не перезаписывается и не пересылается.
9. Phone 360dp показывает тот же exact context и оставляет consent выключенным; отмена не пишет данные.

Среда чата без Dart/Flutter; локальный PASS не заявлен. API и источник synthetic. CI должен принять точный новый SHA, включая прежние тесты и Windows/Android, прежде чем объявлять общий успех.
