## Завершённая функциональная связка

Один путь, без второго компилятора исполнения: готовый source-locked сценарий выбранного героя → отдельно проверенные предметы и игровые факты → несколько NPC с независимыми знаниями/памятью → строгий импорт rich-v3 → реальная проверка путей StoryWorld → SQLite-игра.

`NpcCampaignConsequences` использует прежние `WholePlanGameplayBatchPage` и `ReviewedGameplayCompiler`. Автор видит исходные цитаты, конкретные действия, получение/использование предмета или игровой факт и пояснение. Открытие редактора не разрешает запросы ИИ или установку. Перед включением требуется отдельное согласие на точную редакцию. Эффекты добавляются до NPC-компиляции, поскольку старый effect compiler ожидает базовую игру без уже созданных NPC-фактов.

Одобрение связано с SHA исходного архива, текущим планом, ролью героя и полным review. Перед включением повторно проверяются карточки. Возвращаемые байты копируются; внешнее изменение массива не может изменить одобренный вариант. Смена роли, архивов, источника или текста требует нового согласия. Включение, удаление и повторная подготовка эффектов отзывают итоговое согласие на всю NPC-кампанию. Перед установкой review заново сверяется с активным архивом.

Все ранее исполнимые действия и концовки проверяются после добавления последствий через настоящий `StoryWorld.apply`, а не только связность сцен. Новый NPC writer затем проверяет прежние и новые действия целиком. Ошибка, тупик, недостижимость или исчерпание бюджета закрывают сборку; лимит не повышался ради теста. При отказе показываются статус, число состояний, недоказанные действия/финалы и реальные пути/причины блокировки.

## Совместимость предметного и NPC-согласования

Ранее `RichPrivateBookworldImporter` прямо запрещал сочетание `gameplay_review` и `npc_knowledge`. Теперь импортёр проверяет строгое объединение двух областей:

- Ordinary review покрывает каждое получение/расходование предмета и каждый факт игрока; actor должен быть `player` для ordinary learn_fact.
- Полный NPC-контракт отдельно доказывает точный tuple `scene|choice|actor|fact` по разрешённой исходной цитате, постоянному NPC, реально существующему эффекту и явному частному review.
- Только этот уже проверенный tuple может покрыть соответствующее non-player learn_fact. Одного `user_confirmed`, совпадения имени/ID факта или любого чужого review недостаточно. Все неожиданные эффекты по-прежнему отвергаются.

Схема ZIP и существующие поля rich-v3 не менялись, старые миры сохраняют свои проверки. Однако новые комбинированные миры требуют обновлённого импортёра: нельзя обещать их открытие в старой версии, которая прямо запрещала такую композицию.

Обновлён независимый Python reference в `tools/bookworld`, НЕ внешний E6d. Старый файл проверяющих функций сохранён без изменения содержимого как `private_rich_validation_core.py`; публичный `private_rich_bookworld.py` использует эти же строгие source/social/dialogue/graph/ZIP/SQLite-проверки и объединяет покрытие эффектов. Временная копия, из которой исключены только уже доказанные NPC-grants, используется исключительно для обычного учёта эффектов, не для обхода игры. Реальный blueprint и архив не изменяются. Monkeypatch/eval и нового игрового runtime нет.

## Проверки на настоящих игровых состояниях

### Герой + ключ + два NPC + восстановление

Синтетический русский источник содержит буквальное слово «ключ» и подтверждённые карточки Артема, Марии и Бориса. Выбранный герой — Артем; его личность сохраняется как реальное начальное состояние, но знания других NPC не копируются игроку.

Успешный маршрут: ролевое наблюдение → разрешённое воспоминание → принятие условия и получение `source_key` → закрытие SQLite с ключом в inventory → повторное открытие с тем же героем и предметом → исполнение условия и расходование ключа → две встречи NPC с независимыми фактами/памятью → финал. Доступность действий, inventory, knowledge, hash-chain replay и переносимое сохранение проверены в production runtime.

Ветка отказа не получает ключ. Использование без получения отвергается. В негативных случаях также проверены иной герой, отозванная карточка, чужой/повреждённый базовый архив, отсутствие согласия и попытка изменить возвращённые байты. Исходный мир остаётся без предметов.
