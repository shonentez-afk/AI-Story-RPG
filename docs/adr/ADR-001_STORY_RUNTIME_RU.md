# ADR-001: Выбор сценарного движка для AI Story RPG

**Дата:** 2026-11-01
**Статус:** ПРИНЯТО — основной runtime story_engine, с оговорками по Alpha API.

## Контекст

M0 сравнивал два Pure-Dart движка с независимым эталонным сценарием (11 сцен, 21 выбор, 3 финала), пятью контрольными маршрутами, сохранением/восстановлением и CircleCI.

**Подтверждено пользователем:** CircleCI pipeline #33 зелёный (оба задания `reference-tests` и `dart-sdk`). Из отдельно предоставленного журнала stress: `story_engine` обработал 1000 сцен и 999 переходов за 16 мс; snapshot 121342 байта, restore PASS. Это один синтетический прогон, не промышленный benchmark. `ink_dart` также вошёл в успешный pipeline, но аналогичный stress-замер для него не выполнялся.

## Решение

1. **Основной runtime: `story_engine: 0.1.0-alpha.1`**. Применяется для офлайн-ветвления, детерминированных условий и переходов, сохранения runtime snapshot.
2. **`ink_dart` — опциональный адаптер импорта/отображения Ink-историй**, не второй равноправный хозяин игрового состояния; его сохранения и переменные не должны подменять `.bwsave`.
3. **`story_core` остаётся авторитетным хранилищем фактов**: инвентарь, NPC knowledge, отношения, причинные зависимости, экономика и события — в отдельных структурах / persistence (план Drift), а не только в scalar variables движка.
4. `StoryRuntimeAdapter` отделяет UI/BookWorld от конкретной сторонней библиотеки. Никогда не импортировать чужой `src/`.
5. Нативные сборки Android/Windows и крупные разветвлённые графы остаются следующими критериями M1; проведённые M0 тесты их не доказывают.

## Альтернативы и риски

- `ink_dart` удобен для авторинга диалогов и совместим с Ink, но требует предварительной компиляции `.ink` и согласования состояния с нашим world core.
- `story_engine` ранняя alpha: закрепить версию, автоматические контрактные тесты и migration strategy.
- Зависимость от стороннего проекта BSD-3-Clause требует сохранить LICENSE/атрибуцию при поставке.

## Исполнение

Первый Flutter host находится в `apps/story_reader`. Это M1 source scaffold, **не подтверждённый APK или EXE**. Создание platform folders `android/` и `windows/` происходит командой `flutter create --platforms=android,windows .` в приложении, после установки Flutter.
