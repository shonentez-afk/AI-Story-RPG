## Что добавлено

- `source_narrative_extractor.dart`: детерминированные русскоязычные шаблоны для очень узкого диапазона предложений: явно названный субъект + прошедшее действие («Артем открыл дверь»), конкретное состояние («Дверь была открыта»), явная связка «X по прозвищу Y» / «X также известный как Y». Сопоставление — по исходным UTF-16 spans с SHA-256 через `SourceEvidence.propose`, статус **INFERRED**. Слова в цитате могут быть ложным показанием/слухом/переходом между событиями; обычная регулярка не устанавливает их истинность.
- `possibleConflicts`: только **возможное** расхождение одного свойства в разных главах, например «открыта» vs «закрыта»; `isProvenContradiction=false`. Состояние могло измениться по сюжету — никаких автоматических отметок CONFIRMED/CONFLICTED. `explicitAliasHints` предлагает пары на основании явных оборотов, `possibleCrossChapterMatches` из M2b3a — одинаковые имена между главами; `identityConfirmed=false`, персонажи никогда не объединяются автоматически.
- `story_evidence_review_session.dart`: независимая возобновляемая очередь по чанкам с bounded batch, source fingerprint, `scanned_chunks`, `SourceEvidenceGraph`, подтверждениями пользователя. JSON checkpoint с SHA-256 и повторной source validation. Вложенный граф 12 MiB max, 12 000 evidence candidates max; превышение лимита останавливает анализ без ложного успеха. SHA — проверка случайной порчи, не криптографическая подпись пользователя.
- `source_analysis_checkpoint_repository.dart`: совместимый новый `SourceCheckpointScope.narrativeEvidence` с **другой папкой** `ApplicationSupport/ai_story_evidence_review_v1`. Старый `ai_story_source_analysis_v1` для M2b1 не изменён. Сохранять новые версии атомарно flush-temp/rename, предыдущая успешная порция остаётся при ошибке записи; реальный power-loss на Windows/Android не сертифицирован.
- `source_narrative_review_panel.dart`: **не новый экран/библиотека**, а сворачиваемый раздел в существующем `SourceIndexPreviewPage`. Сначала только закрытая панель; хранилище читается по явному открытию, извлечение — после отдельной кнопки. Обработка по 24 чанка через `Isolate.run`, checkpoint после каждой порции, «Пауза», возобновление после повторного открытия. Превью цитат/алиасов/расхождений скрыто до «Показать утверждения (возможны спойлеры)»; кнопки «Подтвердить текст», «Пометить спорным», «Отклонить цитату». Ручное подтверждение — проверка **существования точной цитаты**, НЕ канона и НЕ готовой сцены. Reset с диалогом удаляет лишь это отдельное evidence checkpoint.

## Честные ограничения и долги

1. Это **не ИИ**, не произвольный смысловой парсер русского языка, не анализ всех персонажей/временных линий и не готовая RPG из книги. Извлекается только крайне узкий поднабор синтаксиса. Ложноположительные и пропущенные результаты возможны; нечёткие предложения, отрицания, диалоги/атрибуция, переименование и временной контекст требуют модели и ручной проверки.
2. Не реализован надёжный identity-resolution по разным падежам и именам, подтверждение алиасов как отдельных типизированных связей, causal timeline, semantic confidence, spoiler-safe narrative planner или разрешение сюжетных конфликтов.
3. Ожидаемая нагрузка 20 МиБ/30k чанков и checkpoint в JSON может потребовать SQLite incremental graph и оптимизацию поиска SourceChunk; в M2b3b **не проверена** на реальных больших романах. Нет автоматического фонового анализа при закрытом окне.
4. `gameplay_coverage=0`, `can_publish_bookworld=false` — **без изменений**. Никаких автоматических .bworld, нелицензированных публикаций или правок `CampaignStore`, `.bwsave`, `BookStorage`, `WorldLibraryGateway`, главного меню.
5. M2b3c / M2b4: alias-identity decision graph с проверкой ссылок и конфликтов; расширение фактов/событий на сменяемый локальный/облачный провайдер **с явным согласованием загрузки текста**, source-cited semantic extraction, chronology/conflict and spoiler policy; затем проверяемый промежуточный blueprint до компиляции в playable BookWorld.
