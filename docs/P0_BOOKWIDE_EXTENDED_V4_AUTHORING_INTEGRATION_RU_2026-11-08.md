## Что реализовано

1. **Источник → редакторские проверки → rich-v4, без обходного v2.** `PrivateClassicScenarioTranslator.translate(expanded:true)` использует тот же `PrivateAdaptationPreflight`, граф точных цитат, семантический каталог, явное редакторское согласование, причинную проверку и private-only права. Путь `compileReviewedExtendedPrivateBookworldInWorker` собирает отдельный v4 нативным Dart isolate. `RichPrivateBookworldWriter.buildReviewedExtended` использует **общий** код преобразования проверенного источника в rich-презентацию с существующим legacy v2→v3 методом, а не второй движок или копию правил.
2. **Приведены в соответствие ёмкости промежуточных данных.** `StoryPlan.validate(expanded:true)` и `IntermediateStoryBlueprint.validate(... expanded:true)` — до 1024 сцен, 64 флагов, 8000 проверяемых состояний; увеличенные checkpoint-границы включаются **только** явно. Старые лимиты v3 (192 сцены, 32 флага, прежние размеры JSON и 2500 состояний) остаются default. Формат v4 создан на предыдущем этапе; данный пакет подключает к нему реальное авторство.
3. **Многоактовая компиляция с подтверждённой полнотой.** `BookwideStoryPlanComposer.compose(expanded:true)` помечает draft целевой версией и имеет верхнюю границу 30 актовых предложений. Это только кандидатная **ёмкость**: реальный сценарий проходит все bounded causal gates и может быть отклонён намного раньше, если число состояний растёт экспоненциально. `MultiActTrialCompiler.compile(expanded:true)` строго требует ту же метку, подтверждённый source fingerprint, каждый обнаруженный event в исполнимых source-decisions и отсутствие непокрытых глав. Роль героя, reviewer prose, source encounters, cross-act continuity, NPC arc и финальный `CompiledCampaignCausalGate` используют версионированные проверки; неоплаченные знания и спойлеры не разрешены.
4. **Автономная команда CLI.** `dart run bin/author_book.dart build-draft-extended source.fb2 reviewed_checkpoints.json full.bworld` — новый путь из точных сохранённых редакторских checkpoints без Flutter или сети. Старый `build-draft` остаётся v3. Для v4 с расширенным произвольным NPC knowledge-конвертом, который пока не имеет полной версионированной приёмки, компилятор **fail closed**, а не пропускает доказательства.
5. **Сценарий/сохранения/формат не дублируются.** Тот же `story_core`, `bookworld_format`, SQLite каталог и `campaign_manager`; никакого второго игрового исполнителя. Старые игровые архивы не преобразуются молча.

## Что всё ещё не готово

**Не считать завершённым «передал любую книгу → полноценная литературная RPG».** 30 актов не гарантируются: пространственно-временная достижимость и память обо всех бинарных исходах создают экспоненциальный рост, при превышении 8000 состояний сборка **корректно отказывает**, а не усечёт книгу. Требуется крупный отдельный проход с безопасным поактным causal-proof / границами сохранённой памяти и контролем лора. Разобрать full CANON/ALTER_FATE/AI_FREEFORM и исходные знания/инвентарь генератора, а не только поддержку этих данных форматом v4. Облачные GLM proposals проходят пользовательскую проверку; не исполнять непринятые факты.

**UI не принят физически:** мастер «библиотека → сценарий → утверждение → RPG», Герой/Предметы/Журнал/NPC/диалоги/портреты и стоп-кнопка AI имеют ранее зафиксированные разрывы. Нужны реальные русские FB2 (не только синтетические тесты), полный Windows/Android проход, сохранения `.bwsave`, исследования на 280dp/200% масштабе, офлайн/429/Resume.

## Следующий ОДИН функциональный пакет, не дробить

**Безопасный актовый контракт длинных книг с завершаемой причинной проверкой:** продумать формально обоснованную поактовую проверку и итоговую связность с долговременными событиями/знаниями NPC; не увеличивать просто maxStates, не сбрасывать последствия и не считать текстовый порядок хронологией мира. Внести в единый `story_authoring` и `story_core` только после fail-closed тестов. Затем довести единую пользовательскую цепь и игровую UI-проекцию по [плану](DESIGN_UNIFIED_BOOK_TO_RPG_PATH_AND_AUTONOMOUS_AUTHORING_RU_2026-11-08.md), без копирования runtime. Два настоящих RU FB2 и проверка Win/Android обязательны для приёмки. PR #133 оставлять Draft до выполнения.
