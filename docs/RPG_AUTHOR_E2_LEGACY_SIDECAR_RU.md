# E2 — приватная сборка BookWorld v2 с отдельной атрибуцией

**Ветка:** feature/external-rpg-author-e2-legacy-sidecar-20261105.
**Изменения:** только внешний генератор, его тесты и документы. Flutter и основное приложение не меняются.

## Что означает legacy mode

Текущий BookWorld v2 требует model_provenance={"provider":"none","model_id":null}
в manifest.json и source/provenance.json. Это ограничение формата упаковки,
а не свидетельство того, что ИИ не участвовал в написании сценария.

ЭКСПЕРИМЕНТАЛЬНЫЙ режим build-legacy существует только по явному согласию,
не стирает внешнее ИИ-авторство из рабочего проекта и создаёт рядом с пакетом
файл attribution.json, связанный с конкретным .bworld посредством SHA-256.

Старое приложение этот внешний JSON НЕ читает и НЕ проверяет. Если перенести
только .bworld, происхождение сценария станет неполным. SHA-256 не является
электронной подписью и сам по себе не подтверждает личность автора.

Публикация не разрешена: rights_status=private_use_only;
publication_authorized=false.

## Использование на отдельной книге

Python 3.12. Все пути рабочей книги и результатов находятся ВНЕ репозитория.
Сначала создать проект:

    python3 -m tools.rpg_author init --book /private/story.fb2 --project /private/story-project

Последовательно получать задания next, сдавать структурированный анализ
через accept-analysis, итоговый сценарий через accept-story и проводить validate.
Точные цитаты должны совпадать с индексом; ИИ-интерпретации не считаются
проверенными литературными фактами автоматически.

Когда проект завершён, запускать:

    python3 -m tools.rpg_author build-legacy --project /private/story-project --output /private/trial.bworld --model-id gpt-6 --ack-legacy-provenance
    python3 -m tools.rpg_author verify-bundle --input /private/trial.bworld --attribution /private/trial.attribution.json

--model-id является декларацией пользователя, а не независимым доказательством
используемой модели. При отсутствии подтверждённого ID опцию можно опустить:
атрибуция сохранит модель как null / not_attested.

Создаются файлы:
- trial.bworld (ровно manifest.json, scenario/blueprint.json,
  source/provenance.json, world.sqlite; старый формат ZIP_STORED v2);
- trial.attribution.json (с указанием ChatGPT/OpenAI и хешем архива).

## Как защищена совместимость

Авторские текстовые идентификаторы утверждений детерминированно преобразуются
в 32-символьные шестнадцатеричные legacy ID. Для каждого процитированного
утверждения восстанавливаются глава, блок, chunk, точные UTF-16 границы,
SHA-256 цитаты и момент её доступности. Используется неизменённый
tools.bookworld.private_bookworld.build(); он проверяет цитаты по локальному
индексу, создаёт SQLite и архив. Затем запускается его независимая verify().

Режим не устанавливает мир и не переписывает сохранения. Старый build
по-прежнему заблокирован, если сценарий был создан внешним ИИ; никакой
автоматической подмены авторства не происходит.

## Проверки и ограничения

CI проверяет оба поля model_provenance, четыре записи ZIP, реальные ссылки,
SHA-256, детерминированную сборку, отказ без явного согласия и безусловный
запрет перезаписи. Нужна ещё независимая проверка реального Dart-импортёра,
а затем E2E на Windows/Android и отдельная оценка художественного качества.
Смысл сцены, мотивы персонажей и права на конкретный перевод формальные
тесты не сертифицируют.

Постоянное решение — новая версия BookWorld, которая хранит фактическое
авторство внутри пакета и не зависит от отдельного файла.
