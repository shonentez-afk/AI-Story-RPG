# Полный проход UX/UI — меню, библиотека, открытие книги, настройки (2026-11-02)

## Проверено по фактической структуре приложения

1. Главное меню: одна библиотека, «Новая история», продолжение и Settings; не создавались вторые импорт/библиотека.
2. Библиотека: поиск, сортировка, подсказки пустой библиотеки, единая кнопка импорта TXT/FB2/.bworld, список книг, удаление с подтверждением, открытие книги касанием, доступ к подготовке книги.
3. Открытие TXT/FB2: FilePicker с данными, лимит 20 МиБ, парсинг в отдельном изоляте, сохранение файла, восстановление позиции, оглавление/закладки, главы, иллюстрации и настройки чтения. Для .bworld отдельно лимит 12 МиБ, проверка перед установкой.
4. Настройки: оформление светлое/тёмное; палитры Свет/Сепия/Тёмная/OLED, шрифт, межстрочный интервал, поля; режим игры, проходжения, импорт/экспорт .bwsave и информация о тестовой версии. Работающий облачный AI/выбор локальной модели ещё НЕ реализованы, поэтому отсутствуют в настройках сознательно.
5. Раздел «Подготовка книги»: offline source chunks, review цитат, spoiler gate, отношения и время событий. Важный UX-долг — много вложенных действий; прямой вход в подготовку теперь доступен из карточки книги.

## Исправления в этой ветке

- В каждой карточке импортированной книги добавлена отдельная иконка **«Подготовить книгу»**, рядом оставлено существующее меню действий. Нажатие по самой карточке по-прежнему открывает книгу на чтение. Это устраняет основной навигационный барьер, не создавая второй библиотеки.
- Настройки теперь показывают актуальное описание возможностей: офлайн RPG, отдельный локальный анализ книги и отсутствие генератора игровой RPG из произвольного романа. Убрана ложная жёстко прошитая метка версии «0.1.0»; для точного номера сборки в будущем требуется build-time package metadata, сам номер пока не выдуман.
- В шторку настроек чтения добавлена понятная кнопка «Готово», не требующая жестов или системной кнопки назад.
- В открытии книги восстановление состояния защищено от сбоя доступа к preferences. Некорректный JSON, устаревший номер главы и некорректные якоря не должны закрывать книгу.
- Добавлены проверки старого читательского UX, повреждённого/устаревшего состояния, явного закрытия настроек и точных подписей на странице настроек.

## Отдельно оставлено на ручной QA

- Физические Windows/Android: системный FilePicker, открытие реальной FB2 с изображениями, сворачивание приложения и восстановление после kill, поворот экрана и изменение шрифта на устройстве, системный Narrator/TalkBack, UI на 320dp с 200% размером текста, доступность и power-loss.
- Испытание больших TXT/FB2 20 МиБ, больших иллюстраций, долгих глав, файлов с неправильной кодировкой и сильного повреждения базы на физическом устройстве.
- Неверный формат обложки защищён Image.errorBuilder, проблемный файл библиотеки пропускается; стоит отдельным шагом показать пользователю количество пропущенных повреждённых файлов, не раскрывая содержимое. Запись настроек чтения остаётся best-effort через SharedPreferences и требует отдельного fault-injection с реальным устройством.

## Критерий приёмки

Не объявлять весь физический UX проверенным по widget-тестам. Сначала GitHub Actions **точного HEAD PR**: Flutter analyze/все widget, Dart/Python/world contracts, Android APK, Windows portable. При FAIL исправить и повторить. После PASS можно объединить PR и зафиксировать состояние в START_NEW_CHAT_RU.md и STATUS/ROADMAP. M2b4 semantic provider пока не реализован.
