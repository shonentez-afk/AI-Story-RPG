## 5. Приёмка и решение

## Дополнение после CI UX hotfix #135 (2026-11-02)
- Workflow `41332089654` по `3560ba54` (первый UX коммит): Python PASS, Dart PASS, Flutter analyze PASS, widget tests **FAIL 6**, Android/Windows SKIP. Новые узкое меню, OLED, журнал, финалы, FB2 и настройки прошли, но обнаружилась одна связанная проблема: `BookStorage.all()` в widget-test окружении может не завершиться (нет platform storage). `LibraryPage` показывала бесконечный `LinearProgressIndicator`, отчего `pumpAndSettle` тайм-аутился. `HomePage._open` держал навигационный lock до завершения `_refresh()` всей библиотеки, поэтому после возврата из игры «Продолжить» могло игнорироваться.
- Корректировка: снять lock сразу после `Navigator.pop`, обновление Home запускать через `unawaited(_refresh())`; чтение `BookStorage.all()` ограничить `timeout 8 s`; ошибки показывать без удаления книг, предложить явный `Повторить загрузку` и разрешить импорт. Загрузки RPG и книг остаются отдельными, старые данные не меняются.
- Дополнен widget-контроль пустой библиотеки в среде без storage plugin. Повторить **весь** CI, проверить 6 предыдущих отказов и обе платформенные сборки, не объявлять PASS до полного успеха.

## Проверка жизненного цикла тайм-аутов книги — CI #137
- Workflow `41332360623` по `ef004a4`: Python/Dart/Flutter analyze PASS, но Flutter widget tests FAIL в разных экранах с одним повторяющимся исключением `A Timer is still pending even after the widget tree was disposed`. Задания Android/Windows SKIP. Причина: `Future.timeout(Duration(seconds: 8))` для чтения `BookStorage` на главной создаёт таймер, который переживал маршрут при бесконечно ожидающем платформенном вызове. Проблема обнаружена инструментальными тестами, а не экранами пользователей.
- Следующая правка удаляет timeout у независимого фонового считывания книг на главной (не влияет на RPG); в `LibraryPage` вводится `Future.any` с владельцем-виджетом контролируемым `Timer`, регистрацией таймеров, `dispose().cancel()`, 8-секундным понятным отказом и повторной попыткой, с защитой поколения запросов от позднего ответа. Так UI остаётся отзывчивым и не создаёт таймеры, переживающие экран.
- Результат повторного CI обязательно зафиксировать, не путать `flutter analyze` PASS с общим состоянием CI.

## Фактическая UX-проверка пользователем: дублирование библиотеки и импорта (2026-11-02)
Пользователь установил приложение и подтвердил работоспособность, но выявил неудобство, пропущенное кодовым аудитом: на Home одновременно карточка «Библиотека», отдельный горизонтальный блок «Моя библиотека» и кнопка «Все книги» вели в один и тот же каталог; внутри каталога импорт дублировали верхняя иконка, пустое состояние и состояние ошибки. На телефоне это создавало ложное впечатление двух библиотек и нескольких способов импорта.

**Исправление UX-15 (P2):** на Home оставлен **один** основной вход «Библиотека»; отдельная горизонтальная полка и «Все книги» убраны до появления настоящей модели `lastOpened`. Главная больше не сканирует файловую библиотеку в фоне. В `LibraryPage` оставлена **одна** явная `FilledButton.icon('Добавить книгу')` под демонстрационной RPG; app bar import-иконка и повторные кнопки пустого/ошибочного состояния удалены. Поиск, сортировка, реальный список и удаление книг, демо RPG, `BookReaderPage` и `CampaignsPage` без изменений. `TXT/FB2 <=20 MB` указан под кнопкой.

**Проверка:** тесты явно требуют отсутствия «Моя библиотека»/«Все книги» на Home и ровно одного `library-import` в каталоге при пустой библиотеке. GitHub Actions запуск/результаты — зафиксировать по commit после публикации. Реальная визуальная проверка исправленной версии на телефоне ещё SKIP.
