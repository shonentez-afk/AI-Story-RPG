## Зачем

Следующий этап после причинного rich-v3 NPC-планировщика — научить Z.ai предлагать *художественные* разговоры без возможности изменить правила уже собранной игры. На текущем этапе можно улучшать текст **существующей** одобренной диалоговой сцены, а не получать готовую полную книгу автоматически.

## Контракт

1. В обычном интерфейсе сборки NPC автор указывает источник знания, говорящих, условия, мотивы и подписывает game-fiction сцену.
2. Готовый архив строго проходит `RichPrivateBookworldImporter`. Отдельный `NpcDialogueDraftContext` повторно проверяет source-origin и `RichNpcDialogueKnowledge.validate` для всех сцен; при отсутствии проверенного диалога запроса нет.
3. `NpcDialogueDraftPage` показывает точный payload (одна сцена, все имена/role IDs, факты и выборы); пользователь отдельно подтверждает возможный платный запрос в Z.ai. Название книги, полный FB2, соседние сцены, fingerprint, API-ключи и игровые сохранения не добавляются.
4. `ZaiNpcDialogueDraftService` запрашивает только новые реплики **для существующих** speaker/turn_index. Строгий парсер не допускает новых персонажей, пропусков, дублирования или иных полей. Нарративные строки, choice/effects и source-meta не изменяются.
5. Ответ `NpcDialogueCloudDraft` всегда непроверенный черновик, без прав установки; UI предлагает только копирование для обычного редактора. Требуется литературная и причинная проверка человека, и повторная сборка новым `RichNpcDialogueAuthoring`/rich-v3 writer перед появлением текста в игровой кампании.
6. После сборки готовые `.bworld` работают без Z.ai, Flutter UI или сетевых вызовов в логике `story_core`, с исходным SQLite replay.

## Риски, намеренно не скрываемые

Структура ответа может быть корректной при фактически неправильном знании героя, ложном мотиве или нарушении смысловой хронологии. Это задача предстоящей литературной проверки, а не доказательство канона. API-ключ не сохраняется в новых файлах, облачная отправка не автоматическая. Публичная публикация адаптации требует отдельной проверки прав.

## Тестовый барьер

Отдельный тест должен взять реальные **синтетические, но полностью подписанные** rich-v3 байты, импортировать, проверить исходную цитату и NPC knowledge, разрешить один строго согласованный запрос и отклонить подмену имён, ходов и текста нарратора. Он должен проверить отсутствие запросов при отсутствии согласия/ключа, повтор 429 идентичным payload, экран согласия и запрет установки; далее exact-head GitHub CI/M0/Windows/Android.

**После успешной приёмки:** source-reviewed мотивы/отношения и route-specific разговоры по всей книге, подтверждение ответов игрока и последствия, затем настоящий полный книжный авторский компилятор (не E6d) с CANON/ALTER_FATE и без устаревших лимитов.
