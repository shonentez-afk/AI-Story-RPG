# P0 — текст полного прохождения в существующей автономной игре

## Один функциональный результат

После общего сюжета, выбранного героя, предметов и нескольких NPC пользователь может подготовить повествование для всех сцен, включая обе развязки. Новая страница является последним этапом прежней установки, не второй библиотекой и не другим runtime. Можно явно оставить прежний текст, не обращаться к ИИ и продолжить установку. Отмена не устанавливает частичную игру.

## Привязка и контекст

`CampaignProseManifest.prepare` независимо импортирует именно финальный архив, проверяет героя/источник/полный набор сцен, выполняет StoryInventoryRouteAudit с финальным socialRulebook в data-only worker. Обход не симулируется вторым алгоритмом. Контекст включает цель/конфликт конкретной сцены, общий авторский замысел, назначение её акта, точный разрешённый source excerpt, возможные игровые намерения и always/branch-dependent/never inventory. Скрытые подписанные реплики NPC, произвольные заметки карточек, ключ API и сейвы не пересылаются.

Общий замысел остаётся авторской гипотезой, а не знанием NPC. Перечисленные действия являются будущими возможностями, не совершёнными поступками. Контекст не доказывает литературную правду, время мира или вероятность маршрута. JSON показан до согласия и в неизменном виде служит user message. Лимиты: до 192 сцен, 2 MiB общей карты, до трёх сцен на запрос, до 24 KiB показанного пакета; крупный пакет дробится без пропуска сцены. Ошибка/неполный route audit блокируют подготовку, не дают ложное всегда/никогда.

## Сохранение, повтор и ручная работа

`CampaignProseStore` использует прежний приватный SourceAnalysisCheckpointRepository, отдельный адрес по exact manifest/archive/story revision. Хранятся только подготовленные/ручные абзацы и пометки автора, не разрешения на облако/установку. Повреждение не приводит к молчаливому сбросу. Сравнение recordHash+revision и очередь записи одного процесса не позволяют запоздавшему ответу затереть новую ручную правку. Межпроцессной или многофайловой атомарной транзакции не обещаем.

`CampaignProseRequest` выбирает только отсутствующие сцены. Модельные предложения не меняют ручные тексты. После каждого полностью проверенного пакета выполняется запись, затем следующий POST. Повторы 429/временного обрыва/тайм-аута ограничены тремя попытками с теми же bytes; неверные credentials/квота/неподходящий Retry-After не маскируются. Проверки автора, настроек и отмены выполняются до попыток, после ответов и перед сохранением. Ушедший запрос отозвать невозможно; устаревший ответ не должен стать одобренной игрой.

## Применение без изменения правил

`ReviewedCampaignProseWriter` — чистый Dart в прежнем bookworld_format. Принимает только точный baseline и полный набор сцен 80–1800 символов. Один абзац, русский текст, без контролов, кавычек, двоеточий и переносов: это повествование, не дополнительная прямая речь. Новые абзацы добавляются перед ВСЕМ старым телом сцены, сохраняя исходные цитаты, прежние технические пометки и принятые диалоги дословно. Это осознанная граница текущей версии: не выдавать её за полностью переписанную, избавленную от технических надписей художественную книгу.

Для подписанных диалогов parse/verify подтверждают ровно один новый narrator turn и побуквенную неизменность всех прежних turns. Меняются лишь scene_text projection и +1 turn_index старых knowledge review. Ни говорящий, ни spoken text, ни memory/fact/trust gates не переопределяются. Не прошедшая парсер структура отказывается собираться.

Все поля механики blueprint сравниваются canonical JSON до/после, исключая лишь новый book_id и scene text. Остальные source/NPC contracts сохраняются. Прежний RichPrivateBookworldWriter заново проверяет оригинальный UTF-16 источник, собирает SQLite/ZIP и запускает независимый importer. Реальный StoryCampaignCausalAudit обязан подтвердить ВСЕ прежние решения, финалы и отсутствие тупиков. Новая игра имеет другой ID, старые кампании остаются. Авторский текст не может подавать effects/actors/knowledge/rights/permissions и не выдаётся за доказанный канон.

## Написанная общая приёмка — проверить exact CI

11 тестов в `campaign_prose_flow_test.dart`:

1. Полный конечный scene set, обе развязки, истинные inventory states до выдачи/в слиянии ветвей/после расходования; отсутствие скрытой речи в запросе.
2. Общий сюжет → герой → ключ через три акта → два NPC → narration всех сцен → 429 с теми же bytes → реальный диск/reopen → fresh approvals → rich-v3 → оба финала → SQLite restart с ключом → replay/portable. Старые механики сравниваются целиком, условная NPC-реплика остаётся скрытой при пропуске знакомства.
3. Частичное покрытие/нет нового согласия/ручная смена текста блокируют применение.
4. Без согласия, enabled-account или защищённого ключа — ноль POST.
5. Отмена после сохранённой части и продолжение только отсутствующих сцен, ручной текст сохраняется.
6. Изменение общей редакции при 429 или позднем ответе останавливает POST/запись.
7. Конкурентный генератор не стартует, более новая ручная запись побеждает поздний ответ.
8. Effects, выдуманный scene_id, потерянная сцена и прямая речь в ответе отклоняются.
9. Failed-write и checksum-пересчитанный install_consent не дают ложной готовности.
10. Повторно подписанные чужие поля/архив/неполное покрытие отклоняются низкоуровневым writer.
11. Телефон 360dp открывает полный локальный текст без API, оба согласия сняты, итоговая кнопка выключена.

Сейчас код направляется в CI; наличие тестов не означает PASS. Предыдущая принятая база 4cbca1a5 / CI #986 с Windows/Android не подменяет новую проверку. В текущей среде нет Dart/Flutter; локальный запуск не заявлен. Реальные книги/живой GLM/физические устройства не проверялись.

## Открытые границы

Полноценный CANON, произвольный нелинейный роман вне прежних форм дилемм, художественное качество и отсутствие смысловых противоречий/спойлеров не сертифицируются структурным JSON или route-аудитом. Итоговый абзац нужно читать автору. Для проверки двух реальных русских FB2 необходимы их доступные байты и живое подключение; повторный поиск в доступных файлах этой сессии не дал исходных приватных книг. Нельзя выдать синтетический пример за пользовательскую книгу.
