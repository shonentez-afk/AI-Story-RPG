# M2h7c5 — независимая литературная проверка сцены с помощью GLM

Статус: отдельная ветка. До exact-head CI, merge, post-merge release QA — НЕ принято.

## Проблема

Формальные проверки BookWorld гарантируют структурные условия, но не литературный смысл. GLM 4.7 Flash должен не только писать художественные сцены, но и искать гипотезы ошибок: что NPC не мог знать, персонаж ещё не получал предмет, обещание не принято, события ошибочно связаны причиной, неверен порядок времени или последствия выбранной ветки.

## Контракт

- Отдельное пользовательское согласие на отправку уже готовой прозы и контекста конкретной сцены. Согласие на генерацию НИКОГДА не разрешает эту дополнительную проверку. Нет сетевого вызова при простом открытии.
- Context digest привязан к исходной редакции, полному плану, ID сцены, SHA исходного черновика, model ID и фактическому отправляемому контексту.
- ИИ видит только одну source-locked цитату (или none), goal/conflict, существующие действия и флаги, сгенерированный текст и его неопределённость. Не отправлять весь файл книги или кампании.
- Строгий русский JSON: scene_id, verdict (possibleConsistency / needsRevision / insufficientEvidence), findings (до 6: kind, severity, problem, evidence_quote) и uncertainty.
- Допустима только вся ДОСЛОВНО проверенная цитата уже выбранного source event, иначе null. Чужой scene ID, неизвестный verdict, дополнительный флаг CANON_APPROVED, обрыв JSON, неподтверждённая цитата — fail closed.
- Даже possibleConsistency — только рекомендация модели. При отсутствии исходной цитаты положительный вывод запрещён; при high-risk замечании positive verdict отклоняется. Никакие слова модели не утверждают автоматически CANON, предметы, правила, знания NPC или состояние мира.
- Хранить результат в отдельном приватном app-support checkpoint; при повторном открытии точно той же сцены и текста повторная платная отправка не нужна. Повреждённое хранилище блокирует новый запрос.
- До 3 идентичных попыток при временном 429/5xx/обрыве по уже подтверждённому контексту; пользователь может отменить дальнейшие попытки.

## Ограничения и критерии

В первой версии только один исходный отрывок. Ни этот ИИ, ни детерминированный валидатор пока не могут доказать полную литературную достоверность. Для настоящего полного RPG нужно связанное multi-evidence/book-wide семантическое ревью, оценка и исправление всех маршрутов и затем полный GLM E2E.

Проверить ноль POST без второго consent, неверный digest/редакцию/ключ, отклонение лишних полей/цитат, повтор 429 без расширения текста, локальный checkpoint при рестарте, UI без скрытого запроса, отсутствие изменения BookWorld/SQLite, Windows/Android CI. Реальные запросы по приватной книге и API ключу не выполнять в публичном CI.
