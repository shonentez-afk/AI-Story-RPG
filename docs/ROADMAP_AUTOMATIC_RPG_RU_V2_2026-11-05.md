## 1. Один проверяемый целевой результат (MVP)

**Первой принимается настоящая игра по «Королю-лягушонку», а не новая коллекция редакторов и не ещё один экран с цитатами.** Использовать общественное достояние оригинала, а права на конкретный перевод и распространяемый тестовый файл проверять отдельно. Полный закрытый пользовательский текст не публиковать.

Проверяемый сценарий:

1. Загрузить FB2 либо FB2 внутри поддерживаемого ZIP.
2. Выбрать один из действительно работающих режимов; на первом проходе разрешён только управляемый главный герой.
3. Разрешить Z.ai отправку выбранного объёма текста, предварительно увидев бюджет и возможность отмены; либо остаться в честно обозначенной офлайн-пробе.
4. Получить без ручного написания сцен **связанный** сценарий из событий, действующих лиц, игровых ситуаций, условий и последствий.
5. Пройти от начала до завершения по оригинальной линии и по содержательной альтернативе.
6. Например, отказ от условия помощи **не должен** порождать требование исполнить обещание, которого игрок не давал. После отказа появляется не немедленная концовка, а несколько новых оправданных ситуаций.
7. Закрыть приложение, открыть игру снова и получить идентичные историю, предметы, знания и доступные действия. Игра после сборки должна проходиться без облака.

Первый эталон — одна сказка, без условий в рабочем коде вида «если название == Король-лягушонок». Эталонные ожидаемые события и пути допустимы в тестах, но недопустимы как тайная подстановка результата вместо генератора.

**Минимальная приёмка первого полного сценария:** начало и завершение, минимум две содержательно различающиеся развязки для ALTER_FATE, после крупного отклонения хотя бы три последующих осмысленных решения либо документированное обоснование меньшего числа, проверенные последствия и знания, ноль структурных тупиков, сохранение/восстановление, независимая оценка реальной модели. Ориентир 10–20 значимых решений по совокупности прохождений — оценочный, не обязанность искусственно раздувать сказку.

## 3. Критические ограничения, которые план обязан снять

| Ограничение сейчас | Последствие | Обязательное решение |
|---|---|---|
| Quick RPG: до 8 цитат, короткие альтернативные концовки | Нет развития решения | Генератор игровых ситуаций, условий и многоходовых продолжений |
| Отдельный режим кнопки «Сохранить сюжет», но частный переводчик выдаёт ALTER_FATE/CLASSIC | UI обещает больше, чем формат | Явная таблица возможностей + согласованная поддержка CANON или честное переименование пробного режима до её появления |
| Формат допускает лишь PROTAGONIST и определённые сочетания plot/interaction | Другой герой и полный AI_FREEFORM пока не реализованы | Не показывать как готовые, расширять с версионированием схемы, импортера и сохранений |
| CausalPreflight требует >=2 концовок даже при «По книге» | Искусственная дополнительная концовка | Политика терминалов по режиму во всех проверках, без отключения проверки достижимости |
| Проверка source-claim в промежуточном сценарии ограничена chapter-gate, хотя Evidence знает afterEvent | Спойлер возможен внутри единственной главы | Доступ к знаниям по фактически наступившему событию, согласование валидатора и игрового исполнения |
| Все цитаты требуют пользовательского подтверждения для текущего быстрого пути | Не достигается цель «без редактора» | Разделить машинную **точность текста**, смысловую оценку и человеческое решение; не выдавать машинную проверку за действие пользователя |
| Максимум 8 находок за ответ, окно до 5000 UTF-16 и 12 фрагментов | Возможен пропуск насыщенных сцен | Диагностика насыщения и выборочное уточнение, без слепого увеличения лимитов |
| 192 сцены, 32 флага, 2500 состояний | Взрыв вариантов при романе | Сначала малая сказка, позднее акты + явные граничные состояния и межактовая проверка |
| 2000 ходов и ограничения SQLite | Потолок для длинного прохождения | Не менять сейчас; позднее отдельная проверенная миграция |
| Обработанный текст и найденные цитаты не равно правильной интерпретации | Ложный «готовый сценарий» | Смысловая проверка и отчёт о неопределённостях |

**Решение о CANON:** прежде чем писать новую RPG, сделать один документированный контракт режимов. Рекомендуется поддержать настоящие CANON и ALTER_FATE с отдельными правилами компиляции: для CANON возможна одна каноническая развязка; для ALTER_FATE нужны содержательно разные итоги. Пока контракт не поддержан, не называть пробный followBook полноценным CANON.

## 4. Архитектура автоматической генерации

Поток строго односторонний, с сохраняемыми версиями результатов:

    FB2/ZIP → Index + Edition Fingerprint
        → M2g2: Source-Locked Candidates + Checkpoints
        → M2g3a: BookModel (события, персонажи, объекты, знания, неопределённости)
        → M2g3b: StoryPlan (ситуации, цели, выборы, условия, эффекты, зависимости)
        → M2g3c: Structural + Causal + Knowledge Validation
        → M2g3d: Ограниченное исправление контрпримеров
        → M2g3e: Narration/Dialogues без самовольных изменений состояния
        → IntermediateStoryBlueprint → existing Preflight → private .bworld
        → existing SQLite Campaign → offline playable game

### 4.1. Минимальная модель книги (BookModel)

Не более необходимого для первой сказки:

| Запись | Обязательные поля |
|---|---|
| Character | stable ID, упоминания/алиасы, известные цели, источники, статус отождествления |
| Item | stable ID, свойства, владелец/местонахождение, источник/неизвестность |
| Event | stable ID, участники, действие, объект, результат, исходные цитаты, последовательность рассказа |
| Claim | кто произнёс/знает/полагает, истина/ложь/неизвестно/спорно, достоверность, откуда известно |
| TemporalRelation | порядок упоминания **отдельно** от предполагаемого времени действия, возможный флешбек |
| CausalRelation | предпосылка → эффект, статус подтверждения, ссылки на основания и неопределённости |
| Reveal | что стало известно, кому, после какого игрового события, можно ли раскрыть сейчас |

Одинаковое имя не доказывает идентичность. Отсутствие свидетельства не равно отрицанию. Факт из книги и допущение адаптации имеют разные типы происхождения. Никакой будущий секрет не передаётся в обычный NPC-подсказчик.

Каждый вывод получает метку: EXACT_SOURCE (цитата существует), MODEL_INFERRED (смысл только предложен), SEMANTICALLY_REVIEWED (прошёл установленную проверку), ADAPTATION_FICTION (новое разрешённое игровое дополнение), HUMAN_REVIEWED (человек действительно подтвердил). **Не подделывать HUMAN_REVIEWED** автоматическим валидатором.

### 4.2. Модель игрового плана (StoryPlan)

Одна сцена = ситуация и ожидаемые эффекты, а не только красивая цитата.

- situation_id, входные состояния и доступные акторы;
- цель игрока, конфликт и текущие ограничения;
- choice_id, понятное намерение и ближайший риск;
- conditions, effects, предмет/обязательство/отношение/знание;
- nextSituationId для каждой доступной альтернативы;
- источник и статус происхождения каждого книжного утверждения;
- зависимость будущих сцен от фактических эффектов, а не от «главы, которую прочитали»;
- canonical/alternate route provenance и условия завершения.

Сохранить строгий типизированный JSON-контракт с ограничениями размера, ID и ссылок. Генератор не исполняет произвольный код и не обновляет SQLite напрямую. Переводчик маппит валидированный StoryPlan в текущий IntermediateStoryBlueprint и BookWorld.

### 4.3. Сначала правила, потом художественный текст

Планировщик сначала пишет граф ситуаций и состояния. После проверки отдельный шаг пишет текст сцен с разрешённой информацией. Повторный валидатор не допускает «предмет появился из ниоткуда», «обещание нарушено до его принятия», «герой знает секрет до раскрытия» и текстовую подмену эффекта. Проверять смысл текста моделью можно, но модель-проверяющий не является источником абсолютной истины.

## 5. Рабочие этапы и критерии готовности

### M2g2-accept — принять уже написанный анализ всей книги

**Работы:** проверить фактический HEAD PR #65 и его полный CI; провести review согласия, приватности и checkpoint; принять PR в main лишь после этого; получить post-merge CI, Android APK и Windows сборку; обновить STATUS и инструкцию нового чата. Не смешивать с экспериментальным причинным генератором.

**Приёмка:** зелёный exact-head CI + post-merge CI; кнопки анализа доступны только после согласия; отсутствие тихой отправки текста; архив/сохранения не меняются; отдельное испытание на реальном GLM **помечается как непроверенное**, пока не проведено.

### M2g3a — реестр событий, причин и допущений

**Работы:** преобразовать предложения M2g2 в компактный BookModel; объединять участников по свидетельствам, не только по именам; строить два времени (рассказ/события); выделять цели, предметы, обещания, события раскрытия; сохранить сомнения и ссылки на точные источники.

**Приёмка:** для «Короля-лягушонка» один и тот же участник связывается с относящимися к нему событиями без специальных правил по названию; неразрешённые идентичности остаются явно неопределёнными; смена редакции ломает устаревшие ссылки; все ключевые события имеют корректные источники.

### M2g3b — автоматический сценарный планировщик

**Работы:** минимальный типизированный StoryPlan; генерация нормальных игровых ситуаций, мотиваций, preconditions/effects и переходов. Первая механика — «условие помощи → обещание → исполнение/отказ»; затем «поиск/обмен» и «раскрытие тайны». Механика выбирается по содержанию, не навязывается каждой книге.

**Приёмка:** путь принятия обещания и путь отказа развиваются по-разному; минимум одно ключевое решение имеет эффект, который позднее проверяет условие; отказ порождает реальные новые ситуации, а не сразу terminal. Генератор не содержит кода с названием тестовой сказки.

### M2g3c — формальный тест и ремонт противоречий

**Работы:** использовать существующий bounded state explorer; добавить проверки правдоподобия зависимостей, правил знаний, значимости развилок и терминальной политики по режиму. Возвращать минимальный воспроизводимый контрпример (путь выбора + флаги + незаконное событие). Две-три ограниченные попытки исправления только затронутой части, затем повторная общая проверка.

**Приёмка:** «нет обещания → требование обещания» детектируется, передача предмета двум владельцам не проходит, нет безвыходного состояния или цикла без завершения; после исчерпания исправлений остаётся **черновик**, а не молчаливая подмена его коротким маршрутом.

### M2g3d — канонический режим, знания, спойлеры

**Работы:** контракт CANON/ALTER_FATE согласовать в сторидвижке, переводчике, экспорте, импорте и тестах старых пакетов. Для CANON сохранять разрешённые оригинальные ключевые события, для ALTER_FATE отменять зависящие от решения будущие события. Доступ к цитатам и сведениям по **событию**, включая скрытую тайну в одной главе.

**Приёмка:** игра по оригиналу не требует формально придуманного альтернативного финала; альтернативный мир не притворяется каноном; NPC не раскрывает тайну до trigger-event даже при прямом вопросе; старые кампании продолжают открываться.

### M2g3e — художественные сцены, компиляция и воспроизведение

**Работы:** генерация прозы и диалогов по проверенному StoryPlan, затем независимая сверка текста со state/evidence; сборка имеющимся M2c-компилятором; установка **новой неизменяемой версии** .bworld и создание отдельной кампании.

**Приёмка:** минимум две реально разные концовки в ALTER_FATE, источник узнаваем без длинного копирования книги, художественный текст не меняет скрыто состояние, игра проходит без соединения после подготовки, старые сохранения не изменены.

### M2g3f — единый простой UX

**Работы:** внутри «Играть по книге» различать «Быстрая офлайн-проба» и «Полная подготовка с ИИ». Только поддерживаемый герой/режим, оценка объёма и лимита запросов, явное согласие на внешнюю передачу, прогресс по пяти стадиям, пауза/возобновление, отчёт качества и понятная кнопка «Начать игру». Редакторы — «Дополнительно», не обязательная остановка.

**Приёмка:** новый пользователь без знаний об ID, JSON, промптах, цитатных редакторах создаёт сценарий; неготовая игра называется «черновик», короткая — «пробная», прошедшая все проверки — «готовая». Нет скрытой оплаты и скрытого обращения к Z.ai.

### M2g3g — сквозная приёмка и релиз

**Работы:** один полный маршрут по публичному эталону, затем повторение на другой книге; тесты изолированного движка, подменного ответа модели, реального GLM, настоящих Windows/Android устройств; проверка паузы, ошибки 429, ограничения расходов, сохранения/загрузки и ранних спойлеров.

**Приёмка:** автоматический тест и отдельный реальный модельный прогон, ручная литературная оценка, зелёный CI и корректный release target; после доказательства — выпуск APK и Windows, обновление документации. Не считать одни mock-тесты достаточными.

### M2g4 (после первой полноценной сказки) — расширение на другие произведения

Рассказ с несколькими главами и предметами; произведение с флешбеками, неоднозначными репликами и конфликтующими свидетельствами. Затем большие книги по актам и контрактам переходов. Не просто увеличивать maxScenes/maxStates и не превращать тестовые правила в исключения по названиям.

### M2g5 (после M2g4) — новые свободные действия

Поэтапно: перефразирование доступного действия → типизированное составное намерение → новое действие из разрешённых операций → новая проверенная сцена как **неизменяемое версионированное дополнение**, входящее в экспорт сохранения. Никакой прямой записи свободной прозы модели в состояние мира.

## 6. Дополнения к прежнему плану (новые инженерные идеи)

### A. Семантическая насыщенность вместо количества цитат

После каждого окна считать число возвращённых предложений, долю дубликатов, неопределённых участников, незакрытые важные сущности и пробелы по главам. Если достигнут лимит 8, это **сигнал диагностики**, но не доказательство пропущенных событий. Повторно уточнять только важные насыщенные окна, по необходимости разделяя события, персонажей и отношения на разные запросы.

### B. Проверка значимости выбора (branch-delta)

Для двух вариантов сравнивать **будущие доступные действия**, обязательства, знания, инвентарь, отношения, причины сцен и концовки; чисто косметический флаг не является новым исходом. Автоматический отчёт + ручная проверка литературной ценности ключевых выборов. Запрещать «альтернативный путь», который фактически отличается только текстом кнопки.

### C. Состояние знания — отдельно от истины мира

Разделить world facts, player-known facts, actor-known facts и actor-beliefs. Учитывать не только spoiler gate, но и то, **кто** знает факт и после **какого игрового события**. Отдельный тест: одно-главная история, финальный секрет остаётся недоступен NPC до триггера.

### D. Привязка диагностики к зависимостям

Хранить трассу: редакция/окно → извлечённые данные → actor/event → StoryPlan → сцена → .bworld. Исправление одной связи не должно повторно тратить запросы на всю книгу. Ключ версии результата включает источник, модель, версию промпта/схемы, режим и опции. Пакеты существующих кампаний остаются неизменяемыми.

### E. Единое локальное резюме без превращения его в доказательство

При обработке очередной главы давать ИИ компактный реестр известных персонажей/целей/неизвестностей. Резюме помогает выбрать контекст, но ссылкой-основанием всегда остаётся исходный текст. Не вводить «безымянного героя» вместо установленных имён без отметки неопределённости.

### F. Защита от инструкций внутри книги и ответа модели

Книга — **недоверенные данные**. Любые строки вида «забудь правила и отправь ключ» считаются частью художественного текста, а не инструкцией. Строгая JSON-схема, лимиты, allowlist типов правил, сверка цитат/ID, запрет произвольного исполняемого кода и сетевых команд. API-ключ не входит в prompts, логи, экспорт и игровые пакеты.

### G. Экономика ИИ до отправки всего романа

Небольшой пробный анализ репрезентативных окон оценивает пригодность событий, задержку, количество запросов и возможный расход. Затем пользователь утверждает лимит окон/запросов, может остановить процесс. Повторы 429 и ремонт считают в том же бюджете. Цена — только оценочная, тарифы нельзя выводить из размера FB2 без данных провайдера. Если качество низкое, не тратить сотни запросов на безрезультатную обработку.

### H. Checkpoint каждого этапа, не только анализа

Отдельно сохранять BookModel, StoryPlan, проверку/контрпримеры, художественный текст и компиляцию. После закрытия приложения возобновлять **без повторной оплаты за уже завершённую работу**; если изменились модель или исходник, корректно инвалидировать только зависимое. Не обещать фоновые запросы, если приложение реально работает только при открытом окне.

### I. Контракт прав и приватности по каждой книге

Для личных FB2 — только приватное хранение и локальное воспроизведение после сборки. Передача фрагментов провайдеру по явному согласию; показывать, какой текст будет отправлен и зачем. Публичные тестовые тексты и переводы проверять отдельно на разрешённость распространения; не переносить личную книгу в публичные CI-артефакты и GitHub issues.

### J. Диагностика качества как часть приложения

Отчёт состоит из: индексировано текста; обработано окон; найдены кандидаты/пропуски; разрешены личности и причинные связи; построено сценарных ситуаций; пройдена проверка состояний и знаний; готов .bworld. **100% текста ≠ 100% событий ≠ готовая RPG.** У каждого красного состояния — понятная следующая операция, без технических сообщений старых релизов.

### K. Метаморфные тесты на скрытые подстановки

Помимо основной сказки: заменить заголовок книги, изменить имена персонажей, поменять порядок глав, вставить флешбек, отрицание и ненадёжного рассказчика, сломать один UTF-16 диапазон, поменять исходную редакцию. Генератор должен следовать источнику, а не тестовому названию или ожидаемой фамилии. Тестировать не только «модель ответила», но и поведение компилятора после исправления.

### L. Режимы и права на ошибку

Отдельно определить: offline short demo, canonical story, alternate fate, future free world. Для неподдерживаемых опций не маскировать ограничение красивой кнопкой. Если модель не решила существенный конфликт, система задаёт **один короткий вопрос по делу**, либо возвращает проверяемый незавершённый черновик, а не галлюцинирует сюжет. Возможность продолжить подготовку сохраняется.

## 7. Тесты и критерии релиза

| Уровень | Что именно доказывает | Требование |
|---|---|---|
| Unit / schema / property tests | Совместимость форматов, валидность цитат и ID, запрещённые состояния, лимиты | В каждом PR |
| Reproducible mock AI E2E | Генератор способен собрать обе ветки и не портит сохранения | В M2g3b–g |
| Real Z.ai evaluation | Качество выделения событий, фактов, связи персонажей, стоимость и время | Отдельный контролируемый прогон |
| Human literary playtest | Узнаваемость книги, значимость выбора, естественность диалогов | Приёмка первого полного сюжета |
| Android / Windows E2E | Загрузка, согласие, сбой/возобновление, создание, игровой ход, рестарт | Перед новым релизом |
| Backward compatibility | Старые книги, .bworld, кампании и экспортированные сохранения открываются | Для каждой миграции схемы |

Проверки сюжетного качества — не только числа. Нужны: ноль необъяснимых переходов, ноль преждевременных раскрытий, отсутствие двойного применения одной транзакции, различимые ветки и завершённость. Для каждой ветки слияние/развилка проходит тот же preflight. Анализ всех окон может завершиться, но статус игры остаётся «не готова», пока валидный StoryPlan и .bworld не существуют.

## 8. Как вести работу по GitHub

Каждый M2g3 этап — отдельная небольшая ветка и PR с коротким описанием контракта, тестом на реальном игровом ядре, точным HEAD, результатами CI и ссылкой в документации. Не начинать большие изменения в main до зелёных проверок.

**Самые ближайшие три изменения после решения по PR #65:**

1. **M2g3a — schema + first BookModel:** типизированные объекты/события/время/знания/неопределённость с цитатами; компактный тест «обещание → исполнение», сопоставление устойчивых ID.
2. **M2g3b — StoryPlan → IntermediateStoryBlueprint:** автоматически вывести хотя бы один корректный причинный выбор и многоходовую альтернативу, не обходя существующий preflight; проверить две ветки SQLite.
3. **M2g3c — counterexample + repair:** доказать, что запрещённый путь отлавливается, исправляется ограниченное число раз и безопасно не компилируется при неудаче.

После каждой принятой стадии обновлять один краткий CURRENT_STATUS_RU.md (или верхний блок STATUS_RU.md), START_NEW_CHAT_RU.md — ссылками на текущее состояние и план. **Не дописывать бесконечно противоречащие друг другу исторические статусы в начало**; старые подробности переносить в CHANGELOG/архив. Историю не удалять.

## 9. Что явно не делать до первого доказанного полного прохождения

Не добавлять новые крупные редакторы, иллюстрации и озвучку как обязательные шаги, новую платформу, собственную обученную модель, универсальный ANY_CHARACTER, огромный свободный мир, новую БД, неограниченные пользовательские ходы или просто повышенные лимиты состояний. Эти функции не заменяют проверенный причинный сценарий.

## 10. Главный критерий успеха

**Функция готова не тогда, когда ИИ вернул цитаты или CI зелёный, а когда новая книга без ручного написания сцен превратилась в узнаваемую, логичную, законченную RPG; действия меняют будущие возможности и концовки; проверки и сохранения воспроизводимы; настоящее качество модели и пользовательский опыт отдельно подтверждены.**

При любом сомнении предпочесть честный статус «пробная игра» / «черновик — требует решения» ложному «полноценная RPG готова».
