# M1.6.6 — переносимое сохранение пилотной RPG (.bwsave)

**Стадия:** первоначальный формат встроенного демо, не полноценная .bwsave для BookWorld.
**Сценарий:** `ai_story_m1_intro` («Тайна особняка»).
**Runtime:** `story_engine 0.1.0-alpha.1`. **Кодировка:** UTF-8 JSON, без ZIP.

## Задача
Перенести существующее прохождение демо между экземплярами приложения на совместимой версии Flutter/Dart для Windows/Android без облака и Python. После успешной проверки импорт создаёт **новую** кампанию; старая и выбранные книги не меняются. Проверка пользователем на обоих физических устройствах/Windows остаётся отдельным gate.

## Контракт v1

Внешний JSON:
```json
{
  "format": "ai_story_pilot_bwsave_v1",
  "schema_version": 1,
  "payload": {
    "book_id": "ai_story_m1_intro",
    "bookworld_hash": null,
    "source_kind": "embedded_pilot",
    "source_campaign_id": "campaign_demo",
    "last_scene": "Библиотека",
    "exported_at_utc": "2026-11-01T00:00:00.000Z",
    "role": null,
    "plot": null,
    "interaction": "CLASSIC",
    "rng_seed": null,
    "checkpoints": [],
    "runtime": {"id": "story_engine", "version": "0.1.0-alpha.1"},
    "engine_snapshot": "<original opaque engine JSON>",
    "world_state": {"courage": 1, "insight": 0, "items": []},
    "decision_journal": ["Тайна особняка: Войти и исследовать дом"],
    "rules_version": 1
  },
  "payload_sha256": "<64 lowercase hex digits>"
}
```

Контрольная сумма: SHA-256 от UTF-8 JSON поля `payload`, рекурсивно упорядоченного по ключам объектов (порядок элементов массивов сохраняется). `payload_sha256` обнаруживает случайную порчу, **не является электронной подписью** и не гарантирует подлинность.

`bookworld_hash`, `role`, `plot`, `rng_seed` — `null` **потому что эти функции ещё не реализованы**. `checkpoints` пока пуст. `decision_journal` — пользовательский текстовый журнал, **не** структурированный `event_log` полноценного `.bwsave`.

## Импорт и защита данных

1. Системный диалог выбирает файл `.bwsave` (не более 4 МиБ).
2. Проверяются UTF-8, JSON, версия 1, SHA-256, ID и тип встроенного сценария, только CLASSIC, точная версия runtime, версии правил 0/1, ограничения журнала и содержимого инвентаря.
3. Снимок движка пробно восстанавливается через `StoryEngine.restore` **без записи в хранилище**; последняя сцена сверяется с метаданными.
4. Игрок видит название истории, последнюю сцену и количество записей журнала, подтверждает импорт.
5. Генерируется новый локальный ID; существующие сохранения не переписываются. Отмена, ошибка файла или несовместимость ничего не импортируют.

Для экспорта используется системный `file_picker.saveFile(bytes: ...)`, поддерживаемый зависимостью 10.x на Android и Windows. Прямой доступ ко всей памяти не нужен. Полный каталог игры, книги, настройки чтения и старый ключ `ai_story_m1_snapshot_v1` не трогаются при импорте.

## Честные ограничения / следующий шаг
- Пока только **встроенный пилот**, не произвольная книга, не готовый BookWorld `.bworld`.
- Внутри переносится **непрозрачный снимок `story_engine`**, совместимость с другим runtime или другой версией демо **не гарантируется**. В M1.7 требуется `StoryRuntimeAdapter` + engine-neutral event log/checkpoints и миграции; старый формат нельзя переименовать в промышленный без преобразования.
- `SharedPreferences` пока используется как локальное хранилище; SQLite/Drift, полноценные транзакции и реальный Windows EXE остаются в ROADMAP.
- CI `flutter analyze/test` проверяет формат и UI; физический перенос APK ↔ Windows проверяется позже.
