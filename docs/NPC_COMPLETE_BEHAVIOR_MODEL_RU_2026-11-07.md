# NPC в «Живой книге»: полноценная модель поведения, а не только карточка

**Аудит:** 2026-11-07. Актуальная основа: PR #126/#127 в main `551e1e07`; draft PR #129 добавляет запросы о доказанном знании/его источнике и fail-closed проверку фактов. **План ниже не объявляет невыполненные механики реализованными.** Приоритет продукта — полноценная игра по загруженной книге, не разработка универсального симулятора жизни.

## 1. Что уже реально существует

- Постоянный `character_id` для NPC; приватные карточки с ролью, внешностью, биографией, характером, речью, целями, мотивами, локальным портретом. Книга/имя/реплика не определяют ID.
- Проверяемый source-only identity: группы упоминаний SAME/DIFFERENT и привязка имён говорящих к `character_id` только при уникальном подтверждённом соответствии.
- Приватные `NpcKnowledgeRulebook`/`NpcKnowledgeGate`, мост `NpcKnowledgeWorldBridge` (выдача `learn_fact` конкретному актёру после выбора и `knows_fact` перед выбором), source-lock и ручные согласия.
- `story_core`: `WorldState.knowledge`, детерминированные переходы и проверка журнала; после PR #129 — read-only provenance и проверка списка обязательных фактов для *заранее размеченной* реплики.
- Структурированные реплики и UI по одной с историей/локальными PNG. Это **не** доказательство, что конкретный говорящий знал произнесённый секрет.

## 2. P0 — фундаментальные недостающие свойства

| Свойство | Причина | Требование приёмки |
|---|---|---|
| **Событийная память** | NPC не обязан знать то, что видел только герой | Персонаж помнит только явно отмеченное, пережитое/услышанное событие. Обещание и предательство не исчезают при смене главы; разные сюжетные пути дают разные воспоминания |
| **Знание ≠ мнение ≠ слух** | Слышанный слух не является каноном | Для source-reviewed материала явно различать подтверждённый факт, убеждение, слух, ложь, неизвестность и секрет; переносить только доказанные состояния, без автоматического повышения «услышал» → «знает истину» |
| **Направленные отношения** | A доверяет B, но B может ненавидеть A | Явные source-locked `from_character_id`, `to_character_id`, тип/сила/причина/событие, стабильный результат после SAVE/REPLAY, запрет несуществующих/подменённых адресатов |
| **Присутствие и доступ к информации** | NPC не может услышать разговор, если его нет рядом | Условия присутствия на событии/сцене, свидетель/участник/получатель слуха; никаких невидимых свидетелей или спойлеров из будущих актов |
| **Доказательство каждой смысловой реплики** | Уже существующий `knows_fact` блокирует выборы, но не текст сцены | Для проверенных authored-turns: `speaker_character_id`, scene/event ID, список обязательных `fact_id`, статус source/private-fiction и проверяемый хэш. До отрисовки реплики проверить доступность говорящего и знание всех фактов. Если доказательств нет, безопасный отказ/переподготовка, а не угадывание текста |
| **Причинность реакций** | NPC не должен внезапно менять отношение без причины | Реакция ссылается на конкретное committed событие, выбор, наблюдателя и изменение отношения/обещания; все альтернативные маршруты согласованы |
| **Цели и конфликт мотивов** | Статическая биография не управляет поступками | Авторские цели могут направлять выбор *предлагаемых* действий, но реальные переходы требуют подтверждённых правил. Никаких самостоятельных скрытых изменений мира от генеративного текста |
| **CANON/ALTER_FATE разграничены** | Нельзя ошибочно менять мотивацию и знания книжного героя | CANON сохраняет подтверждённые исходные роли/последствия. ALTER_FATE честно обозначает частную альтернативу и её новые мотивы/факты; смешение запрещено |
| **Финальная сквозная проверка** | Unit-тест карточки не доказывает игровую историю | 2 реальные разные FB2 + GLM, включая диалоги, предметы, знания, отношения, смерть/отсутствие NPC, две осмысленные развилки, save/replay и офлайн-перезапуск Win/Android |

## 3. P1/P2 — после работоспособной полной книги

- Эмоциональная реакция, меняющаяся поза/портрет, интонация, манера речи, доступные жесты; настройки доступности и локализации.
- Расписания, местонахождение вне обязательных сцен, автономные планы, фракции, динамическое распространение слухов. Не вводить полноценную симуляцию времени прежде сценарной достоверности.
- Диалоги в свободной форме с LLM, только через ограниченные world-tools; фильтры приватности, расходы/согласия и серверная недоверенность текстов.
- AI-генерация портретов и TTS — только разрешённые пользователем материалы и отдельное согласие.

## 4. Порядок без десятков маленьких PR

**Пакет A — знания/доказательства (PR #129):** неизменяемые источники `learn_fact`, текущий `actorKnowsFact`, fail-closed prerequisites для утверждённой реплики, маршруты/хэши/replay, публичный Dart API. Нет неявного изменения формата.

**Пакет B — отношения + память + присутствие (следующий функциональный PR):** сперва явно описать сериализуемый typed contract; если существующих DSL/состояний недостаточно, согласованно изменить **формат и версионирование** с writer, Dart/Python importer, SQLite save/replay, миграционно совместимыми тестами. Субъект и адресат — реальные постоянные `character_id`, действия привязаны к принятому событию. Свободный текст `NpcDraftNote` сам по себе не создаёт relationship effect. Не кодировать отношения магическими строками через флаги или «уровень дружбы» без контракта.

**Пакет C — реальная интеграция диалогов:** привязать подтверждённые реплики к knowledge prerequisites, presence и source roles; проверка **до показа** текста, явная обработка отсутствия подтверждений, сохранение курсора только для допустимого текста, авторские/книжные реплики различать. Тесты на спойлеры и одинаковые имена.

**Пакет D — книга → готовая игра:** компилятор всей книги через проверенные модули StoryPlan/GLM/g1/g2/effects/NPC, режимы CANON/ALTER_FATE и герой, два real E2E. UI редакторов — необязателен; пользователь должен иметь короткий мастер.

## 5. Непересекаемые границы движка

- `packages/story_core`: только детерминированные правила, память, отношения, известные факты/реакции. Никаких Flutter, SQLite, сети, GLM и приватного исходного текста.
- `story_runtime_adapter`: публичные чтения и проверенные actions. `bookworld_format`: строгий `.bworld`, независимая Dart/Python проверка. `campaign_manager`: транзакционный SQLite и переносимое сохранение.
- Flutter/GLM/литературная экспертная проверка являются клиентами. Не создавать второй двигатель и не публиковать независимый репозиторий раньше готового продукта.
- Не менять внешнюю E6d. Не публиковать текст приватных FB2, переводов, ключи и изображения.

**Стоп-факторы выпуска 1.0:** нет проверенных правил NPC поведения на двух действительных книгах; «запрет выбора, но показ спойлера в реплике»; смешение имён и ID; разные последствия после replay; любой импорт `packages → apps`; неустойчивая source/format parity.
