## Что реализовано в экспериментальной ветке

1. tools/bookworld/private_rich_bookworld.py — строгий локальный v3
   компилятор/верификатор, четыре ZIP_STORED файла в прежнем порядке,
   настоящая SQLite. Полный текст книги НЕ включается.
2. tools/rpg_author/rich_package.py — одобренное авторское расширение
   для проверенного проекта E1, с SHA привязкой к книге и сценарию.
   Авторство OpenAI/ChatGPT пишется в оба JSON внутри v3 и дублируется
   отдельным SHA-связанным файлом. model_id_status = user_declared /
   not_attested, не криптографическое подтверждение.
3. packages/bookworld_format/lib/private_rich_bookworld.dart — отдельный
   Dart-импортёр. Проверяет источники, ZIP, SQLite, происхождение и
   ограниченную симуляцию с предметами, характеристиками, знаниями.
   Старые импортёры v1/v2 оставлены строгими.
4. packages/campaign_manager — допускает третий тип мира, не меняя
   формат существующей SQLite кампании и переносимых .bwsave.
5. apps/story_reader — три вкладки получают русские подписи героя,
   предметов и знаний. Журнал выводит реальные изменения состояния,
   восстановленные последовательным replay проверенных событий.
6. tests/rpg_author/fixtures_rich.py — синтетический исходный рассказ
   с двумя разными концовками и получением/расходованием верёвки.
   Нет утверждения, что это уже полноценная RPG по произведению Гримм.

## Как пользоваться внешним генератором

Python 3.12; все личные файлы и проекты — ВНЕ публичного репозитория.
Сначала принять весь анализ реальной книги и StoryPlan командами init,
next, accept-analysis, accept-story, validate старого E1. Потом создать
rich_enrichment_v1.json со следующими полями:
  format, source_fingerprint, story_sha256,
  hero, stats, items, facts, scene_names, choices.

В choices допускаются только типизированные проверенные операции:
  has_item / flag_is / stat_at_least / knows_fact;
  grant_item / consume_item / stat_delta / learn_fact / set_flag.
Именно эти правила обновляют настоящие характеристики, владение и знания.

Пример конфигурации: tests/rpg_author/fixtures_rich.py.

    python3 -m tools.rpg_author build-rich \
      --project /private/project \
      --enrichment /private/rich_enrichment_v1.json \
      --output /private/game_rich.bworld \
      --model-id gpt-6

    python3 -m tools.rpg_author verify-rich \
      --input /private/game_rich.bworld \
      --attribution /private/game_rich.attribution.json

Внутренний model_provenance v3 не подменяет внешний ИИ на none:
это отличие от старого совместимого v2.

## Ограничения, которые нельзя скрывать

- Старый APK/EXE не понимает v3. Нужна новая сборка из этой ветки.
- Не смешивать E4 с актуальным main без отдельного PR и нового полного CI:
  ветка наследует E3 и не содержит все изменения main от PR #86/#87.
- Права на пользовательский русский перевод Гримм не подтверждены:
  не загружать его текст/ключи/модельные ответы в публичный GitHub.
- Только PROTAGONIST/ALTER_FATE/CLASSIC, один player, ограниченные
  каталоги; не реализован AI_FREEFORM или автоматическое RPG по любой книге.
- Структурный state graph ограничен 2500 состояниями; недостижимые
  финалы, зацикленные пути, действия с несуществующими предметами и
  несовместимые ссылки на источник отвергаются до импорта.
- Смысловая точность цитат, художественное качество и права не
  подтверждаются детерминированным компилятором/хешами.
- Физические Windows/Android UI E2E, включая проверку всех трёх
  панелей после перезапуска и переноса сохранения, требуют отдельного теста.
