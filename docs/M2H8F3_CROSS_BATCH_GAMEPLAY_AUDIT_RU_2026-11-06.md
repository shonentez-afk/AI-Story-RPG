# M2h8f3 — единая проверка разных пакетов кандидатов перед записью в RPG

Дата 2026-11-06. Код в отдельной PR-ветке и на GitHub CI. Нельзя считать завершённым до проверки exact-head Windows/Android/Flutter.

## Почему

Для длинной книги введён источник-ограниченный пакетный сбор предложений (M2h8f1–f2). В одном пакете игрок может получить ключ, в следующем попытаться его применить. Проверять каждый пакет отдельно недостаточно: расход не может быть обоснован без состояний предыдущих актов, а одноимённые ID из разных пакетов могут описывать разные вещи.

## Реализация

- В действующем GameplayCandidateReachabilityAuditor появился **auditAcrossBatches(plan, manifest, drafts)**. Принимает все завершённые пакеты только той же точной версии StoryPlan, редакции книги, consent manifest и SHA каждого исходного запроса.
- Каждое предложение повторно проверяется по точной сцене, choice ID, source-event ID, дословной цитате и разрешённой операции. Пустой список в одном/нескольких пакетах допустим; число пакетов должно быть полным. Подмена digest согласия блокирует проверку.
- Сквозная таблица ID требует одни и те же kind и label для каждого предмета/знания независимо от пакета. Повтор одной и той же операции запрещён даже между разными пакетами.
- Все решения передаются **одному ограниченному автомату состояний**: флаги, сцена, инвентарь, знания героя, путь выборов. По всем достижимым маршрутам диагностируются CONSUME_UNOWNED, GRANT_WHILE_OWNED, AMBIGUOUS_SAME_CHOICE, UNREACHABLE_EFFECT и недоступные концовки. Дается путь выбора, приводящий к конфликту. Максимум 2500 состояний и 32 разных проблемы.
- Исправлено сопоставление операций: ключ теперь строго scene_id/choice_id, а не один choice_id, который случайно может повторяться в другой сцене.
- Новые тесты используют четыре части синтетической книги, два и более GLM-пакета, сквозной ID факта, испорченное согласие и сквозной конфликт расхода без получения.

## Принципиально не подтверждено

Цитата доказывает точность **слов** оригинала, но не факт владения вещью, мотив NPC, время события или литературный CANON. Ни этот аудит, ни пустой список ошибок НЕ разрешают автоматически менять настоящий игровой мир, инвентарь/журнал или SQLite. Для выполнения требуются человеческое подтверждение игровой интерпретации, литературная независимая проверка и отдельный компилятор с новой личностью архива.
