# Изображения FB2 и EPUB — архитектура и требования M1.2/M1.3

Дата: 2026-11-01. Решение: поддерживать **обложки и изображения внутри глав** как независимые медиа-объекты; сохранять расположение иллюстраций в порядке исходной книги, а не извлекать только плоский текст.

## Подтверждённые сведения форматов
- FB2: элементы `<image xlink:href="#id"/>` ссылаются на `<binary id="id" content-type="image/...">base64...</binary>`; `<description><title-info><coverpage>` содержит ссылку на обложку. Изображения могут находиться внутри `body/section`, не только на обложке. Референс: https://github.com/Gremlin2/Fb2Fix/blob/master/FictionBook.xsd .
- EPUB: ZIP/OCF-контейнер; OPF manifest перечисляет ресурсы; XHTML использует `img`, SVG и относительные ссылки, иногда иллюстрации занимают отдельную spine-страницу. EPUB 3 определяет необязательное свойство `cover-image`, потому обложку следует определять также через metadata/guide/cover page. Референс: https://www.w3.org/TR/epub-34/ .

## Доменная модель (не путать с игровым миром)
```text
ImportedBook
  id, title, author, coverResourceId?, sourceFormat
  resources: Map<ResourceId, BookImage>
  chapters: List<BookChapter>
BookChapter
  id, title?, blocks: List<BookBlock>
BookBlock
  paragraph | heading | quotation | separator | imageRef | table (future)
BookImage
  id, mediaType, localPath or bytes, width?, height?, alt?, caption?
```
Обложка хранится как ресурс книги с отдельной ролью `cover`; она может совпадать с одним из внутренних изображений, но в тексте нельзя удалять вхождения иллюстраций лишь потому, что ресурс используется как обложка. Блоки сохраняют исходную последовательность текста и изображений, включая вложенные секции и подписи.

## UX
1. Библиотека: миниатюра обложки, название, автор. Если обложки нет — аккуратный плейсхолдер. При множестве книг применять кэшированные thumbnails, а не декодировать полноразмерный JPEG каждый раз.
2. Карточка: крупная обложка; кнопки «Читать» и в будущем «Играть». Если обложка слишком большая — fit.contain, без обрезки важных элементов.
3. Чтение: иллюстрации строго между соответствующими абзацами. Масштаб по ширине текстовой колонки с сохранением пропорций; для карт, чертежей и схем — тап → полноэкранный просмотр + zoom/pan; необязательная подпись и alt-text.
4. На устройствах с малой памятью: decode по требованию, миниатюры на диске, lazy-loading. Настройки темы, шрифта и полей не должны менять положение иллюстрации относительно её абзацев.
5. Игровой режим: по умолчанию показывать оригинальную иллюстрацию там, где она относится к сцене, **только если её появление не раскрывает будущий сюжет**; для альтернативного сюжета пометить изображение как `canonResource` с source anchor, не делать его доказательством текущего игрового состояния. Создание ИИ-иллюстраций в будущем — отдельная опциональная функция с указанием происхождения.

## Инженерные требования
- Строго локальное хранение и отображение; никакого скачивания внешних ресурсов из EPUB без согласия.
- Безопасное разрешение EPUB-relative href: нормализация и запрет `../` вне OCF корня, абсолютных, сетевых и data-URI по умолчанию. Проверка ZIP bomb: предел распаковки/число entries/размер изображения.
- Проверять magic bytes и допустимый MIME, ограничения декодирования и корректную деградацию для сломанных картинок. Путь в manifest не считать безопасным автоматически.
- EPUB с DRM/защитой не обходить; сообщать о неподдерживаемой защите.
- SVG отрисовывать только через безопасный рендерер, без выполнения скриптов/внешних ссылок.
- Сохранение книги должно быть версионировано: нынешний JSON schema 1 содержит `chapters: List<String>` и `coverBase64`; schema 2 должна включать blocks/resources. Миграция schema 1 → schema 2 обязательна; существующие локальные книги не удалять.
- Файл оригинала и лицензированный контент остаются локальными. Сохранения game state отдельные.

## Этапы
- **M1.2.1** — FB2 XML: собрать все `binary`, ссылки `image` в `body` и дочерних `section` как блоки; отображать картинки в корректном порядке. Обложку и внутренние картинки хранить отдельно.
- **M1.2.2** — просмотр с увеличением (zoom/pan), lazy loading, captions, обработка ошибок и тестовые FB2 с несколькими рисунками, картой, отсутствующей/повреждённой обложкой.
- **M1.3** — EPUB importer: OPF, spine, XHTML, nav/toc, images; SVG и fixed-layout либо позже, либо через проверенный рендерер.
- **M1.4** — единый BookBlock/StoryScene renderer, источники изображений и spoiler policy для развилок RPG.

## Тесты приёмки
1. FB2 с обложкой + тремя внутренними рисунками: обложка в библиотеке, все три на правильных позициях.
2. Ссылка на несуществующее изображение не ломает книгу; fallback только в месте картинки.
3. Разные JPEG/PNG размеры/ориентации, карта крупного разрешения — без искажения и с zoom.
4. FB2 с вложенными секциями, заголовками и иллюстрациями — правильный порядок.
5. EPUB с cover-image и отдельной XHTML обложкой — отсутствие случайного дублирования на первой странице; внутренние иллюстрации не потеряны.
6. Перезапуск приложения и обновление со schema 1 не теряют книги и snapshot игры.
7. Все обычные и игровые тесты CircleCI зелёные.
