# Очистка Actions, артефактов и тестовых релизов

Пользователь 8 ноября 2026 явно запросил очистку старых Actions/артефактов и ненужных релизов с тегами. План реализован в прежнем storage-prune-once.yml; автоматического расписания нет. Main не меняется.

Сохраняются три последних полных test-build релиза с APK, Windows ZIP и SHA256; обычные/нестандартные релизы и теги не удаляются. Удаляется только тег удалённого старого автоматического тестового релиза, чей коммит достижим из main или рабочей ветки. Исходники, ветки и коммиты не удаляются.

Сохраняются свежие проверки и успешные базовые проверки всех открытых PR/default branch, выполняющиеся запуски, CI #979/#975, их M0 и предыдущая проверенная внешняя baseline. Артефакты: не менее двух последних успешных копий каждого известного типа для активных веток; неизвестные отчёты сохраняются вместе с родительскими runs. Старые run IDs перед удалением повторно проверяются на статус и attempt. Подробный план/результат сохраняется в маленьком maintenance audit артефакте, краткий итог — в Summary. Ошибка API останавливает очистку с честным частичным отчётом.

Локальные шесть тестов политики прошли до отправки; тот же набор запускается до реальных удалений в workflow. До завершения workflow не утверждать, что конкретное количество удалено.

При сверке текущей разработки: CI #979 на 71824a0c завершил Python/Dart/M1.7/Flutter и Windows/Android успешно. Publish release в этом запуске SKIPPED; артефакты не равны опубликованному релизу. Последний опубликованный релиз на момент проверки — test-build-921 из main 81fb75b7, а не #975.
