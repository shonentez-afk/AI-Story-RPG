## Что защищено

Сохраняются три последних полных автоматических test-build релиза, нестандартные релизы и теги; последние успешные и текущие проверки default branch и открытых PR; все активные runs; явно принятые CI #979/#975 и M0; последняя успешная внешняя baseline; необычные отчётные артефакты и их родительские runs; минимум две свежие успешные копии каждого известного типа артефакта активных веток. Новый report audit тоже сохраняется.

Удаляемый run повторно проверяется по status и run_attempt. Устаревший release проверяется по tag/updated_at/immutable; связанный тег удаляется только при неизменной ссылке и достижимом коммите. Удаление ограничено фиксированным репозиторием и allowlist endpoints actions/runs, actions/artifacts, releases и только refs/tags/test-build-<число>. Ветки, исходники, коммиты, PR, секреты и настройки не удаляются.

## Управление и отчётность

Сначала выгружается полный снимок пагинации и формируется план; при неожиданном объёме или неполной пагинации действия не выполняются. Ошибка API прекращает дальнейшие удаления с частичным отчётом. JSON обновляется после успешных операций. Retention audit-артефакта 7 дней. Основная очистка и orphan-tag проход сериализованы одной concurrency group и не отменяют друг друга.

Локально прошли 6 базовых тестов политики и затем 9 с защитой orphan tags. Workflow требует запуска соответствующих тестов перед реальными удалениями. execute_request.py исполняет только точный записанный scope; текущий cleanup-request.json содержит verified_historical_test_tags и НЕ повторяет массовую очистку runs. Не повторять workflow вслепую и не менять scope без новой проверки фактической необходимости.

Удалённые байты отражают сумму размеров выбранных файлов, а не мгновенное подтверждение перерасчёта биллинговой квоты GitHub. После завершения получить итоговые Summary/JSON обоих запусков и заменить этот временный раздел окончательными числами. Ошибки или сохранённые исключения не скрывать.
