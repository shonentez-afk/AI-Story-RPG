## Новая цепочка интерфейса

Книга → редактор сцен и NPC → «Проверить и собрать RPG с NPC» → ручная проверка существующих правил, цитат, ролей → **строго собрать базовый rich-v3 .bworld и проверить его** → при наличии допустимых сцен открыть «Ответы героя в разговорах» → выбрать одну/несколько сцен → конкретный постоянный NPC → источник → *все* реплики героя для каждого choice_id → просмотреть реальные исходы и подтвердить всё → пересобрать и повторно проверить rich-v3 ZIP → установить в обычную библиотеку и открыть кампании. Кнопка «Собрать без новых ответов» пропускает именно авторский этап. Системная кнопка «Назад» отменяет текущую сборку, не устанавливая неподтверждённый файл.

Новая UI-панель отношений доступна только в уже сохранённой игре, когда персонаж **встречен** и его слова не закрыты knowledge gate либо есть committed memory. Она не перечисляет всех NPC из будущих сцен. При отсутствии life-transition не выдаёт абстрактный статус за истинный. В старой встроенной пилотной игре нижняя панель остаётся трёхкнопочной.

## Важные границы

- Эта доработка не добавляет сюжетных эффектов от текста, не вызывает модель при прохождении, не меняет Schema rich-v3 и не создаёт второй runtime. Адаптации без нового scene_dialogue_responses открываются по-старому.
- Выбор разрешён только через уже подписанный StoryWorld.apply. При несовпадении blueprint/social digest повторная компиляция отказана.
- Source quote доказывает лишь происхождение контекста, не что говорящий произнёс все отредактированные слова. Автоматический CANON и вся книга всё ещё не завершены.
- Никакие изменения E6d или main не допускаются. Старый External RPG author tests contract_drift не служит основанием перебирать E6d сейчас.
- Этот аудит основан на источниках экранов, маршрутах и Flutter widget-тестах. **Визуальная проверка на физическом Android и Windows, скриншоты, проверка доступности экранным диктором ещё не выполнены**; не называть её законченной.

## Приёмочные проверки

1. Валидный source-reviewed мир с 3 вариантами: страницы показывают реальные source и последствия, не разрешают принять без заполнения всех ответов и согласия; результирующий ReviewedNpcResponsePlan проходит двойную проверку и формируется уже существующим богатым компилятором.
2. Устаревшая или не-source диалоговая сцена не предлагается, финальная сцена без выборов не подменяется.
3. Нажатие «Пропустить» не создаёт proposal и не устанавливает ложную авторизацию, системное «Назад» не устанавливает игру.
4. Replayed NPC память/отношение/жизнь видны в панели NPC, а неизвестный ещё персонаж там отсутствует. Нижняя панель старой пилотной игры остаётся прежней.
5. Отдельные widget-тесты 320 px и большого текста; exact-head Python/Dart/M1.7/Flutter, Windows portable и Android debug APK.
