и реальные последствия выбора (grant_item, consume_item, stat_delta,
learn_fact, has_item, knows_fact).

**CI на точном SHA `8429d2b7f26fccf90742bb18d62823c8a5055a3e`:**
[External RPG author tests #41991002173](https://github.com/shonentez-afk/AI-Story-RPG/actions/runs/41991002173)
— Python/Dart jobs `success`.
Независимый Dart-probe использует **неизменённый реальный**
`BookworldImporter` v1, `StoryWorld.apply` и `StoryWorld.replay`.
Три маршрута подтвердили изменения inventory, stats, knownFacts и
сохранение журнала ходов и state SHA при replay:

1. Фонарь → осветить брод → помочь ребёнку → отдать медальон.
   В конце фонарь остаётся, медальон израсходован; insight растёт 1→4,
   courage растёт 1→2; журнал содержит четыре хода.
2. Верёвка → переправиться → не помогать ребёнку → рассказать о броде.
   Верёвка исчезает при использовании; courage 1→3;
   журнал содержит четыре других хода.
3. Без снаряжения → вернуться. Нет предметов, журнал фиксирует два хода.

CI создаёт артефакт `AI-Story-RPG-Hero-Items-Journal-Test-v1` с .bworld,
человекочитаемым сценарием, SHA и инструкцией.

## Важные ограничения

- Это *собственный тестовый мир* BookWorld **v1 original_demo**, не
  приватная RPG по книге и не расширение v2.
- Старый `.bworld v2` внешнего генератора по-прежнему запрещает предметы
  и характеристики. Нельзя считать задачу «игра по книге с тремя вкладками»
  выполненной только из-за этого демо.
- Вкладки Flutter не проверены вручную на устройстве: необходимо импортировать
  пакет на Windows/Android и пройти маршруты.
- В v1 предметы в интерфейсе отображаются машинными ID на английском,
  без литературных названий и описаний. Герой имеет реальные числовые stats,
  но не отдельный персональный профиль с именем/биографией.
- Журнал сейчас показывает реальные choiceLabel, но без описания предметов,
  изменений статуса и причинно-следственных пояснений.
- Не изменены main, импортёр v1/v2, SQLite, сохранения, Flutter UX.
- Это не доказательство полноты литературного сценария.
