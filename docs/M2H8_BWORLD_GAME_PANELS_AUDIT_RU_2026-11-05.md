# M2h8 — проверка «Герой», «Предметы», «Журнал» для .bworld

**Проверено по исходному коду на 5 ноября 2026.** Вход: реальный `WorldLibraryGateway`, `WorldPlayPage`, `campaign_manager` SQLite; частный v2 и оригинальный демо v1 — **разные форматы с разной функциональностью**.

## Фактический контракт основного приложения

- `WorldGameView.stats`, `inventory`, `knownFacts` берутся из текущего `StoryWorld.state`. Журнал `WorldEventView` строится из **подтверждённых** `coordinator.events` с сохранёнными идентификаторами выбора и реальными подписями из установленного Blueprint. Перечитывается и проверяется через SQLite/replay при каждом открытии; не из текста модели.
- `WorldPlayPage` содержит настоящие вкладки **Герой** (характеристики, время, число фактов), **Предметы** (актуальные ID, без выдуманных объектов), **Журнал** (последовательность записанных решений). Кнопки доступны в нижней панели. Человекочитаемые имена/описания героя, предметов, заметки о последствиях и сюжетные задания в текущем v1/v2 не предусмотрены.
- Старый `original_demo .bworld v1` способен исполнять `grant_item`, `consume_item`, `stat_delta`, `learn_fact` и показывает реальные изменения в тех же вкладках. Это **не** эквивалент «RPG по загруженной книге».
- **Частный `.bworld v2` текущих внешнего/встроенного компиляторов** требует `items=[]`, `facts=[]`, `stats={}`, `inventory=[]`, `knowledge={player: []}`; принимает только `flag_is/set_flag`. В нём могут работать сцены, выборы, `flags` и *исторический журнал решений*, но **невозможны** настоящие предметы, изменение характеристик или знания из `learn_fact`. Вкладки будут пустыми там, где формат не поддерживает данных.
- Простая запись новых полей в v2 нарушает жёсткие валидаторы ZIP/blueprint/SQLite; такой архив должен быть отклонён. Не «дорисовывать» вещи по литературному тексту и не сохранять вымышленные флаги как реальный инвентарь.

## Независимый формат v3 — пока отдельно

В `feature/external-rpg-author-e4-rich-private-v3-20261105` разработан **экспериментальный** rich v3 с подписями/предметами/знаниями, но он не находится в `main`. Позднее создана `feature/external-rpg-author-e4-isolated-20261105`: только **внешний** Python-генератор; никаких изменений приложения. Существующие APK/EXE `v1/v2` не могут импортировать `v3`. Сохраняем договорённость о разделении: не сливать v3 в основное приложение без отдельного согласованного этапа и полноценной регрессии. [Issue #88](https://github.com/shonentez-afk/AI-Story-RPG/issues/88) отслеживает расширение.
