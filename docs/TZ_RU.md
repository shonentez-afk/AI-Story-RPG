# AI Story RPG «Живая книга» — единое техническое задание

> **Документ:** TZ-RU-001 · **Версия:** 0.1 (первичная проектная база) · **Дата:** 2026-11-01 · **Статус:** УТВЕРЖДЕНА КОНЦЕПЦИЯ, РЕАЛИЗАЦИЯ НЕ НАЧАТА.  
> **Репозиторий:** https://github.com/shonentez-afk/AI-Story-RPG  
> **Основной язык:** русский. **Целевые платформы:** Android + Windows с первого рабочего прототипа; iOS позднее.  
> **Нормативность:** это единый источник требований. Вспомогательные документы уточняют план, но не могут незаметно изменить требования здесь.  
> **Порядок приоритетов:** P0 — обязательно для жизнеспособного ядра; P1 — обязательно для полного режима «Живая книга»; P2 — дальнейшее развитие.

## 1. Цель и видение

AI Story RPG — кроссплатформенное приложение-читалка и движок интерактивных книг: пользователь открывает произведение, читает его обычным способом или создаёт/загружает игровой пакет, выбирает героя, степень свободы сюжета и способ взаимодействия, после чего проживает события книги с проверяемыми последствиями своих решений.

**Игровое обещание:** «Загрузи книгу. Стань частью её мира. Проживи историю по книге или измени её».

**Основные принципы:** mobile-first, offline-first, единый воспроизводимый игровой движок, однократный анализ книги с повторным использованием результата, сохранность фактов оригинала, независимость от конкретной LLM, отсутствие обязательного аккаунта/сервера, уважение прав автора и приватности игрока.

**Ключевое ограничение:** offline-first означает, что подготовленный пакет игры работает без интернета и без ИИ. Это НЕ означает, что совершенно новая большая книга автоматически превращается в качественную RPG без каких-либо ИИ-вычислений. Полная подготовка книги требует облачной или локальной модели, либо ручного авторского сценария.

## 2. Пользовательские сценарии

- **UC-01 — Читать:** открыть EPUB/FB2/TXT (позже PDF/DOCX везде), листать текст, сохранять место, шрифт/тема/закладки; без ИИ и без обязательного преобразования.
- **UC-02 — Подготовить книгу:** импортировать файл, увидеть этапы анализа и покрытие глав, при необходимости дать согласие на передачу текста провайдеру; получить игровой пакет BookWorld.
- **UC-03 — Начать кампанию:** выбрать персонажа, модель сюжетных ограничений и тип управления; получить только совместимые с подготовленным пакетом варианты.
- **UC-04 — Классическая RPG:** проходить сцены, выбирать готовые действия, получать вычисленные последствия, развилки и концовки полностью офлайн.
- **UC-05 — ИИ RPG:** вводить свободные команды на естественном языке, получать живой текст и новые допустимые действия; изменения мира решает игровой движок, не текст LLM.
- **UC-06 — Гибрид:** выбирать готовое действие либо вводить своё, когда доступен ИИ.
- **UC-07 — Несколько прохождений:** создать независимые кампании по одной книге; от конкретной точки создать альтернативную ветку.
- **UC-08 — Перенос:** экспортировать/импортировать BookWorld и сохранение между Android и Windows без обязательного облака.
- **UC-09 — Переключение из чтения:** начать игровую сцену, привязанную к прочитанной главе, если такая сцена подготовлена. Оригинальный текст неизменен.
- **UC-10 — Смена режима:** переключать классический/гибридный/ИИ режим без повреждения сохранения, соблюдая ограничения совместимости уже изменённого состояния.

## 3. Три независимые оси выбора

### 3.1. Игровой персонаж (ROLE)

- **ORIGINAL:** собственный персонаж с выбранным именем/описанием и возможностями согласно миру.
- **PROTAGONIST:** главный герой книги, игрок управляет дальнейшими решениями.
- **EXISTING:** иной существующий персонаж, доступный по структуре данной книги.

Если в произведении нет подходящей роли или она не поддержана подготовленными сценами, приложение сообщает это ДО начала кампании. Произвольный второстепенный персонаж не обязан быть играбельным без дополнительной подготовки.

### 3.2. Режим сюжета (PLOT)

- **CANON («По книге»):** сохраняются значимые события и концовки оригинала. Вариативны локальные действия, диалоги и побочные сцены, если они совместимы с каноном. Для несовместимого вмешательства предложить ответ, объясняющий ограничение, или создание отдельной ветки, но **никогда не навязывать игроку действие**.
- **FATE («Изменить судьбу»):** оригинальная книга — базовая хронология; правдоподобные действия могут изменить важные события. Изменение причины инвалидирует зависящие от неё будущие события; независимые сохраняются.
- **FREE («Свободная история»):** мир, законы, способности и исходные характеристики основаны на книге; дальнейший сюжет не привязан к обязательным главам. В классическом офлайне свобода ограничена авторским контентом и правилами, при ИИ может расширяться.

«Неизменяемый факт оригинала» — это не обязательно «неизменяемое событие кампании»: первоисточник никогда не переписывается, а расходящееся прохождение хранится отдельно.

### 3.3. Управление (INTERACTION)

- **CLASSIC:** только подготовленные варианты действий/диалогов, детерминированные проверки, полностью без LLM при игре.
- **AI_FREEFORM:** свободный текст, парсер намерения → предложение структурированного действия → движок правил → фиксация изменений → художественный ответ LLM.
- **HYBRID:** классические варианты всегда при наличии готовой сцены, дополнительно свободный ввод с ИИ при соединении.

Для книги необходимо показывать матрицу реально поддерживаемых комбинаций и причину недоступности каждой. Максимальное теоретическое число сочетаний — 3×3×3=27, но реализуемые возможности определяются содержимым пакета и движком.

### 3.4. Спойлеры и доступ к знаниям

Переключатель **«Без спойлеров» включён по умолчанию**. Планировщик может знать финал; персонаж и рассказчик видят только разрешённые сведения. Учитываются: оригинальная хронология, факт раскрытия игроку, события кампании, знания и ошибочные убеждения конкретного NPC. При повторном прочтении/специальном пользовательском режиме предупреждения допустимы, но раскрытие не происходит случайно.

## 4. Платформы и UX

**FR-PLAT-01 (P0).** Единый Dart-пакет игрового ядра, независимый от Flutter UI, работает и тестируется на Android и Windows; iOS добавляется позднее без переписывания ядра.

**FR-PLAT-02 (P0).** Flutter UI адаптивен: мобильный вертикальный экран с приоритетом текста, крупные области касания, нижняя навигация; широкий экран с двухколоночным/адаптивным отображением.

**FR-PLAT-03 (P0).** Системный импорт/экспорт файлов Android через системный диалог и механизмы доступа к выбранным документам; не запрашивать ненужный полный доступ к памяти.

**FR-PLAT-04 (P0).** Портативность файлов: один BookWorld и совместимое сохранение дают те же игровые переходы на Windows и Android при одинаковой версии правил и seed. Криптографические идентификаторы и миграции версий обязательны.

**FR-UI-01 (P0).** Читалка: темы светлая/тёмная/сепия, шрифт, размер, интервал, закладки, история чтения, автосохранение места, спокойный полноэкранный режим.

**FR-UI-02 (P0).** Игровой экран: художественный текст, текущая локация, выборы, журнал, персонажи, инвентарь и индикатор статуса подключения без перегрузки экрана.

**FR-UI-03 (P0).** Мастер новой кампании включает ROLE → PLOT → INTERACTION → настройки спойлеров → краткий обзор → «Начать». Выбранные параметры относятся только к новой кампании, не к глобальным настройкам приложения.

**FR-UI-04 (P1).** Чтение и игра связаны по source anchor (глава/сцена). Кнопка «Прожить этот момент» доступна только когда существует подходящая игровая точка.

**FR-UI-05 (P1).** Озвучивание текста через доступную системную TTS-службу; офлайн-доступность зависит от голосов/движка устройства. Озвучка и иллюстрации не блокируют игру.

**FR-UI-06 (P1).** Доступность: масштабирование шрифтов, экранные дикторы, контраст, управление с клавиатуры Windows, понятные метки, экран не требует постоянного интернета.

## 5. Импорт и обработка исходных книг

### 5.1. Форматы и этапность

| Формат | Чтение/импорт Android | Чтение/импорт Windows | Полная компиляция |
|---|---|---|---|
| TXT UTF-8/распознаваемые кодировки | P0 | P0 | P1 |
| FB2 (XML) | P0 | P0 | P1 |
| EPUB (без DRM) | P0 | P0 | P1 |
| DOCX | P1 | P1 | P1 |
| PDF с извлекаемым текстом | P1 | P1 | P1 |
| PDF-скан | P2, OCR по явному выбору | P2, OCR по явному выбору | P2 после успешного OCR |

Статус P0/P1 означает целевую фазу разработки, а не реализованную поддержку. Скрытая отправка файла на сервер запрещена.

### 5.2. Book Compiler — pipeline

**FR-IMP-01 (P1).** Проверить файл: расширение и сигнатура, размер, читабельность, кодировка, ограничение распаковки, обнаружение DRM/ошибок. Не обходить защиту DRM.

**FR-IMP-02 (P1).** Сохранить исходные границы глав, параграфов, порядок чтения, логические идентификаторы и ссылки на диапазоны текста; текст не должен теряться при обработке.

**FR-IMP-03 (P1).** Разбить текст по смысловым границам на фрагменты с перекрытием при необходимости (ориентир 1500–3000 токенов, настраиваемый, не жёсткое правило).

**FR-IMP-04 (P1).** Вести задания по каждой главе/фрагменту: PENDING, RUNNING, DONE, FAILED, REVIEW. Сохранять результат каждого задания и возобновлять после закрытия приложения. Охват всей выбранной книги проверяется счётчиками, а не оценкой LLM.

**FR-IMP-05 (P1).** Извлекать факты, персонажей и варианты имён, локации, предметы, отношения, сроки, мотивы, тайны, сюжетные события и возможные игровые действия в валидируемый JSON. Запись без источника помечать как вывод/дизайнерское дополнение.

**FR-IMP-06 (P1).** Строить канон в несколько проходов: локальный анализ → объединение сущностей → хронология → проверка будущими главами → контроль фактов по оригиналу → общий реестр. Важно выявлять ретроспективные раскрытия.

**FR-IMP-07 (P1).** Для важных утверждений фиксировать provenance: идентификатор книги, глава, фрагмент/диапазон и статус: CONFIRMED, INFERRED, CONFLICTED, INVENTED. Дополнительно границы адаптации: immutable/adaptable/open/conflicted.

**FR-IMP-08 (P1).** Создавать игровой граф сцен: исходное состояние, доступные игроку действия, условия, эффекты, переходы, предусмотренные неудачи, таймеры и развилки. Факты и догадки не должны превращаться в игровые правила без проверки.

**FR-IMP-09 (P1).** Для режима CLASSIC заранее создавать тексты сцен и исходов, включая негативные результаты. Проверить достижимость, отсутствие необъяснённых тупиков, целостность причинности, недоступность секретов и хотя бы одну завершённую дорожку.

**FR-IMP-10 (P1).** Компиляция завершается публикацией неизменяемого игрового пакета с явным отчётом: охвачено N/N глав, статус ошибок, количество сцен/веток/ролей, поддерживаемые режимы и предупреждения. Пакет не помечать «вся книга готова», если критические части пропущены.

**FR-IMP-11 (P1).** Повторная обработка той же версии произведения с теми же настройками использует кеш и хеши; частичная переподготовка не меняет уже сохранённые кампании без миграции.

**FR-IMP-12 (P1).** На Android простой импорт и оркестрация облачного анализа должны работать без Python/постоянного сервера. Python + Docling допускается как **опциональный** мощный компилятор для Windows/серверного окружения. Форматы BookWorld/JSON-схемы одинаковы. На первых этапах расширенная обработка PDF/сканов может требовать ПК.

### 5.3. Редактирование и неоднозначности

Неоднозначные связи персонажей, спорные факты и неразрешимые условия выносятся в отчет/редактор. Человек может исправить извлечённые сведения в адаптации; исходный текст, ссылки на него и журнал правок сохраняются. Автоматическое замещение противоречивых фактов вымыслом запрещено.

## 6. Общая игровая модель

**FR-CORE-01 (P0).** Игровой движок не зависит от сети и LLM. Вход: GameState + typed PlayerAction + SceneDefinition + Seed; выход: DecisionResult + атомарный набор изменений + новые доступные действия.

**FR-CORE-02 (P0).** Состояние разделено на:
1. SOURCE_CANON — факты и оригинальная хронология книги, read-only;
2. ADAPTATION — подготовленные сцены и правила, версионируются вместе с BookWorld;
3. CAMPAIGN — фактические изменения текущего прохождения, журнал событий и контрольные снимки;
4. KNOWLEDGE — что знает/во что верит игрок и каждый NPC, с источниками и моментами раскрытия.

**FR-CORE-03 (P0).** Ключевые сущности: Book, SourceChunk, CanonFact, Entity, Alias, Location, Item, CharacterProfile, Relationship, Belief, Event, Dependency, Scene, Choice, Condition, Effect, Campaign, ActionLog, Checkpoint.

**FR-CORE-04 (P0).** Проверка условий — безопасный ограниченный DSL/набор типизированных предикатов: имеет предмет, известен факт, уровень доверия, персонаж жив, доступна локация, наступило время, сработал флаг, выполнено событие. Никакого исполняемого Python/JS-кода из игрового пакета.

**FR-CORE-05 (P0).** Действия вызывают атомарные изменения; ресурс не расходуется, предмет не создаётся и тайна не раскрывается без допустимого события. Идемпотентность по action_id, транзакция SQLite.

**FR-CORE-06 (P0).** В классическом режиме используются подготовленные тексты и выборы; нельзя скрыто обращаться к LLM. Неудачные проверки должны иметь осмысленный результат, а не создавать несвязный сюжет.

**FR-CORE-07 (P1).** В AI/HYBRID режиме парсер переводит фразу игрока в конечный набор typed actions; движок проверяет физические, социальные и сюжетные предпосылки; LLM получает только согласованные эффекты и формирует художественный текст. Слова рассказчика не меняют state.

**FR-CORE-08 (P1).** NPC имеют отдельные планы, ресурсы, поведение во времени, знания, убеждения и ограничения. NPC не должны знать секреты, с которыми не сталкивались. Параллельные/отложенные реакции привязаны к событиям и времени.

**FR-CORE-09 (P1).** Причинность: у оригинальных событий есть предусловия и зависимости; изменение причины блокирует зависимые канонические события. Пересчёт будущих событий должен сохранять независимые линии, проверять достижимость и никогда не «восстанавливать» погибшего или разрушенный объект ради удобства сюжета.

**FR-CORE-10 (P0).** Ветвление и возврат: новая ветка создаётся копированием checkpoint + новых событий, исходная ветка остаётся неизменной. Пересохранение не должно перезаписывать альтернативный сюжет.

**FR-CORE-11 (P1).** Переключение способа взаимодействия возможно только при совместимости текущего состояния с подготовленными классическими сценами. Несовместимый переход не выполняется молча; предлагается найти совместимый checkpoint или сохранить отдельную ветку.

**FR-CORE-12 (P1).** Свободный сюжет полностью офлайн не обещает бесконечную генерацию: только заранее подготовленные сцены, реакции и комбинации правил; явное отображение границ.

## 7. Форматы файлов и данные

### 7.1. BookWorld: .bworld (P0 схема, P1 полный)

Контейнер ZIP с минимумом:
- **manifest.json:** format_version, bookworld_id, source_fingerprint, title, author, languages, engine_min_version, content_capabilities, build_status, hashes, build_tool, model_provenance, rights_status;
- **world.sqlite:** normalized scenes, entities, world rules, canon facts, source references, event dependencies, option definitions, templates, optional FTS5;
- **assets/** — изображения/обложки/аудио при наличии лицензии;
- **source/** — исходные фрагменты, включаемые ТОЛЬКО если это разрешено и выбрано пользователем; ссылки на диапазоны могут оставаться локальными без упакованного текста.

При импорте проверяются версия, SHA-256, размеры, допустимые пути ZIP, целостность SQLite и совместимость. Книги/пакеты недоверенные: никакого выполнения встроенных скриптов. Одна скомпилированная книга может иметь несколько кампаний.

### 7.2. Save: .bwsave (P0)

Содержит ссылку на точную версию BookWorld (id + hash), campaign_id, parent_campaign_id, роль, режим сюжета, текущую сцену, seed/RNG-state, журнал принятых событий, контрольные снимки, знания NPC/игрока, инвентарь и отметку последнего подтверждённого хода. Поддерживает миграции schema_version. Не изменяет BookWorld и не раскрывает секреты при синхронизации сторонним пользователям.

### 7.3. Локальное хранилище

Flutter/Dart: SQLite + Drift, отдельные директории библиотеки, кампаний, кеша и секретов. Исходный текст и пакеты не помещать в общедоступный кеш. Использовать транзакции, резервное копирование перед миграцией и проверки импорта. Встроенный FTS5 применять только после проверки доступности в поставляемой сборке.

## 8. LLM и Z.ai GLM-4.7-Flash

**FR-AI-01 (P1).** Провайдер по умолчанию — Z.ai API, model_id **glm-4.7-flash**, OpenAI-совместимый endpoint **https://api.z.ai/api/paas/v4/**. Заменяемый интерфейс провайдеров с профилем возможностей (JSON, streaming, context, token count, limits, pricing policy).

**FR-AI-02 (P1).** Подключение личного API-ключа (BYOK) в настройках, проверка соединения и выбор задачи: анализ / структурирование / рассказчик / аудит. Ключ в OS secure storage; никаких ключей в репозитории, .bworld, логах и telemetry. Для будущего публичного hosted режима общий ключ — только на сервере-посреднике.

**FR-AI-03 (P1).** На **2026-11-01** официальный прайс Z.ai показывает GLM-4.7-Flash как **Free** для входных, выходных и кешированных токенов. **Это не гарантия будущей бесплатности или отсутствия лимитов.** Лимиты аккаунта проверять при использовании; реализовать 429/backoff, очередь, отмену, восстановление, ограничения параллелизма, переключение модели и явное подтверждение платного режима. Источник: https://docs.z.ai/guides/overview/pricing.

**FR-AI-04 (P1).** Отдельное согласие на передачу текста книги/фрагментов стороннему облачному провайдеру; до согласия локальные файлы не покидают устройство. Показывать, какие данные и куда отправляются. Локальный ИИ на мощных ПК — последующая опция; Android-локальная LLM — экспериментальный P2.

**FR-AI-05 (P1).** Для извлечения данных: JSON output там, где подтверждена поддержка конкретной моделью; независимо — серверная/Dart проверка по JSON Schema и логическая проверка ссылок на оригинал. Если режим формата не поддержан, безопасное повторение запроса или штатная ошибка; не считать любой JSON истинным.

**FR-AI-06 (P1).** Во время игры модель получает только подобранные сведения с бюджетом контекста: правила, текущая сцена, персонажи и их доступные знания, нужные фрагменты книги, последние подтвержденные события, текущее действие. Нельзя передавать весь роман на каждый ход.

**FR-AI-07 (P1).** При недоступности Z.ai классический режим продолжает работу; AI_FREEFORM не «додумывается» бесконтрольно, пользователь видит предложение перейти на подготовленные выборы, если существует совместимая сцена.

**FR-AI-08 (P1).** Никаких автоматических скрытых платных fallback-провайдеров. Учёт числа запросов, входных/выходных токенов, времени, ошибок; отключаемые приватные журналы без текста книги/секретов.

**FR-AI-09 (P1).** Контент книги и ответ LLM считаются недоверенными данными. Prompt injection из текста не может заставить программу отправить ключ, выполнить код, открыть файлы или изменить правила. Инструменты с побочными действиями не предоставляются тексту романа.

## 9. Mobile-first, перенос и чтение в дороге

**FR-SYNC-01 (P0).** Поддерживается ручной экспорт/импорт игровых пакетов и сохранений. Экспорт — атомарный, с хешами/версией, без включения токенов доступа. Нужен понятный UX передачи на телефон.

**FR-SYNC-02 (P1).** При двух разных ветвях одного сохранения создавать две ветки и предложить выбор; не перезаписывать бесшумно.

**FR-SYNC-03 (P2).** Необязательная синхронизация через сервис после отдельного согласия. Регистрация аккаунта не нужна для обычного офлайн-прохождения. Облачная синхронизация не должна блокировать запуск.

**FR-SYNC-04 (P0).** Автосохранение после принятия каждого игрового действия и после изменения позиции чтения; корректное восстановление при принудительном закрытии Android-приложения.

**FR-SYNC-05 (P1).** При потере связи ИИ-запрос помечается как неисполненный, а не как подтверждённое действие. Восстановление не должно удваивать ход.

## 11. Архитектура и репозиторий

~~~text
AI-Story-RPG/
  apps/story_reader/                # Flutter UI Windows + Android; iOS later
  packages/story_core/              # deterministic world state, rules, actions
  packages/bookworld_format/        # .bworld import/export, schema, integrity
  packages/campaign_manager/        # event log, branching, .bwsave
  packages/book_reader/             # reading, anchors, bookmarks
  packages/llm_client/              # provider abstraction, Z.ai adapter, quotas
  packages/book_compiler_core/      # portable Dart analysis orchestrator
  tools/book_compiler_python/       # optional Docling/Python enhanced importer
  shared_schemas/                  # JSON Schema, migrations, fixtures
  samples/                         # only rights-cleared fiction and test packs
  tests/                           # unit, integration, golden, e2e, long-play
~~~

**Архитектурная граница:** Dart story_core — единственный авторитетный механизм фиксации хода. Python, LLM, UI и облачный сервис не записывают канонический state напрямую. Подготовка BookWorld — отдельный конвейер и процесс; она не требуется при обычном офлайн-запуске готовой книги.

Сценарные правила должны быть сериализуемыми и переносимыми: данные, а не исполняемый код произвольного происхождения.

## 12. Нефункциональные требования

- **NFR-01 (P0):** корректное офлайн-прохождение готовой классической книги без запуска модели, сети, аккаунта и сервера.
- **NFR-02 (P0):** одинаковые результаты интерпретации действий и хеши состояния между Android и Windows при одинаковых входных данных и seed.
- **NFR-03 (P0):** атомарность сохранений, миграции с проверкой, отсутствие потери подтверждённых ходов после перезапуска.
- **NFR-04 (P0):** все важные действия и изменения состояния имеют машиночитаемый идентификатор, могут быть воспроизведены тестами; записывать provenance фактов из книги.
- **NFR-05 (P0):** UI читается на небольших мобильных экранах, поддерживает масштабирование, энергосберегающий офлайн-режим. Целевые модели устройств и численные метрики FPS/памяти уточняются в M0 после выбора контрольных устройств.
- **NFR-06 (P1):** обрабатываются длинные книги с возобновлением частичных задач. Запросы ограничены квотами и token budget; текст не отбрасывается без пометки.
- **NFR-07 (P1):** русский текст в первую очередь; оригинал может быть на другом языке, но перевод/адаптация не подменяют канонические термины. Чтение UTF/Unicode корректно.
- **NFR-08 (P1):** наблюдаемость: журналы этапов компиляции/игры, ошибки классифицированы; приватные пользовательские данные редактируются/исключаются, сбор телеметрии по согласию.
- **NFR-09 (P1):** BookWorld должен иметь versioned schema и migration contract, а неподдерживаемые пакеты — понятное сообщение, не падение приложения.
- **NFR-10 (P1):** UI соответствует выбранному жанру книги и даёт читательский опыт, не превращает программу в технический чат с моделью.

## 15. Риски и принятые меры

| Риск | Мера |
|---|---|
| Плохая точность LLM на больших книгах | Чанкинг, полный coverage, ссылки на источник, cross-chapter validation, ручной review |
| Случайное раскрытие сюжета | Разделение author/planner/player/NPC knowledge, антиспойлер тесты |
| Взрыв числа веток | Граф условий и причин, ограниченные классические ветки, поддержка разветвлений по потребности |
| Мобильное устройство не тянет Python/OCR/локальную LLM | Общий Dart runtime, облачная компиляция с согласия, Python только в отдельном optional tool |
| Изменение «бесплатной» модели/лимитов | Provider abstraction, BYOK, квоты, явное согласие на платные модели |
| Чужие права на произведение | Локальная обработка, явные правила публикации, отсутствие DRM bypass |
| Ошибки в импортированном архиве | Limit/checksum/validation/sandbox for data, no executable package scripts |
| Разные результаты Android/Windows | Deterministic engine, fixed seed, golden cross-platform tests |
| Неопределённые лицензии чужого кода | MIT/BSD only with notices or legal confirmation, dependency register |
| Потеря истории разработки | Нормативное ТЗ, статус/hand-off, changelog, tests, committed source |

## 16. Известные решения и открытые вопросы

**Зафиксировано:** кроссплатформенность с начала; общий Dart движок; книга как один read-only BookWorld; независимые кампании; 3×3×3 выбора; классический офлайн-базис; сменяемый ИИ провайдер и GLM-4.7-Flash как стартовый; согласие на передачу текста; разработка с тестами и воспроизводимостью; русский язык первым.

**Требует решения в M0/M1, не блокирует фиксацию концепции:**
1. Лицензия собственного продукта и условия будущей публичной библиотеки адаптаций.
2. Минимальные поддерживаемые Android API/Windows версии и перечень тестовых устройств.
3. Точный механизм общего импорта EPUB/FB2/DOCX/PDF на мобильном устройстве и выбор библиотеки.
4. Пределы квот и качество конкретного аккаунта Z.ai; контракт формата JSON именно для glm-4.7-flash проверяется live.
5. Дизайн редактора, стратегии синхронизации и iOS build pipeline — поздние этапы.

Изменения обязательных решений вносить через отдельный ADR/PR и обновление этого документа; в STATUS записывать **только подтверждённые** факты, не планы.
