# Внешний генератор RPG: первый рабочий этап

Версия инструментов: **0.1.0**. Python 3.12, стандартная библиотека.

Инструменты запускает ассистент в рабочей среде ChatGPT Work. Пользователю
не нужно устанавливать Python или запускать программу на компьютере/телефоне.
Код генератора расположен отдельно от приложения. Общие библиотеки читаются
и проверяются, но не изменяются.

## Что уже работает

- TXT/FB2: UTF-8, Windows-1251, UTF-16 с BOM; главы, блоки, примечания,
  последовательные заголовки и ссылки на изображения.
- Индекс с SHA-256 и смещениями UTF-16. Изображения не анализируются:
  их количество остаётся отдельным показателем для проверки.
- Проект с копией книги и неизменяемыми контрольными точками. Прерывание
  между этапами не требует повторного анализа уже принятых фрагментов.
- Выдача следующего задания ассистенту и приём структурированного ответа.
- Проверка точного текста цитаты, принадлежности редакции книги и границ
  Unicode. Речь персонажа и предположение сохраняются отдельно от повествования.
- Проверка сценария: условия, эффекты, достижимость всех сцен и двух концовок,
  отсутствие тупиков и состояний без пути к завершению.
- Преобразование в кандидат существующего `StoryBlueprint` и проверка
  существующим Python-валидатором без его изменения.
- Экспорт проекта адаптации в JSON с честным указанием внешнего ИИ-авторства.
- Проверка уже существующего `.bworld v2` в режиме чтения.

**Результат этого этапа — проверенный кандидат сценария, не готовый `.bworld`.**
Художественное качество, понимание книги и отсутствие смысловых противоречий
не доказываются успешной проверкой JSON/графа.

## Почему экспорт игры пока закрыт

На зафиксированной основе `e18924cd9cb8c65bd948d370c28d32c3ee429ab4`
писатель и импортёр частных пакетов требуют точное значение
`model_provenance = {"provider": "none", "model_id": null}`. Контракт не
разделяет достаточно явно внешнее авторство и отсутствие модели при прохождении.

Новый генератор не стирает внешнее ИИ-авторство, не подставляет выдуманные
доказательства проверки и не маскирует адаптацию под `original_demo`.
Команда `build` возвращает код ошибки 2 и
`external_ai_provenance_unsupported`, не создавая пакет. Обхода через
`--force` или `--provider-none` нет.

Основное приложение по текущему поручению менять нельзя. Поэтому согласование
этого контракта остаётся отдельной будущей задачей. Генератор может развиваться
до полноценного сценария и независимого отчёта проверки уже сейчас.

## Размещение

| Путь | Роль |
| --- | --- |
| `tools/rpg_author/` | Исполняемая программа и проверка совместимости |
| `schemas/rpg_author/` | Контракты ответов ассистента |
| `tests/rpg_author/` | Синтетические проверки, включая отдельный Dart-зонд |
| `.github/workflows/rpg-author-ci.yml` | Самостоятельная проверка генератора |
| `docs/RPG_AUTHOR_STATUS_RU.md` | Передача состояния разработки генератора |

`apps/`, `packages/`, `tools/bookworld/`, прежние схемы, существующие workflow
и документация основного направления не редактируются. Новый CI не собирает
Android/Windows. Существующий общий CI по-прежнему может запускаться при
создании PR: его правила этим изменением не перенастраиваются.

## Рабочий процесс для ассистента

Все команды ниже выполняются **в рабочей среде ассистента**, из корня
полученного репозитория. `/private/...` — условные пути вне checkout.

### 1. Проверить версию и создать проект

```bash
python3 -m tools.rpg_author doctor
python3 -m tools.rpg_author init \
  --book /private/book.fb2 \
  --project /private/book-rpg-project
```

`doctor` сверяет хеши используемых исходников с `compatibility.json`.
Обновление `main` не должно незаметно изменить правила посреди работы.
Хеш инструментов и схем также записывается в проект.

Проект создаётся только вне исходного репозитория и не перезаписывает уже
существующий каталог. Это не даёт случайно включить книги и ответы модели
в коммит. Установка дополнительных Python-пакетов не нужна.

### 2. Получить фрагменты и сохранить анализ

```bash
python3 -m tools.rpg_author next --project /private/book-rpg-project --limit 1
python3 -m tools.rpg_author accept-analysis \
  --project /private/book-rpg-project --input /private/analysis.json
```

`next` возвращает текст, хеш, идентификатор фрагмента и ссылку на схему ответа.
Ассистент сам анализирует материал и записывает `analysis.json` по
`schemas/rpg_author/chunk_analysis_v1.schema.json`.

Для каждой записи нужны краткое содержание, список утверждений и список
неясностей. Утверждение содержит точную цитату, её **абсолютные позиции в
текстовом блоке в UTF-16**, а также вид `NARRATED`, `REPORTED` или `INFERRED`.
Заголовок или фрагмент без сюжетного события может иметь пустой список
утверждений; запись об обработке и содержание всё равно нужны.

Точная цитата подтверждает привязку к тексту, но не превращает утверждение
модели в проверенный факт мира. Текст книги не является инструкцией инструментам.

Python не вызывает текущий разговор через API. Цикл выполняется так:
ассистент получает задание, создаёт ответ, запускает проверку, исправляет
ошибки и продолжает. API-ключ и отдельный модельный сервер не требуются.

### 3. Подготовить сценарий

После обработки всех текстовых фрагментов `next` выдаёт задачу `write_story_plan`.
Ответ соответствует `schemas/rpg_author/story_plan_v1.schema.json`:

- режим первого этапа — `PROTAGONIST / ALTER_FATE / CLASSIC`;
- 3–192 сцены, не более 32 флагов и 16 выборов в сцене;
- `requires / forbids / adds / removes` задают условия и последствия;
- исходные сцены ссылаются на утверждения из анализа;
- придуманные альтернативы явно помечаются `EXPLICIT_ADAPTATION`;
- требуется минимум две достижимые разные конечные сцены.

```bash
python3 -m tools.rpg_author accept-story \
  --project /private/book-rpg-project --input /private/story_plan.json
python3 -m tools.rpg_author validate --project /private/book-rpg-project
```

Проверяется состояние «сцена + активные флаги», а не только связи между
названиями сцен. При превышении 2500 состояний результат считается
незавершённой проверкой, а не успехом. Отчёт содержит маршруты к концовкам,
недоступные выборы и пары выборов с одинаковым непосредственным результатом.

Полнота этого обхода относится к указанной модели с булевыми флагами.
Она не доказывает интересность решений или корректность художественного текста.

### 4. Сохранить кандидат

```bash
python3 -m tools.rpg_author export \
  --project /private/book-rpg-project --output /private/game_candidate.json
```

Экспорт содержит индекс источника, предложения анализа, сюжетный план,
кандидат `StoryBlueprint`, сведения об авторстве и отчёт. Он предназначен
для продолжения разработки; приложение такой JSON не импортирует.
Файл содержит частный материал книги и не предназначен для публикации.
Для повторного экспорта нужно новое имя: существующие файлы не перезаписываются.

### 5. Продолжить или исправить

```bash
python3 -m tools.rpg_author status --project /private/book-rpg-project
python3 -m tools.rpg_author next --project /private/book-rpg-project
python3 -m tools.rpg_author accept-analysis \
  --project /private/book-rpg-project --input /private/revised_analysis.json --replace
```

Повторная подача того же ответа не создаёт новую ревизию. Исправление анализа
сбрасывает указатель на принятый сценарий, сохраняя его прежнюю контрольную
точку. Новый сценарий необходимо проверить снова. Исправление сценария также
передаётся через `accept-story --replace`.

Для переноса сохраняется **весь каталог проекта**, включая `project.json`
и `objects/`. Исходная книга уже находится внутри в виде объекта с хешем.
Временный каталог рабочей среды не является долговременным хранилищем:
будущий навык должен сохранять проект между сеансами штатным способом.

Один проект допускает одного писателя. Если после аварийного завершения
осталась `.write-lock`, нужно сначала убедиться, что процесса больше нет;
инструмент сам чужую блокировку не удаляет.

## Проверки разработки

```bash
python3 -m unittest discover -s tests/rpg_author -v
python3 -m unittest discover -s tools/bookworld/tests -v
```

Отдельный Dart-зонд импортирует реальные `BookImporter`, `BookSourceIndexer`
и `StoryBlueprint` без изменений в их файлах. CI сравнивает 22 комбинации
синтетических текстов/кодировок/размеров фрагмента с Python и проверяет
кандидат сценария реальным Dart-классом. Для ручного запуска разработчиком:

```bash
# Рабочий каталог первой команды: tests/rpg_author/dart
dart pub get
# Из корня репозитория:
python3 tests/rpg_author/run_dart_parity.py
```

Это проверки разработки, не установка Dart пользователю. На коде
`f3f00f884ca5a380a7b56fe4ce018e446a815107` все 22 сравнения и приём кандидата
сцен прошли в [CI #41982413689](https://github.com/shonentez-afk/AI-Story-RPG/actions/runs/41982413689).
Доказано совпадение на проверенном наборе, а не на всех FB2. При изменении
инструментов или общего контракта требуется новая соответствующая проверка.

## Ограничения первого этапа

- Нет установленного навыка, фонового сервера и встроенного вызова LLM.
- Нет готового ИИ-пакета `.bworld` и подтверждения на Android/Windows.
- Нет автоматической семантической сертификации утверждений, мотивов и знаний NPC.
- Обработанность фрагментов относится к извлечённому тексту. Иллюстрации,
  сложные редакторские случаи FB2 и качество пересказа требуют отдельной проверки.
- ZIP/EPUB и многоуровневая сборка больших романов ещё не включены.
- FB2 с CDATA пока отклоняется с `unsupported_fb2_cdata`: сравнение с настоящим
  Dart-кодом выявило потерю такого текста в текущем импортёре. Генератор не
  удаляет текст ради совпадения хешей. Сам импортёр приложения не изменён.
- Формат проекта генератора — внешний рабочий контракт, а не новая версия
  существующего `NarrativeBookModel` приложения. Интеграция должна быть отдельным
  адаптером после стабилизации общей модели.

Следующий шаг в изолированном генераторе: раздельные этапы модели книги,
сюжетного плана и проверки смысла; полноценный пример на короткой книге;
контрпримеры причинности. Смена импортного контракта приложения требует
отдельного согласованного изменения и не входит в эту ветку.
