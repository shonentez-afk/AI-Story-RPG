# M1.7.4b1 — подключение подготовленных BookWorld к единой библиотеке Flutter

**Исходная база:** docs HEAD `15e32e5fd5991bf8457f14940520190bcacf9844`, кодовая база `cc69778586b45c3e82c4f1dc415ce2dc545b043e` (Actions #145 SUCCESS, 71 Flutter, 10 SQLite, Android/Windows PASS).

## Архитектурная граница

ТЗ §7.1/7.3 и ADR-001 сохраняются: `story_engine` отвечает за переходы сцен, `story_core` за проверку условий, инвентарь и event log, `campaign_manager` — SQLite транзакции/восстановление. Python используется только в отдельном компиляторе; ни один экран не исполняет Python и не требует ИИ/сервер.

Новые файлы:
- `apps/story_reader/lib/world_library_gateway.dart` — `WorldLibraryGateway`, DTO и `DeviceWorldLibraryGateway`. `path_provider.getApplicationSupportDirectory` определяет приватный каталог `ai_story_bookworld/`. Каждая операция открывает свой `BookworldCampaignStore` внутри `Isolate.run` и закрывает SQLite в `finally`: UI не выполняет тяжёлый replay/ZIP/SQLite синхронно.
- `apps/story_reader/lib/world_campaigns_page.dart` — карточка выбранного мира с реально сохранёнными кампаниями, старт/открытие, настоящее ответвление из родителя, экспорт и импорт BookWorld `.bwsave` v2 через системные диалоги. Не смешивать с пилотным `.bwsave` v1.
- `apps/story_reader/lib/world_play_page.dart` — самостоятельная игра с реальным текстом сцены, вариантами с `lockReason`, кнопкой «Герой», «Предметы», «Журнал». На UI подтверждённые изменения появляются **после возврата SQLite COMMIT**; при сбое состояние не меняется оптимистически. Названия характеристик/предметов берутся из фактических данных тестового мира, не генерируются ИИ.
- `apps/story_reader/lib/home_page.dart`: единственный существующий `LibraryPage`, **одна кнопка `library-import` «Добавить книгу»**, общий системный picker TXT/FB2/.bworld. Проверенный мир в существующей библиотеке отличим от книги (метка «Подготовленная RPG»), поиск умеет фильтровать и его. Старый `BookReaderPage` открывает только настоящие TXT/FB2, `WorldCampaignsPage` — только подготовленные RPG. Загрузка мира с ошибкой не скрывает книги.
- `apps/story_reader/pubspec.yaml`: добавлен прямой path dependency `campaign_manager`; для widget integration tests — dev-only `path_provider_platform_interface`. Runtime использует уже одобренный `sqlite3` FFI через Dart package + build hooks.

## Сохранность данных

- Старые `BookStorage` JSON с TXT/FB2 и изображениями остаются в `ai_story_library` (DocumentsDirectory). Их формат, порядок и ключи не менялись.
- Старые `CampaignStore`, `GameProgress`, `SaveStore`, `rulesVersion=0/1` и пилотный `ai_story_pilot_bwsave_v1` остаются без изменений в `SharedPreferences`.
- Новый SQLite `bookworld_campaigns_v1.sqlite` в `ApplicationSupportDirectory/ai_story_bookworld`. Внутри реальный подтверждённый журнал, revison/head hash, верификация full replay на каждый load. Новый v2-save содержит ссылку на точный установленный BookWorld SHA; при несовпадении мира или нарушении целостности импорт отказан.
- Пользователь не должен терять старые кампании только из-за отсутствия/повреждения новой базы: экран библиотеки ловит ошибки второго backend отдельно; любые подсказки про восстановление должны оставаться честными.

## UI/UX решение

Сохранены главный экран с одним входом «Библиотека», «Новая история», «Мои прохождения», существующие настройки, темы и читалка. В библиотеке нет второй кнопки «Импортировать», нет отдельного второго каталога. Только одна новая карточка *подготовленного игрового мира* в результатах поиска. После открытия мира — его собственные кампании и выбор нового прохождения. RPG-экран переиспользует `GameQuickBar` для трёх игровых панелей. Выбор с невыполненными условиями виден, но недоступен и подписан объяснением; отмена во время сохранения исключает двойной ход.

### Автоматические критерии

`apps/story_reader/test/world_integration_test.dart`:
1. Наличие **единственной** CTA импорта в библиотеке при установленном настоящем .bworld, открытие WorldCampaignsPage, затем StoryEngineCoordinator через SQLite, реальная причина недоступного выбора, panel «Герой» и «Журнал».
2. **35 реальных Flutter UI-нажатий**, SQLite commit каждого, выход/повторное открытие после 23, финальная сцена, сверка 35 событий, знаний игрока и флагов. Это не тест только чистого Dart ядра.
3. Принудительная ошибка сохранения в UI-шлюзе — сцена и revision не изменяются; подтверждено чтением actual SQLite.
4. Компактный экран 320dp и масштаб текста 200% — чтение журнала и отсутствие runtime overflow.
В Flutter CI добавлен сборщик тестового `.bworld` из того же blueprint, что проверяется отдельно, а затем весь старый widget/reader набор и новые тесты. Android и Windows jobs по-прежнему зависят от всех тестов.

**CI/QА статус:** для нового SHA статус `PASS` писать только после полного run. Не выдавать запуск на CI Linux за физическую проверку устройства.

## Не реализовано и следующий шаг

- Новый мир пока доступен **через библиотеку**, но общий экран `Мои прохождения` M1.6 ещё показывает старые пилотные кампании; консолидированный список всех кампаний (без дублирования библиотек) — следующий UX шаг.
- Удаление импортированного BookWorld и его кампаний **не реализовано**: нельзя удалять мир с сохранениями неявно; нужна безопасная явная политика удаления и recovery.
- Перенос/конверсия legacy M1.6 в новый world невозможны без достоверного отображения старого графа на новый blueprint. Действующая политика — **dual-read без разрушительной миграции**, с сохранением .bwsave v1 и v2 раздельно. Настоящая миграция M1.6 и резервные копии — после формализованного соответствия сцен/состояний.
- Никакой загрузки произвольной TXT/FB2 непосредственно в RPG, роли/меняющийся сюжет/HYBRID/AI, source references/coverage/provenance; demo .bworld содержит только оригинальный тестовый мир.
- Полный **reader chrome** (normal/reading/fullscreen) и собственные настройки чтения пока реализованы для старой читалки/пилотной RPG. Новая сцена использует общий Theme и нижний GameQuickBar; до окончательной UI/UX приёмки нужна унификация масштабирования, прокрутки и экранных режимов.
- Приложение пока не выполняло настоящий Android↔Windows E2E перенос `.bwsave`, аппаратный accessibility audit, power-loss и crash-recovery с физическим отключением питания.
- Следующие фазы M1.7.4b2: объединение «Мои прохождения», безопасное управление установленными мирами, QA 320/200%, состояния ошибки, device E2E, резервные копии; после — полный M1.7 acceptance и компилятор книг M2.
