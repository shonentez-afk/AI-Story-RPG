## Фактически проверенный оригинальный файл (не публикуется)

Название файла: `Andersen Gans. Samye krasivye skazki (s illyustraciyami) - BooksCafe.Net.fb2`.
SHA-256 исходного файла: `6713c5ab79bd68e30b647177a9ac951c73d72b36b6942f2195f247221763148a`.
Размер: **7 441 257 байт**, корректный UTF-8 XML, корень `FictionBook` с namespace FictionBook 2.0 и xlink. Титул: «Самые красивые сказки (с иллюстрациями)»; автор: Ганс Христиан Андерсен. Формат в пределах лимита импорта **20 МиБ**.

Локально проверены реальными байтами исходника:
- **2 FB2 body**: основной без имени, 6 `section`/сказок; `body name="notes"`, 3 пронумерованные сноски с id/bookmark. Старый импортёр превращал 3 сноски в отдельные главы 7, 8, 9.
- **67 `binary` image/jpeg**: все 67 корректно Base64-декодируются и успешно проходят открытие и верификацию Pillow как JPEG/RGB; наибольшая по площади обложка 1212×1725; **66** ссылок на изображения в основном тексте, ни одной отсутствующей; обложка `image1.jpg` ~282 393 байта.
- **667 XML `p` элементов**, text extraction с сохранением структуры дал около 115 750 символов; схема текстовых блоков не превышает установленный лимит.
- Есть внутренние ссылки `<a type="note" href="#bookmarkN">`; существующий Dart reader показывает номер как текст, но **пока не поддерживает интерактивный переход к сноске**. Это отдельный UX-долг, не подменять готовой возможностью.
- Файл пользователя **не добавлен в GitHub, Actions, Releases или fixtures** из-за авторских прав/приватности; опубликованы только метаданные и исходный синтетический тест.

## Что исправлено

В `BookImporter._fb2` обычные `body` обрабатываются как раньше, а `body name="notes"` и `body name="comments"` сохраняются в отдельные агрегированные главы «Примечания»/«Комментарии». Содержимое всех подпунктов сносок (1/2/3) сохраняется, но больше не выдаётся за самостоятельные сказки. Ожидаемая структура этой книги после **повторного импорта**: 6 сказок + 1 глава «Примечания» = **7 глав**, 67 доступных ресурсов и 66 внутритекстовых изображений.

Новая регрессия `apps/story_reader/test/illustrated_fb2_collection_test.dart` создаёт **полностью оригинальную** XML FB2 с аналогичной структурой (2 body, 6 сказок, 3 сноски, 67 встроенных валидных мини-JPEG, 666 абзацев), проверяет парсинг, иллюстрации, обложку, индексацию, хранение и повторное открытие из JSON-библиотеки. Это структурная реплика, а не полная бинарная проверка пользователя на работающем Flutter: в текущей среде нет Dart/Flutter SDK для прямого запуска Dart импортёра над закрытым исходным FB2.

Уже сохранённые в старом формате библиотечные JSON не содержат исходный FB2: новая группировка сносок применяется **к новому импорту**; не менять/переписывать старые пользовательские файлы автоматически. Для исправленного оглавления пользователь может импортировать FB2 заново, а старую запись удалить по собственному желанию.

## Исправление Releases

Ранее GitHub Releases показывал только старый Android `android-build-247`; Windows bundle существовал лишь как временный Actions artifact. В `.github/workflows/android-ci.yml` публикация перенесена в один `publish-release` job, который ждёт **успешного Android APK и Windows portable**, скачивает оба проверенных артефакта и публикует тестовый GitHub Release `test-build-N` с:
- `AI-Story-RPG-Android-debug.apk`;
- `AI-Story-RPG-Windows-portable.zip` с **полной** папкой exe + dll + assets/data;
- `SHA256SUMS.txt` для обеих сборок.

PR CI должен пройти 6/6 до merge. Публикация происходит только при `push`/ручном вызове на `main`, на PR не происходит. После merge проверить появление **реального** `test-build-N` Release, размеры/хэши assets, commit, успешный release job. Старые ссылки Android test releases не уничтожать автоматически.

## Границы QA

Pillow+XML подтверждают корректность пользовательского файла, синтетические Dart тесты — работу настоящего FB2 импортёра на аналогичной структуре. **Реальное открытие этого же оригинала в запущенном Windows EXE/Android APK остаётся непроверенным без локального Flutter SDK или пользовательского E2E.** Проверить на устройстве: импорт файла, чтение первой и шестой сказки, 66 картинок, «Примечания», сохранение позиции, «Подготовить к RPG», повторный вход; при сбое сохранить полный stack trace.
