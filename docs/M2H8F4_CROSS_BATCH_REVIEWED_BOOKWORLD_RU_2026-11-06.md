# M2h8f4 — отдельная приёмка эффектов из разных пакетов и выпуск частного rich BookWorld v3

Дата 2026-11-06. Статус: новая PR-ветка поверх M2h8f3; необходим exact-head CI.

## Что реализовано

Добавлен API `ReviewedGameplayCompiler.previewAcrossBatches(...)`, который принимает ОДНУ книгу, ЕДИНЫЙ StoryPlan, точный WholePlanGameplayBatchManifest и все проверенные локальные предложения из каждого пакета. Читатель выбирает только допустимое подмножество и вводит отдельное личное объяснение каждого решения. Не выбранные модельные предложения НЕ становятся частью мира.

- Сверяются fingerprint редакции, SHA плана, фактический состав пакетов и SHA каждого consent source window; подмена одного пакета или пользовательского выбора блокируется.
- Подтверждается точность каждой текстовой цитаты в исходном индексе; привязка effect к scene/choice/source-event и названиям предметов также повторно проверяется.
- Все выбранные эффекты проходят **единый** граф состояний M2h8f3, независимо от номера пакета. Нельзя потратить предмет до получения, выдать дважды на одном достижимом пути либо спутать предметы с одинаковым ID.
- Для первого безопасного контракта принимается не более **шести** выбранных эффекта на один новый мир. Этот предел соответствует существующим строгим Dart и Python импортёрам и не должен скрываться. Возможность расширить объём на всю большую книгу остаётся отдельным этапом.
- На выходе — неизменяемый JSON предпросмотра и SHA полного набора; отдельный `compileAfterUserConfirmation` обязан получить именно SHA этого предпросмотра и явное подтверждение частной игровой выдумки.
- Итоговый rich v3 создаётся заново с новой identity. `source/provenance.json.gameplay_review` указывает исходный SHA и только реально одобренные операции, подтверждаемые Dart и Python. Действуют `grant_item`, `consume_item`, `learn_fact`. Старые книги, игровые миры и SQLite-сохранения не изменяются.
- Литературная достоверность и CANON **не доказываются**, даже при нуле игровых конфликтов. Модель не получает разрешение выдумывать владение, знания NPC или сюжетные причины.
- Синтетический E2E на четырёх актах: два разных исходных пакета с предметом/фактом → два подтверждения → импорт нового богатого v3 → установка в чистую SQLite кампанию → отказ при повторном применении или подменённой подписи.

## Следующие шаги

Подключить этот двухступенчатый API к пользовательскому экрану после M2h8f2–f3 (индивидуальный выбор между пакетами, редакторская заметка, просмотр конфликтов, финальное подтверждение), затем поднять обоснованный лимит реально принимаемых эффектов для длинных книг с синхронным обновлением Dart/Python контрактов. Далее независимый литературный аудит всего дерева, режимы CANON/ALTER_FATE и E2E на двух реальных книгах с GLM на Windows/Android.

Реальных книг и API-ключей в публичных CI-тестах нет; старые вымышленные миграции не добавляются.
