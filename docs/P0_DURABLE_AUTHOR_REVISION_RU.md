8 ноября 2026. Единый пакет внутри Draft PR #133. Не меняет main, внешний E6d, автономный движок, сохранения кампаний или wire-схему .bworld.

## Пользовательский результат

Герой и реплики уже сохранялись; теперь не теряется выбранный набор предметных/знаниевых эффектов и пояснения к ним. В общем редакторе: восстановить героя → подтвердить исходную редакцию → открыть редактор → «Проверить сохранённые эффекты» → общий просмотр NPC → начать новую игру. Восстановление не обращается к ИИ, не запрашивает предложения повторно и не устанавливает архив. Разрешения не отмечаются автоматически.

## Данные и повторная проверка

`NpcCampaignConsequenceStore` использует тот же SourceAnalysisCheckpointRepository в отдельном hashed scope. Ключ включает source fingerprint, plan digest и hero review digest. Запись включает SHA базового архива, ревизию, уникальный write_id, manifest digest, лимит исходного manifest, отобранные candidate records и авторские notes. Лимит 64 KiB и 1–6 эффектов. Оригинальные цитаты, главы, готовый ZIP, ключ API и сохранённые согласия не копируются.

Каждая загрузка заново строит WholePlanGameplayBatchManifest из текущего source plan. Кандидаты связаны с текущими context digests, событиями и действиями. Прежний NpcCampaignConsequences.preview / ReviewedGameplayCompiler / GameplayCandidateReachabilityAuditor проверяет literal item names и достижимость совместного набора. Пересчитанная checksum не заменяет эти проверки; сама checksum не является аутентификацией автора или доказательством канона.

`NpcConsequenceDraft` всегда имеет cloudConsent=false, installConsent=false и effectsAccepted=false. После повторного открытия .preview позволяет показать уже выбранный набор, но ещё не выдаёт исполняемый вариант. NpcCampaignConsequences.accept требует нового точного согласия и по-прежнему выполняет строгий импорт и полный причинный обход до применения.

## Конфликты и восстановление

Запись сериализована в одном процессе приложения и сверяет expected record hash перед атомарной заменой файла. Это не заявление о межпроцессной распределённой транзакции. Ошибка записи не публикует новую ревизию в UI. Удаление оставляет пустую запись с новым write_id; старое окно не сможет воскресить прежний выбор через ABA-совпадение. Повреждённый/устаревший файл не обнуляется автоматически: автор явно сбрасывает только эту запись, а её точный токен проверяется снова после диалога подтверждения.

NPC-реплики, выбор героя и эффекты остаются отдельными сохраняемыми записями. Их не выдаём за один атомарный многофайловый снимок. Вместо этого общий экран перед review и install заново сверяет все версии. Изменение героя, карточек, реплик или эффектов в другом окне блокирует старую итоговую приёмку. Установка существующей игры не переписывается.

## Не выполнено этим пакетом

Маршрутно-зависимый контекст предметов/мотиваций для ИИ ещё не добавлен. Модель реплик не должна считать выбранный grant_item уже состоявшимся владением. Следующий блок должен передавать только отдельно показанные и разрешённые сведения, различать возможное и обязательное состояние по маршрутам, проверять смысл реплик и не превращать текст ИИ в runtime-правила.

Полная произвольная книга, CANON/ALTER_FATE, живой GLM, две разные приватные русские FB2 и физическое испытание Android/Windows остаются открыты. Синтетический PASS не закрывает #118 и весь PR #133.
