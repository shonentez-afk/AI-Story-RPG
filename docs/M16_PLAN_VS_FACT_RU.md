# M1.6 — сверка первоначальной дорожной карты с фактической реализацией

Дата: 2026-11-01. Источник базовых требований: docs/ROADMAP_RU.md.

## Что подтверждено
- Android debug APK и Flutter/Python/Dart CI: run #88 success (на момент фиксации). Android сборка производится после генерации host Flutter.
- UI «Моя история», импорт и чтение TXT/FB2, офлайн сохранения книг, разделение настроек чтения и общего оформления.
- Основной runtime выбран ADR-001: story_engine; есть независимые reference tests со сценарием 11 сцен, 21 действие, 3 финала в experiments/m0_engine_comparison.
- M1.6.0: журнал текущего сеанса выводит реально выбранные действия, не имитирует уже несуществующие факты. После восстановления snapshot список пока не восстанавливается.

## Несоответствия первоначальному M1
1. Клиентская демонстрационная история — две сцены, не целевые 6+ сцен и 2+ финала / 2 изменяемых состояния.
2. Герой и инвентарь — информационные заглушки, нет доменной модели предметов и характеристик в пользовательском экране.
3. Встроенный SaveStore: 1 слот в shared_preferences; это не отдельные версии .bwsave, импорт/экспорт и не автоматические чекпойнты.
4. Форматы BookWorld (.bworld) и .bwsave не встроены в GUI.
5. Windows EXE с проверенной сборкой в Actions отсутствует.
6. Book Compiler, конструктор героя/режимов, свободный ввод и интеграция LLM — M2/M3 и не выполнены.
7. Фирменные Android ресурсы генерируются CI; Android 12+ adaptive icon и точный системный splash требуют инспекции на устройстве.

- M1.6.4: .bworld/.bwsave, импорт/экспорт, 20 офлайн ходов, Windows EXE.
- После стабилизации M1: M2 Book Compiler с coverage/provenance, затем M3 AI free text.

Критерий закрытия M1: полный M1 acceptance из docs/ROADMAP_RU.md, не зелёный UI CI сам по себе.

## M1.6.1 — постоянный журнал решений
- Сохранение `SaveStore` расширено до версионированного envelope: snapshot `story_engine` и список выборов записываются вместе в старый ключ `ai_story_m1_snapshot_v1` одной операцией `SharedPreferences.setString`.
- Старые записи, содержащие только engine snapshot, читаются без миграции; журнал при этом пустой. Ошибочная новая оболочка вызывает ошибку вместо скрытого обнуления.
- Интерфейс RPG сохраняет и восстанавливает журнал одновременно с engine; старт новой истории по-прежнему создаёт независимый текущий сеанс.
- Добавлены `test/save_store_test.dart` (новый формат, legacy и повреждение) и widget-сценарий «решение → сохранение → главная → продолжить → журнал».
- Это пока **ручное сохранение одним слотом**, а не автосохранение и не полноценный `.bwsave`. CI необходимо подтвердить отдельно.

## M1.6.5 — локальные независимые сохранения (проверка по CI требуется)
- Реализуется `CampaignStore`: несколько отдельных записей, UI выбора/удаления, очередь автосохранений после каждого решения, создание отдельной кампании при перезапуске истории.
- Старый одиночный ключ сохранён как виртуальная legacy-кампания без потери данных; `rulesVersion=0` продолжает старые правила, а новые кампании используют 1.
- Формат переносимого `.bwsave`, экспорт/импорт, SQLite и гарантии crash recovery **пока не выполнены**. Следующий этап M1.6.6, затем BookWorld/Windows acceptance.
