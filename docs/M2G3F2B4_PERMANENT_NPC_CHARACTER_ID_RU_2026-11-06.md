# M2g3f.2b.4 — полная карточка NPC и постоянный character_id

**Дата:** 2026-11-06 · **Ветка:** `feature/m2g3f2b4-stable-npc-character-card-20261106` · **Статус:** код создан, необходим exact-head GitHub CI, до зелёного не сливать.

## Причина

До этого этапа `NpcKnowledgeRulebook.actorId` создавал runtime-ID из SHA книги + текущих ID источниковых упоминаний. В результате новое решение SAME/DIFFERENT, смена текста книги или переизвлечение цитат могло менять актёра. Переименование или редактирование литературного имени не должно менять личность героя и выданные ему знания.

## Что сделано

1. Новый `NpcCharacterCard` в основном Flutter-приложении: **неизменяемый `character_id`** формата `npc_` + 128 случайных бит, генерируется криптографически безопасным генератором при первом создании карточки. Никаких имён, псевдонимов или цитат в алгоритме ID нет.
2. Поля карты: прозвища, роль, биография, внешность, характер, манера речи, мотивация, цели, ключ локального портрета. Для всех полей строгие ограничения размера и управление только локально. Представление редактора НЕ является автоматически литературным каноном и НЕ даёт игрового знания.
3. Полная карточка сохраняется через прежний отдельный атомарный checkpoint `NpcEditorialNotebook`; исправление имени, заметок и полей сохраняет исходный `character_id`, включая после закрытия приложения. Дубликаты и попытки подменить ID отвергаются до записи. Старые черновики без поля карты могут быть открыты, постоянный ID присваивается только при явном открытии новой полной карты, без молчаливой перенумерации старых игровых миров.
4. `NpcEditorialPage`: новый раздел «Полная карточка NPC» с офлайн-формой. ID явно виден. Старые заметки о знаниях и отношениях остаются в прежнем редакторе — никаких конфликтующих «вторых» источников истины.

**Защита сохранений:** `book_id` нового мира дополнительно зависит от упорядоченного набора постоянных actor IDs при наличии хотя бы одной новой карточки. Поэтому создание/смена пространства ID не позволяет открыть старую кампанию под тем же идентификатором мира. Для профилей без новой карты идентификатор мира остаётся прежним; никакой автоматической миграции не выполняется. При последующих переименованиях/смене портрета ID мира остаётся неизменным, потому что `character_id` не меняется. Это проверяет отдельный тест в `npc_knowledge_rulebook_test.dart`.

5. `NpcKnowledgeWorldBridge` использует **сохранённый `character_id`** в `StoryBlueprint.actors`, `initial_state.knowledge`, эффектах `learn_fact` и проверках `knows_fact`. Только если старый тестовый/редакторский профиль ещё не имеет карты, остаётся старый вычисляемый actor ID. Импортёр игрового мира / SQLite engine не переписывались, чужие миры и сохранения не мигрируются.
6. Закрытый текст персонажа, характер и цель не публикуются в публичный BookWorld и не отправляются в API без отдельного этапа согласия.

## Проверка

- `npc_character_card_test.dart`: 128-bit ID, неизменяемость после редактирования и сериализации, запрет произвольных путей к портрету, неизвестных полей и испорченных ID.
- `npc_editorial_notebook_test.dart`: записал → изменил имя и заметки → перезагрузил → ID тот же; подмена и дублирование IDs заблокированы.
- `npc_editorial_page_test.dart`: фактическая UI-форма, создание и изменение подробной карточки, повторное открытие с прежним ID.
- `npc_knowledge_rulebook_test.dart`: настоящий runtime `StoryWorld`, получение знания только после действия, сохранённый actor ID после смены имени, портрета, манеры речи и целей; проверка отсутствия конфиденциального текста в `StoryBlueprint`.
- Exact-head CI Flutter, Dart/Python/schema, Windows portable, Android APK до merge; после merge — отдельная проверка post-merge main и релиза.

## Честные ограничения — ещё P0

Это закрепление личной авторской **идентичности** NPC, а не автоматический литературный `character_id` для каждой роли из любого FB2. Чтобы импортировать новый или повторно проанализированный источник без подмены персонажа, нужен **явный редакторский перенос группы с сохранением ID** и проверка однозначного соответствия цитат. Он НЕ может происходить только по совпадению имени.

Дополнительно нужны: обязательная source-locked привязка говорящего диалога к `character_id`; выбор момента знания событий с цитатой и chapter/act gate; отношения по ID; автоматическая карта персонажей при GLM анализе без придуманных знаний; реальные CANON/ALTER_FATE и полная RPG по двум FB2 с Win/Android E2E. Действующие правила знаний `NpcKnowledgeRulebook` остаются проверяемым источником истины. Внешний генератор **E6d разрабатывается другим чатом**, ветку не изменять.
