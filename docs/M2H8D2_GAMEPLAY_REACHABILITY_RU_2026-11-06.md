# M2h8d2 — проверка игровых маршрутов для предметов и знаний

Дата: 2026-11-06. Статус: отдельная ветка поверх PR #99; требуется exact-head GitHub CI.

## Задача

Перед включением предложенных ИИ операций в живую RPG проверять все достижимые варианты выбора, не только один удачный путь. Отдельная ветка не меняет основную игру и не выполняет сетевых вызовов.

## Реализовано

- GameplayCandidateReachabilityAuditor принимает проверенный локальный контекст цитат, точную версию StoryPlan и привязанный к нему черновик кандидатов. Сверяет SHA плана, fingerprint конкретной редакции, digest согласия, scene/choice/event ID, названия предметов и допустимые операции.
- Полный ограниченный поиск по состояниям: сцена, сюжетные флаги, инвентарь героя, изученные факты. Отдельные маршруты не смешиваются.
- Возвращает диагностические пути для CONSUME_UNOWNED, GRANT_WHILE_OWNED, AMBIGUOUS_SAME_CHOICE, UNREACHABLE_EFFECT, NO_AVAILABLE_CHOICE и ENDINGS_NOT_REACHABLE. Бюджет: 2500 состояний, 32 сообщения.
- Один ID предмета может участвовать в разных операциях, например сначала получение, затем использование. Название и тип этого ID должны быть одинаковыми. Повтор одной операции отвергается.
- Отсутствие предметов/знаний — корректный результат; нет искусственных обязательных сущностей.
- Тесты моделируют оба окончания, корректное приобретение и расход предмета, расход в несовместимой ветке отказа, использование до получения, повторную выдачу, изменение источника и дубли эффектов.

## Важная граница

Логическая непротиворечивость игрового графа НЕ доказывает, что оригинальная книга подтверждает владение вещью или знание персонажа. Модуль не меняет SQLite, архив BookWorld и не выдаёт предложения ИИ за литературный CANON.

## Осталось

Точный CI на каждой целевой платформе; затем независимая семантическая проверка владения и человеческое согласие; только затем перенос типизированных подтверждённых эффектов в native RichPrivateBookworldWriter и создание новой SQLite-кампании. Отдельно нужны выбор героя, режимы CANON/ALTER_FATE, реальный GLM E2E двух книг и испытания Windows/Android.

Частные книги и API-ключи нельзя выкладывать в публичный GitHub. Не создавать миграцию несуществующих старых пользовательских миров.
