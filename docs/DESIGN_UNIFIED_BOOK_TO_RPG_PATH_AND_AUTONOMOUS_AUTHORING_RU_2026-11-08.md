# AI Story RPG — отдельное проектирование единого пути «книга → RPG» и полной автономности

Дата: 8 ноября 2026. **ЭТО ТЕХНИЧЕСКИЙ/UX ПРОЕКТ ДО НАЧАЛА ПЕРЕДЕЛКИ МАСТЕРА**, не обещание готовых режимов. Один Draft [PR #133](https://github.com/shonentez-afk/AI-Story-RPG/pull/133), два крупных функциональных пакета, одна сквозная приёмка. Главный критерий: не терять функциональность `story_core`, rich-v3, проверку источника, NPC/предметы/события, ИИ, сохранения или автономность ради упрощённого UI.

Исходные требования: [единая матрица разрывов](ENGINE_FORMAT_UI_GAP_AUDIT_RU_2026-11-08.md), [общий план](PLAN_TWO_UX_AUDITS_ONE_PR_RU_2026-11-08.md), [критерий завершения 1.0](PROJECT_COMPLETION_GATE_RU_2026-11-06.md). Архитектура и источник истины — `story_core` + `story_runtime_adapter` + `bookworld_format` + `campaign_manager`. Ни Flutter, ни GLM не должны становиться альтернативной реализацией игрового состояния.

## 1. Три независимые оси режима — не смешивать в одном переключателе

| Ось | Вариант | Состояние сейчас | Что требуется, чтобы открыть |
|---|---|---|---|
| **Кем играть** | Собственный протагонист | Текущий executable `PROTAGONIST` | Поддержан |
| | Подтверждённый книжный герой | Частный выбор `character_id` и identity flag на части authoring пути, но не полный режим `BOOK_CHARACTER` в `StoryBlueprint` | Начальные проверенные знания, предметы, мотивы, ограниченная точка входа; строгая source review |
| | Пользовательский персонаж | `CUSTOM` перечислен в enum, валидатор не разрешает | Отдельная безопасная роль/биография/начальные свойства, не выдавать за героя книги |
| **Как развивается история** | CANON | Для private rich-v3 НЕ разрешён; `CANON` в core только original-demo | Одно доказанное исходное окончание и проверенная хронология, без навязанной альтернативной концовки |
| | ALTER_FATE | Действующий частный структурный вариант, но не литературное подтверждение всей книги | Разветвления с источниковой точкой расхождения, мотивами, актовыми последствиями и честным указанием адаптации |
| | FREE_WORLD / собственная вселенная | Строка перечислена, текущим core не исполняется | Не брать книжный мир без источника, separate world-lore contract, самостоятельное source/provenance |
| **Как управлять** | CLASSIC | Исполняется: типизированные `choice_id` и SQLite replay | Полное покрытие сцен/действий, ясные блокировки |
| | HYBRID | Не поддержан текущим верификатором режимов | Все действия проверяются core, ИИ только предлагает допустимые typed additions |
| | AI_FREEFORM | Не поддержан; существующий ИИ выбирает лишь из allowed choices | Ограниченная генерация проверяемых действий, validation/apply/replay, согласие, политика приватности. Произвольный ответ модели НЕ может напрямую менять мир |

**Правило UI:** показывать «доступно сейчас / частная проба / в разработке», не отображать неподдержанные значения как работающий режим. Для длинных книг и для режима без интернета заранее выявлять блокеры.

## 2. Одна пользовательская траектория со сквозным состоянием

### Вход
Библиотека → «Читать» или единая «Создать RPG» → выбор источника (локальный TXT, FB2, FB2.ZIP либо подтверждённый пользовательский мир в будущей версии) → обзор формата, лимитов, изображений/оглавления, обнаруженных глав, проверка источника и возможного продолжения. На том же пути «Продолжить подготовку» поднимает точный checkpoint; не открывает второй мастер и не сбрасывает принятую работу.

### Подготовка до любого облака
1. **Снимок исходной редакции:** UTF-16, полное индексирование, source fingerprint, главы, изображения, содержимое и пропуски; нельзя молча заменить текст или автоматически скачать другой источник.
2. **Состав персонажей и мира:** упоминания/алиасы, роли и постоянные `character_id`, места, предметы, последовательность повествования отдельно от фактической хронологии мира. Не выводить имя NPC из совпадения текста.
3. **Факты и доказательства:** literal quote/offset/chapter, слух/знание/интерпретация, подтверждение человеком. Разделять «цитата подлинна» и «вывод верен».
4. **Режим и герой:** выбор допустимой оси персонажа, типа сюжета и взаимодействия с пояснением, какие функции на выбранной редакции работают, ограничения стартовых знаний/вещей. Смена роли сохраняет другие editor drafts, инвалидирует лишь связанные согласия.
5. **Предварительный отчёт:** покрытие глав/событий, пропущенные роли, противоречия, ожидаемые лимиты актов/сцен/времени/каталога, статус offline/Z.ai, примерное число bounded пакетов и возможных повторов; никаких облачных расходов до явного согласия.

### Авторство книги по актам — единый возобновляемый процесс
6. **Разбивка на акты/окна:** окна по цитатам с bounded бюджетом, полный список событий, источниковые эпизоды и сюжетные связи. При >12 актов работать пачками, передавать по цепочке доказанные факты, NPC память и последствия. 48/192/160 KiB не должны превращаться в молчаливое усечение.
7. **Логика и развилки:** CANON — утверждённый порядок и один источник-финал; ALTER_FATE — альтернативные ветви после разрешённой точки расхождения; будущий FREE_WORLD — собственная world bible. Проверять исходную мотивацию, хронологию, непротиворечивость знаний, условия выбора, циклы без выхода, обязательные события, конечные исходы.
8. **Персонажи, NPC и диалоги:** опциональные 0/1/много NPC; карточки с identity, алиасами, безопасными биографиями, характером, целью, манерой речи; реальная встреча/местоположение/life state, направленное отношение, witness, обещания, память; реплика с `character_id`, source knowledge, причиной и timestamp, не подставлять портрет по тексту имени.
9. **Игровые ресурсы:** характеристики, предметы, исходное владение, перемещения NPC↔player, получение/расход, правила по фактам/флагам/времени, подсказки об открытых и закрытых действиях, рассказанные сцены. Не создавать предмет за счёт текста модели.
10. **Литературная подача:** независимые повествование, диалоги и ответы героя. Все тексты проверяются/сохраняются с digest; художественный рендер не меняет условия, источники и `StoryWorld`.
11. **Изображения:** обложка, иллюстрация, портрет, карта, предмет, локация с source reviewed media reference/asset provenance и spoiler policy. Не включать произвольные пути/API или опасные media; отсутствующие картинки → читаемая заглушка.

### Проверка, сборка, игра
12. **Строгая локальная проверка:** одна машина правил: source coverage/citations, aliases/knowledge, chronology, NPC social, предметы, item custody, effect provenance, выборы/выходы/циклы, reachability, обе/одна развязки по выбранному режиму; структурированные ошибки «акт → сцена → условие → исправить», без утраты сохранённых редакций.
13. **Предпросмотр игры** на выбранном реальном `story_core`/rich import с безопасным журналом, а не на отдельном preview-engine.
14. **Сборка** `.bworld` через ОДИН `bookworld_format` с versioned contracts и независимым импортом/self-check, источник и фактическая модель авторства явно записаны в provenance (совместимые `none` для legacy где обязательно).
15. **Установка и игра:** та же библиотека, separate campaigns, `WorldPlayPage` с героем/предметами/журналом/NPC/диалогами, offline, сохранением SQLite, fork, export/import `.bwsave`. Для private game не требовать GLM на устройстве. Игрок видит отличие свободного текста-матчинга от будущего dynamic AI-master.
16. **Возвращение:** на каждом шаге точный независимый checkpoint с fingerprint, revision/digest, editor approves, interrupted/resume, rollback при неполной записи; выбор новой главы или модели не теряет подтверждённый материал.

## 3. Роли ИИ — полный перечень и границы доверия

| Этап | Что вправе предложить Z.ai/GLM 4.7 Flash или альтернативный провайдер | Что всегда проверяет автономная часть |
|---|---|---|
| Анализ книги | кандидаты NPC/мест/фактов/событий, альтернативные имена | точная цитата, позиция и статус гипотезы; подтверждение человека |
| Литература и история | хронология, мотивы, последствия, CANON-план, альтернативный сюжет | source-linked проверка причинности и редакторский смысл |
| RPG-сценарий | сцены, выборы, NPC диалоги, ответы героя, художественная проза | допустимые typed choice/effects/knowledge, item custody, терминалы и циклы, подписанные цитаты |
| Визуальные описания | внешность, портретный промпт, назначение локального изображения | режимы spoiler-safe, права, тип медиа, пользовательское согласие |
| Игра в момент прохождения | **сейчас** только сопоставление текста с signed allowed `choice_id` | `story_core.apply`, состояние SQLite, no prompt-as-code. Будущий динамический режим — только через новый sandbox/typed validator |

**Сеть и consent:** до каждого bounded запроса показать точный набор отправляемых цитат/меток (в том числе labels!), примерную стоимость/число попыток; общий opt-in не заменяет согласие на конкретный фрагмент; 408/429/5xx/обрыв → ограниченные retry с отображением, Cancel предотвращает новые запросы, уже отправленный POST нельзя отозвать. Секретные знания NPC, чужие прохождения, ключи и файлы целиком в игровой prompt не отправлять. BYOK и offline остаются независимыми.

**Без ИИ:** индекс, локальная механика анализа, работа редактора, проверка сценария, компилятор, импорт и игра работают без сети. Нет обещания самостоятельного литературного анализа романа без какой-либо модели; офлайн-режим позволяет ручное создание/утверждение и deterministic validation. В будущем можно подключить локальную модель через отдельный Provider-порт, не импортировать сеть в core.

## 4. Границы полной автономности — не путать

- **Уже автономно:** исполнение проверенного `.bworld` и SQLite replay (`story_core`, `story_runtime_adapter`, `bookworld_format`, `campaign_manager`) без Flutter/ИИ.
- **Переносимая авторская подсистема, которую доводим:** pure-Dart `story_authoring` отвечает за импорт/индекс, исходные цитаты, сценарную валидацию, редакторские digests, фазовую сессию, deterministic build/checkpoint. Имеет CLI и тесты. `apps/story_reader` только отображает формы и предоставляет файловый/сервисный адаптер. Никаких зависимостей авторского ядра от Flutter, path_provider, shared_preferences, Z.ai, SQLite state of UI, Python/E6d.
- **API для ИИ:** интерфейс `AuthoringModelPort`, вход и ответ — сериализуемые bounded типы с source SHA и согласиями; сетевой адаптер Z.ai — за пределами core. Локальная модель может использовать тот же порт без переписывания сценарного компилятора.
- **Никакой второй реализации:** сохранить действующие source/logic types и rich-v3 writer; переносить существующие pure логические файлы, оставляя в app совместимые re-export-модули до завершения миграции. Недопустимо копировать алгоритмы и затем развивать их в двух местах. Не импортировать исходники app относительным путём из пакета.
- **Сосуществование:** legacy books/worlds/saves и работа внешнего E6d не меняются до отдельного согласования версий. Для новой версии формата обязателен версионированный миграционный маршрут и сравнение Python/Dart.

## 5. Крупные пакеты работы и определение готовности

**Функциональный пакет 1 — независимый книжный вход + совпадение UI с ядром:** переместить существующий импортёр/индекс в pure Dart `story_authoring` и дать CLI для независимой source-locked проверки/сборки; затем без дублирования основного мастера связать в один понятный процесс source/preflight/resume, 0/1/2 NPC, Герой/Предметы/Журнал/диалоги, NPC spoiler-safe, AI allowlist/payload/stop, responsive/contrast, backup. Никаких микро-PR.

**Функциональный пакет 2 — полная переносимая авторская логика и книжная семантика:** вынести `NarrativeBookModel`, StoryPlan, causal/chronology/NPC source checks, batches, reviewed roles, prose/build из Flutter в pure Dart с теми же тестами; устранить контрактные ограничения масштабирования, стартовых знаний/вещей, времени и CANON/ALTER_FATE; добавить model-provider adapter. Крупная готовая книга → один validated `.bworld` из CLI и приложения, без зависимости core от Flutter.

**Один итоговый gate:** Flutter <-> CLI побайтовое совпадение source fingerprint/проверенных пакетов, независимый rich-v3 import/Python parity, две разные настоящие RU FB2 с ручной проверкой событий/мотивов, 0/1/2 NPC, исходный и альтернативный финалы, 24/48/>192 сцены без потерь или честный fail, циклы/знания/передача вещей, real GLM/429/offline, SQLite fork/export/import, Windows/Android 280–600dp/200%/TalkBack/Narrator/3×4 палитры, exact HEAD CI+M0. После — закрытие P0/Issue #118 и merge Draft #133; не раньше.

## 6. Как принимается каждый экран

Для любой видимой функции указать: **источник истины**, изменения state/consent, save/replay, отображаемые и скрываемые данные, ошибку/отмену, CLI parity. Если pure-Dart engine умеет действие, а путь UI к нему отсутствует — явная диагностика/включение в тот же пакет, не «готово». Если action не поддержан ни format, ни core — скрыть или пометить планируемым.

**Текущее решение:** этот проект дизайна фиксируется ДО реализации единого мастера. Начать с независимой source-locked авторской основы; графические экраны создавать после фиксации режима, контракта и критериев проверки каждого шага.
