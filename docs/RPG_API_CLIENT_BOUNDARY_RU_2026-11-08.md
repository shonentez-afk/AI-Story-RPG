# AI Story RPG — движок как API, Flutter как один из клиентов

**Решение 8 ноября 2026:** весь RPG-движок предоставляет публичный независимый API. Flutter — клиент этого API, а не владелец игровых правил. Сетевой сервис не обязателен; если понадобится, появится отдельный HTTP/gRPC адаптер, использующий те же правила.

## Уже реализованная граница

```text
   Flutter UI          Dart CLI          future native/web/HTTP adapter
       |                   |                          |
       +-------------------+--------------------------+
                           |
                    packages/rpg_api
                      API contract 0.1
                  /                      \
          RpgGameApi                 RpgAuthoringApi
               |                           |
         rpg_gameplay                 story_authoring
               |                           |
       campaign_manager              bookworld_format
               |                           |
          story_core  <---- единственный источник правил
```

**В коде этого пакета:** новый pure-Dart `packages/rpg_api` без Flutter; `LocalRpgGameApi` делегирует операции к текущему `RpgGameplayEngine`, `LocalRpgAuthoringApi` — к `BookAuthoringEngine`, `OfflineBookAnalyzer` и проверенному `PortableReviewedDraftCompiler`. Нет второго runtime, нового формата, нового файлового хранилища и новых правил.

Клиент предоставляет приватную SQLite (и управляет временем жизни), пути/планировщик isolate, интерфейс, согласия, ключи и опциональный облачный транспорт. API **никогда** не запрашивает ключи и не выполняет HTTP. Flutter `DeviceWorldLibraryGateway` и worker импорта/индекса книги используют новый API; остальные экраны будут переведены без ломки старых интерфейсов.

## Чего пока нет и что не нужно обещать

Самостоятельная компиляция из **проверенных** данных есть, но полный автоматический книжный CANON, формальная поддержка всех ролей, свободное создание новых действий AI-GM и готовый пользовательский book-to-RPG workflow пока отсутствуют. Наличие API v0.1 не устраняет эти функциональные ограничения.

## Выполненный пакет разделения authoring-логики

Реализации `NpcContinuityAudit`, `DraftSceneGraphOverview`,
`CrossActSourceEvidencePacket`, `PreparationReadinessReport` перенесены из
Flutter в `story_authoring` **без изменения алгоритмов**; локальные файлы
клиента — переэкспорты. Добавлен офлайн `BookToRpgWorkflow`, который выбирает
точную исходную редакцию/отдельную сказку, делает resumable scan и формирует
готовность с обязательной редакторской проверкой. `RpgAuthoringApi` предоставляет
эти операции другим клиентам. Чистые NPC/graph-тесты перенесены в
`story_authoring/test` в дополнение к существующим Flutter widget-тестам.
Граница импортов теперь отвергает возврат этих правил во Flutter.

## Проверяемые ИИ-предложения без Flutter

В `story_authoring` перенесены четыре проверки ответов модели и их промпты.
`rpg_api` предоставляет `RpgProposalReviewApi`, а Flutter оставляет
ключи, сетевой транспорт и явное согласие. Подробности:
[docs/RPG_AI_PROPOSAL_CONTRACT_RU_2026-11-09.md](RPG_AI_PROPOSAL_CONTRACT_RU_2026-11-09.md).
