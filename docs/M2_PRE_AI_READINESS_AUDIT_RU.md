## Главный вывод

Кнопка «Подготовить к RPG» — пока индекс/локальные предположения, а НЕ
завершённый Book Compiler. Нельзя сначала просто включить API модели.
Модель сможет высказать предположения; для создания игры ещё должны существовать
законченный семантический слой, редактор канона, валидатор причинности,
компилятор и импортёр пригодного для игры пакета. Этапы ниже не должны
повторно создавать библиотеку, импорт и файловые форматы сейвов.

## Реализация текущего изолированного подэтапа (без ИИ)

1. `source_semantic_catalog.dart`: типизированные утверждения
   EVENT/FACT/CHARACTER/LOCATION/RELATION/ALIAS, несколько source evidence IDs,
   субъект/предикат/объект, narrator/reported/uncertain, polarity и textual time,
   строгая сериализация/десериализация и точная проверка исходных цитат.
   Локальные факты/события берутся только из ранее выделенных M2b3b citations.
   **Статус остаётся INFERRED**, противоречия только POSSIBLE, никакой автоматической идентичности.
2. `intermediate_story_blueprint.dart`: структурированный, ограниченный черновик
   сценария, с links к проверенному каталогу/источнику; spoiler gate не позволяет
   использовать цитату из будущей главы. Все изменения игрового состояния —
   только декларативные sets/requires/forbids и ID из отдельного реестра.
3. Причинная симуляция по (сцена, набор флагов): проверка корректных переходов,
   двух достижимых концовок, softlocks и циклов без достижимого окончания,
   невозможности сохранить каноническую сцену после предотвращённой причины.
4. Права и пакет ещё **НЕ принимаются**: `canPublishBookworld=false`;
   никакого silent export при «успешной причинности». Отсутствие реальной
   semantic-модели не скрывается.

## Обязательные следующие работы до включения реального ИИ

**P0 — финальный pre-AI контракт:**
- Негативные тесты на ложные цитаты, чужую редакцию, идентичность, противоречия,
  цитаты будущих глав, сценарные deadlocks, отсутствие концовок/условия веток.
- Отдельное хранилище промежуточного сценария с versioned schema и отменой,
  независимое от `.bwsave` и оригинального текста.
- Редактор канона и решения пользователя: `цитата найдена` / `событие подтверждено`
  / `связь установлена` / `дополнение игрового автора`. Все четыре статуса НЕ одно и то же.
- Проверка прав использования для личной игры и публикации адаптации: личная
  обработка не даёт автоматических прав на общую библиотеку.
- M2d: сборка/проверка **настоящего** пользовательского .bworld и реальная
  игра на Windows и Android; старые .bworld и saves продолжать читать.
- Полностью автоматизировать повторный проход, сохраняя явные review gates,
  не заставляя игрока нажимать «24 фрагмента» много раз.
- Экспорт отчёта: 100% главы по тексту отдельно от coverage событий,
  0 — если семантический анализ не проведён; численные unmet gates.

**P1 — подключение ИИ после P0:**
- Использовать один SourceSemanticProvider интерфейс, не смешивая генерацию текста
  с записью `BookWorld`; валидировать структурированный JSON по точным цитатам.
- Выбрать provider Z.ai GLM BYOK/локальный при готовности, без скрытого fallback.
  Просить отдельное согласие на удалённую обработку и учитывать права.
- Сначала сравнительная QA на 10+ оригинальных рассказах с фиксацией precision/
  recall, зависимости от длинных глав, идентичность/тайны; затем настоящая книга.
- Ввести лимиты токенов/денег/запросов, resume после 429/сети/перезагрузки,
  корректную отмену и явные статусы.
- ИИ-текст никогда не меняет state без typed rule validation; без ИИ уже
  подготовленный CLASSIC путь обязателен.

## Границы приёмки текущей PR

Не изменять `BookStorage`, `CampaignStore`, `world.sqlite` и существующие
M2b checkpoints. Никаких model/API tokens и копий текста в публичном GitHub.

После мержа отдельный push(main) CI и реальный Release. Device E2E и длинные книги — SKIP
до отдельной явной проверки. Этот этап — **не полная реализация M2b4b/M2c**,
а строгое основание для неё.
