## Достоверность и текущий объём

- `overview.json` — проверенная по исходникам **обзорная выборка из 12 элементов и 12 взаимодействий**; это не полный граф репозитория.
- [`codegraph.json`](codegraph.json) — уже созданный CI полный статический индекс **906 отслеживаемых файлов, 692 файла кода, 7 379 узлов, 14 320 связей** (включая 5 796 недоказанных кандидатов вызовов). Обновляется проверкой GitHub Actions на этой документационной ветке.
- `tools/architecture_map/generate.py` — read-only индексатор, который воспроизводит полный каталог отслеживаемых файлов и граф локальных импортов / определений. Он не требует GitNexus.
- В исходном индексе Python разбирается через `ast`, а Dart — консервативно лексически. **Дополнительно запущен настоящий GitNexus 1.6.12 с Tree-sitter**, который подтвердил 12 058 узлов, 36 026 связей, 316 групп и 726 частично ограниченных потоков; 9 581 связь имеет тип `CALLS`. Из 8 748 строк CALLS с оценкой ≥0,7 в [`gitnexus_calls.json`](gitnexus_calls.json) перенесено **6 127 уникальных проверяемых связей** между 2 944 определениями (прочие строки отброшены без подтверждаемого пути или строки). Эти связи смешаны с предыдущим индексом без второй конкурирующей карты; точные callsite-строки не доказаны, ссылки ведут на объявления caller/callee. Лексические кандидаты показаны отдельно.
- Узлы содержат путь, строку и ссылку с закреплённым SHA; связи содержат отдельные подтверждающие строки.
- Литературная CANON-функциональность, поведение ИИ и согласование всех экранов **не объявляются завершёнными** на основании графа.

## Модель LikeC4

Один исходник архитектуры: [model.c4](model.c4), её представления: [views.c4](views.c4). В режиме **Архитектура** используется **настоящий LikeC4 Web Component**, генерируемый из `model.c4` и `views.c4`; четыре проекции доступны в одном окне. Режим **Связи кода** использует отдельный SVG-граф внутри того же интерфейса. LikeC4 валидируется CLI в GitHub Actions.

## Создание полного исходного индекса

```sh
python3 tools/architecture_map/generate.py \
  --root . \
  --base-sha 9e5c11eb4dc8c5fd70cd588baca4d3c12e565dbc \
  --out docs/architecture-map/codegraph.json
python3 -m unittest discover -s tools/architecture_map/tests -v
```

Это создаёт JSON с `fileCatalog` (все отслеживаемые файлы), `codeInventory` (проверочные SHA256, строки, языки), `nodes` (файлы/объявления), `edges` (статические импорты, файл→объявление и **кандидаты** вызова). Кандидаты не должны представляться доказанными вызовами без разрешения по типам/AST. Для полноценного Dart AST следует подключить Dart analyzer; для Rust/Java/JS — соответствующие парсеры. Реальный GitNexus использован; исходный индекс остаётся независимым и воспроизводимым без него.

## Примеры проверенных цепочек

**Игровой ход.** Flutter `world_library_gateway.dart:27-72` открывает независимую `LocalRpgGameApi` в isolate. API `rpg_api.dart:109-158` делегирует `RpgGameplayEngine`. `rpg_gameplay.dart:827-841` вызывает `BookworldCampaignStore.commitChoice` и возвращает обновлённую проекцию; `campaign_manager.dart:335-380` восстанавливает `StoryEngineCoordinator` из журналируемых событий с проверкой последовательности и хэшей. Это проверяемая связка, но не доказательство успешного E2E на устройстве.

**Подготовка книги.** `book_to_rpg_workflow.dart:69-139` выполняет `BookImporter.parse` → `BookAuthoringEngine.indexImported` → `OfflineBookAnalyzer.scan` → `PortableReviewedDraftCompiler.build`, с проверкой неизменности fingerprint, охвата chunks и авторской редакции. Успех подготовки не доказывает литературный CANON.

**Локальный HTTP.** `rpg_loopback_server.dart:25-112` привязывает сервер к loopback IPv4, требует длинный токен, обрабатывает запросы последовательно. `client_protocol.dart:31-57` возвращает коды ошибок без локальных данных и текста книги.

## Что ещё не подтверждено

1. GitNexus извлёк высокодостоверные статические связи, но **не доказал runtime-выполнение**, полную динамическую диспетчеризацию или точные строки каждого вызова. Сообщены ограничения глубины трассировки и число пропущенных кандидатов.
2. Для тех Dart-символов, где GitNexus не установил связь, остаётся лексический fallback, явно помеченный как кандидат; отсутствие связи не доказывает отсутствие реализации.
3. Автоматические проверки: Python tests, JS syntax, LikeC4 CLI/Web Component, Graph invariants, Chromium Playwright. Результат для текущего коммита проверяется в GitHub Actions.
4. Публикация GitHub Pages требует включения Pages администратором репозитория; доступность альтернативного статического HTTP-просмотра отдельно проверяется в CI.

**Не выдавать статический граф и генерацию модели за доказательство завершения движка, CANON или E2E на реальном устройстве.**
