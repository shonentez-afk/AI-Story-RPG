# CANON ↔ ALTER_FATE: литературные причинные обязательства и свободные NPC-действия

9 ноября 2026. Единый большой пакет Draft PR #133. Источник: отдельный source-reviewed private BookWorld v5. **Не объявлять полностью готовым, пока exact-code CI и платформенные сборки не завершились SUCCESS.**

## Что действительно добавлено к уже существующему literal CANON v5

Ранее v5 сохранял весь текст книги слово в слово и разрешал только локальные свободные игровые эффекты \`gm_*\`: предметы, факты игрока, статистику и флаги. Его единственное обычное сюжетное решение означало «Продолжить книгу»; ни предупреждение NPC, ни изменение доверия не влияли на следующий источник.

Теперь из уже подтверждённого private literal CANON автор может создать НОВЫЙ совместимый v5-архив с редакционно проверенными причинными обязательствами. Отдельный контракт \`ai_story_source_causal_review_v1\` содержит:
- SHA256 точного исходного архива, fingerprint той же редакции, явное согласие человека и неповышаемую отметку \`semantic_canon_automatically_verified=false\`;
- постоянный \`npc_<32 hex>\`, видимое имя, точное source-reference SHA сцены, \`present\` или \`reported\`; разрешение общаться даёт только \`present\` в уже достигнутой сцене;
- для конкретной БУДУЩЕЙ исходной сцены — утверждённую цитату и запрет конкретного \`gm_*\` воспоминания или пределы доверия NPC. Это редакторское утверждение о литературной причинности, **не семантический вывод автоматически из текста книги**.

\`ReviewedCanonCausalBookworldWriter\` не переписывает литературный текст и не меняет исходную библиотеку/сохранения. Он создаёт отдельный private BookWorld v5 с собственной идентичностью и byte-verified именем/источником. \`CanonCausalContract.inspect\` повторно проверяет source quote, permanent actor, наличие в сцене, подпись, согласие и типы. Не существует «API для создания нового неизвестного NPC» из LLM-ответа.

## Живое игровое действие и последствия

Новый \`FreeformActionDraft\` из Z.ai — **недоверенный JSON-кандидат**: \`player_text\`, \`narration\`, \`effects\`, опционально \`npc_interaction\` и \`plot_intent\`. Интервенция описывает строго подтверждённого NPC, \`gm_*\` memory ID, тип memory, направленное изменение trust в диапазоне [-10..10], новую игровую цель \`gm_*\` (или null). Только \`story_core\` может принять этот переход. Отсутствующий, неизвестный, умерший NPC, закрытый источник, неподтверждённое присутствие, чужой факт/секрет или устаревший state hash не меняют игру.

Независимый \`NpcSocialLedger\` строит directed trust, память/цели и жизненный статус из хеш-цепочки **совершённых** действий. Сам текст модели не считается свидетельством. \`NpcCanonInvariant\` связывает будущую исходную сцену с редакционно подтверждённым обязательством: запрещённое знание, минимум/максимум доверия. Если действие нарушило обязательство, \`StoryWorld.applyFreeform\` создаёт \`AlternateNarrativeScene\` (текст + новый ID + terminal), сохраняет её в \`WorldState\` и меняет текущее состояние прохождения на \`ALTER_FATE\`. Предыдущая сцена книги остаётся исходной опорой replay, будущий текст **не выдается за канон**. Каждое следующее свободное действие продолжает свою собственную новую сцену и историю, вплоть до \`plot_intent=end\` (недопустим до ухода из CANON).

Новая сцена, NPC memory/goal/trust, событийный hash/stateHash, каждый шаг SQLite и переносимый \`.bwsave\` воспроизводятся через тот же автономный \`story_core → story_runtime_adapter → campaign_manager\`, без альтернативного Python или Flutter rule engine. Старые \`.bworld/.bwsave\` не получили обязательных полей и сохраняют старые хеши.

## Другие клиенты и UI

\`LocalRpgLiteralCanonApi.compileReviewedCausality\` доступен Dart. JSON/HTTP протокол предоставляет \`compile_reviewed_causal_canon\`, далее существующие \`install_world\`, \`start\`, \`preview_dynamic_action\`, \`commit_dynamic_action\`, \`choose\`, \`export_save\`, \`import_save\`. Projected status: \`active_plot_mode\`, \`source_reviewed_npc_targets\`, \`npc_encountered[].current_private_goal\`, плюс прежние \`source_literal_canon\`, \`gm_action_palette\`, counters/journal.

Flutter не определяет, кто из NPC доступен или что является CANON: только показывает статус, подпись текущей сцены и разрешённые движком действия. Z.ai получает только видимый текущий фрагмент, до 5 совершённых вымышленных действий и уже достигнутых авторизованных NPC (имя, trust, количество memory, игровая цель). Требуются отдельное согласие на отправку и отдельное подтверждение на сам коммит. В неизменённом режиме без \`canon_causality\` эффекты ИИ работают как раньше; попытка создать NPC memory без авторского контракта закрывается.

## Крупная приёмка

Обязательна цепочка: полный исходный TXT/FB2 → literal v5 → редакционно подтверждённая Анна в первой сцене + цитата будущего исходного события → новый одобренный v5 → предупреждение Анны → trust +4, memory, goal → законный автоматический CANON→ALTER_FATE → следующее действие, trust +3 и другая цель → собственное завершение альтернативы → полное восстановление из портативного save в независимой SQLite → тот же stateHash, NPC и сюжет. Также тест через JSON-клиент и отрицательные тесты на поддельного NPC, неподписанный источник, старое согласие, недопустимое раннее завершение, запрет старого канонического выбора.

**Честное ограничение:** наличие этих правил НЕ означает автоматического литературоведческого анализа каждой мотивации произвольной книги. Для историй без редакционно проверенных NPC/source-предпосылок генератор не имеет права объявлять это \`source-wide literary causality proven\`. ИИ не создаёт полные новые книжные причины, пока нет новых проверяемых source obligations. В тестовом пакете закрепляется одна строгая причинная цепочка как архитектурная приёмка; на двух реальных больших русских FB2 и реальных устройствах её следует проверять отдельно. Это ограничение отражать в capability и handoff, не маскировать флагом "всё".
