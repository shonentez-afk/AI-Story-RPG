## Целевая навигация и UX (сначала согласовать, затем код)

**Библиотека → «Создать RPG» → Подготовка → Проверка готовности → Герой/режим → Кампания → Игра → Сохранение/продолжение.**

- На входе честно различать: **быстрая офлайн-проба**, **обычная подготовленная RPG / ALTER_FATE**, **буквальный CANON без смыслового анализа**, **полный проверенный source-causal CANON/ALTER_FATE** (последний только при наличии проверенного reviewed v5, полученного из E6q.1/импорта). Не называть буквальный источник «полная сюжетная причинность». Варианты не поддерживаются — объяснять и отключать.
- Подготовка полного reviewed v5 должна учитывать текущую архитектуру **ChatGPT Skill-first E6q.1 как внешний автор**. Не изображать встроенный Z.ai-вызов тем же генератором и не обещать автоматическую работу Skill внутри телефона. До реальной встроенной интеграции обеспечить ясный поддерживаемый путь импорта готового `.bworld` с проверкой, источником и режимом; вариант будущей интеграции проектировать как отдельный адаптер авторства, не как движок.
- Роль (ORIGINAL / PROTAGONIST / EXISTING) и режим (CANON / ALTER_FATE / доступная классика / динамический AI) выбирать **по фактическим возможностям установленного мира** и подтверждённым исходным данным. Не включать неподдерживаемые комбинации и не изобретать персонажа из отображаемого имени.
- Игровая страница: источник + режим + текущая сцена + подписанный диалог + разрешённые действия + свободный ввод (при поддержке) + компактная **постоянно доступная** панель Герой / Предметы / Журнал / NPC. Оформление адаптировать под 320–360dp/200% scale, планшет и Windows; верхние инструменты по правилам читателя, но доступ к игровым панелям и состоянию не теряется.
- Информационные панели сохранять отдельными, лаконичными, без внутренних `gm_*`/UUID по умолчанию. Техническая информация — в явном «Диагностика» и только по запросу.

## Матрица возможности → UI → контракт

| Функция core/API | Пользовательское представление | Источник истины / правило |
|---|---|---|
| Герой, роль, характеристики, знания и время | Герой: портрет/имя при наличии, роль, текущие факты, параметры, история личных изменений | `WorldGameView.heroName, heroDescription, heroSourceCharacterId, stats, knownFacts, tick, sourceReviewedHeroStart`; неизвестное не выдумывать |
| Инвентарь, владение, передача и расход | Предметы: карманы героя, подтверждённое владение встреченных NPC, свойства и контекстные доступные действия | `inventory, npcItemOwners, itemNames, itemDescriptions, choices`; никаких оптимистичных drag/drop без typed preview |
| Подтверждённые решения и последствия | Журнал: хронология, изменение состояния по каждому ходу, источник (книга/игровая вставка), фильтр важных причин и NPC | `journal, sceneSource, activePlotMode`, только committed/replayed |
| NPC-отношения и знания | NPC: карточки встреченных героев, доверие, память, состояние, текущая цель, открытые обещания, самостоятельные решения и имущество | `npcRelations.currentGoal, openPromiseIds, autonomousDecisionIds, memoryKinds, lifeState`; не раскрывать невстреченных |
| Литературный CANON и альтернативы | Постоянный ясный режим CANON / ALTER_FATE; явный момент смены и причина, без переписывания книжной прозы | `activePlotMode, sourceLiteralCanon, sceneSource, journal` |
| Долгосрочная альтернативная линия | Журнал/сюжет: текущая ветка, её цель, открытые обязательства, допустимые направления, финал только после подтверждённых последствий | `alternatePlotContinuity`; не обещать автоматический литературный планировщик без правил |
| Подписанные диалоги и портреты | Читаемый диалог, поочерёдные говорящие, история, локальные портреты по actor ID, «пропустить» с корректными гейтами | `sceneDialogueTurns, sceneSpeakerIdentityReviewed, visibleSpeakerActorIds` |
| Свободное действие и последствия | Одна понятная форма; перед confirm показать место, персонажа, доверие, обещание, предмет/факт, цель, сюжетный маршрут, риск для CANON; после подтверждения — снимок из нового view | `WorldDynamicActionGateway.previewDynamic/commitDynamic`, `FreeformActionDraft.effects/npcInteraction/plotBeat`; нет эффекта до commit |
| Выбор и запреты | «Ваш выбор»: доступные/недоступные решения с понятной причиной, никогда не проигрывать неподтверждённый ход | `choices.enabled, lockReason, revision, stateHash` |
| Несколько прохождений/ветки и перенос | Список кампаний по каждому миру, ответвление, экспорт/импорт `.bwsave`, ошибки конфликтов и повторное открытие | `WorldLibraryGateway` и SQLite; не копировать состояние Flutter в отдельное сохранение |
| Подготовка / импорт | Готовность исходного мира, поддерживаемые роли и режимы, полный/частичный статус source-review, честное «черновик», «готовый пакет», «пробная игра» | `LocalRpgWorldIntakeApi`, исходные сертификаты и одобренный author review; не показывать `semantic_canon_automatically_verified=true` по одному SHA |

## Единая UI-приёмка (блокирующий gate до литературного QA)

1. **Все реализованные свойства видимы:** проверенные NPC-цели, обещания, автономные решения; инвентарь/владение; сгенерированные альтернативные обязательства/маршруты; источник каждого результата. На 320/360dp и 200% шрифте ни один элемент не недоступен.
2. **Свободный ввод:** предупреждение о ловушке → после commit доверие/память/цель видны в карточке NPC и журнале; через несколько ходов отложенное решение видно; неверный ход preview НЕ меняет состояние, повторный запрос после сети не дублирует событие.
3. **CANON→ALTER_FATE:** корректный источник + причина разрыва + альтернативная цель, события книги не выдаются за новые; закрыть обязательство одной прозой нельзя, а подтверждённым эффектом можно.
4. **Портреты:** верный actor ID, не появляются до источниково проверенной встречи; дубли имен не раскрывают чужой портрет. Многосерийные диалоги и пролистывание на телефоне/Windows.
5. **Создание:** человек без JSON/CLI/идентификаторов понимает, где офлайн-проба, буквальный CANON, уже подготовленная source-causal игра и полная AI-подготовка; неуспех и отмена не повреждают книгу, подготовку или кампанию.
6. **Сохранения/команды:** воспроизводимый SQLite stateHash, импорт/экспорт между клиентами; обновление/перезапуск UI не создаёт второго состояния; старые worlds и .bwsave остаются доступны.
7. **Визуальный QA:** настоящий Flutter render при светлой/тёмной темах, масштабах, длинном русском тексте, широком экране Windows, мобильных кнопках и полноэкранном чтении. Отдельные screenshot QA и перечень фактически проверенных устройств, не заявлять физический QA по виджет-тестам.
