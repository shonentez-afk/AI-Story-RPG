# M2g3f.2b.5 — постоянный character_id адресата отношений NPC

Дата: 2026-11-06. База: main 641fabbcd32ff8491ebf83d8c6e6a8f7a03efc48. Статус: PR #127 MERGED в main (`4cfdab1147`); exact-head CI #804, M0 #889, Windows/Android и независимый Dart CLI — SUCCESS. Post-merge main CI #805/M0 #890 перепроверить.

## Что изменилось

- `NpcDraftNote` получил необязательное `target_character_id` в существующем локальном авторском notebook. Это **не** новый независимый NPC-профиль.
- Только новые связи, созданные из UI, выбирают другого персонажа с сохранённой полной карточкой и постоянным ID. Сохраняется и исходный `target_dossier_id` + digest подтверждённой группы упоминаний.
- При чтении и перед записью валидатор требует, чтобы сохранённый `target_character_id` совпадал с ID фактического профиля адресата. Переименование, редактирование внешности/мотивации и псевдонимов связь не переназначают. Подмена ID, удаление профиля адресата или изменение подтверждённой группы блокируются.
- Старые заметки без `target_character_id` читаются по прежним source-bound правилам и явно помечаются как неприкреплённые к постоянному ID. **Никакой молчаливой миграции по имени.**
- Сохранение остаётся частным и локальным, без отправки в GLM и без автоматической публикации в BookWorld.

## Тесты

`apps/story_reader/test/npc_editorial_notebook_test.dart`: roundtrip постоянной связи, переименование цели, отклонение чужого/отсутствующего ID, запрет целевого ID у нереляционных заметок. Приёмка: точный GitHub CI Flutter, Dart/Python, Windows и Android + post-merge.

## Что ещё не реализовано

Это только адресация **редакторских отношений**. Не существует автоматического графа отношений всей книги, отдельного provenance каждого поля, полноценного `speaker -> character_id`, ветвевых knowledge gates для всей книги, встроенного NPC каталога `.bworld` или произвольного AI-диалога. Ветка внешнего E6d не изменялась. Следующая задача — валидируемая привязка имён говорящих и source mention groups к постоянным ID, затем полная книга CANON/ALTER_FATE и реальный FB2/GLM E2E.

## Укрупнение пакета: M2g3f.2b.6 — источник → идентичность говорящего (только проверка)

В том же PR #127 реализован `SourceLockedDialogueSpeakerAudit.bindReviewedCharacterIds`. Вход: точный `sourceFingerprint`, source-locked `NarrativeCharacter` с уникальными `mentionGroupId`/`citationIds`, сохранённый приватный `NpcEditorialNotebook`. Возвращает неизменяемую проекцию `speaker -> character_id` только при однозначном источниковом соответствии, разрешённой идентичности и наличии постоянной карточки. Другие имена, совпадения двух групп, неподтверждённые личности, будущие упоминания и изменённые списки цитат остаются без привязки. Дубликаты постоянных ID и чужая редакция — ошибки.

Проверки: `source_locked_dialogue_speaker_audit_test.dart` — однозначная / неоднозначная / поздняя / непроверенная / отсутствующая личность, переименование, изменённые группы и дубль ID. Всё локально, без сети и игрового эффекта. Это **не удостоверяет текст реплики, право NPC знать секреты или CANON**. В текущем PR только контракт и тесты, автоматическое использование в сквозном генераторе, UI подтверждения и BookWorld пока отдельная P0-интеграция, не выдавать её за готовую.
