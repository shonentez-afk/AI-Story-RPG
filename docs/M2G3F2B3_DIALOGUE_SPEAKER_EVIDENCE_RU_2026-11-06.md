# M2g3f.2b.3 — говорящие, источниковые упоминания и ранние спойлеры

**Дата:** 2026-11-06. **Ветка:** `feature/m2g3f2b3-dialogue-speaker-evidence-20261106`. **Статус:** ожидает exact-head CI и принятия PR.

## Цель

В `.bworld v3` уже есть проверенные структурированные реплики (PR #124), имена, портреты и история диалога. Но совпадение слова «Лена» в литературном тексте с именем NPC на экране **не устанавливает тождественность** и тем более не доказывает, что NPC мог знать/произнести конкретную информацию в этой главе. Нужна видимая безопасность до принятия художественного текста, без новых платных запросов и дополнительных двигателей.

## Изменение основной программы

Добавлен `SourceLockedDialogueSpeakerAudit.inspect` (Dart, on-device) поверх принятого `RichSceneDialogue.parse`, `NarrativeBookModel.characters` (наследует существующие проверяемые `SourceCharacterDossierIndex` и решения SAME/DIFFERENT) и `StorySituation.chapterIndex`. Использует только **реально присутствующие в текущем BookModel** источниковые группы; **не ищет по сети**, не переписывает save, не превращает имя в идентификатор игрового актёра.

Для каждого явно подписанного говорящего различает:
- нет соответствующей подтверждённой группы упоминаний;
- совпадающее имя относится к нескольким разным группам (никакого молчаливого слияния);
- единственное первое упоминание находится **после текущей главы** — возможный преждевременный спойлер;
- имя найдено не позже текущей главы, но тождественность упоминаний не подтверждена;
- группа упоминаний объединена принятыми решениями, однако слова, мотивы, владение предметами и знания всё ещё **не подтверждены**.

Заметки выводятся при повторном открытии локально закэшированного художественного черновика непосредственно на экране `SourceLockedProsePreviewPage`, перед двумя существующими подтверждениями частного использования. Никакого самостоятельного признания CANON, новых подтверждений для пользователя, новых API-вызовов и запрета художественного ALTER_FATE нет. Неатрибутированные `—` диалоги не получают произвольного говорящего.

## Проверки

- `source_locked_dialogue_speaker_audit_test.dart`: пять статусов, отсутствие присвоения NPC знаний или CANON, будущее имя до/после появления, отсутствие подтверждённых карточек и случай одинаковых имён.
- `zai_source_locked_prose_preview_test.dart`: два именованных говорящих из локально сохранённого черновика показываются с предупреждениями; **zero network POST при просмотре**.
- Требуется exact-head M0, CI Flutter + Python + Dart + контрактов, Windows + Android перед merge.

## Следующие приоритеты

Это только честная **предварительная разметка рисков**, не литературная семантическая приёмка. Чтобы получить настоящую автоматическую полную RPG:
1. M2g3f.2b.4 — для source-backed говорящих связывать точные цитаты и утверждения с проверенными персонажами, knowledge gates и event-scoped spoiler rules, а не только совпадать по имени. Без источника — явная игровая выдумка.
2. M2g3d — закончить CANON и ALTER_FATE, правильные альтернативы и продолжение без двух искусственных финалов.
3. M2g3f/g — две разные FB2 с **настоящим GLM**, в том числе короткая одно-главная сказка, private `.bworld v3`, полная игра, офлайн-прохождение и сохранение после рестарта на Windows/Android.

Ветка E6d с внешним генератором разрабатывается **другим чатом** и не менялась. Публичный `main` не содержит этот этап до успешного CI/merge. Контроль выпуска — Issue #118.
