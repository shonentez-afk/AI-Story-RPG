# M1.7.4c3 — переносимость BookWorld, предварительный replay и политика legacy

Дата: 2026-11-02. Ветка разработки: `feat/m174c3-portable-save-preflight`.
**Статус:** код и тесты внесены, новый CI необходимо проверить по фактическому SHA. Физический Android↔Windows E2E — не подтверждён.

## 1. Контракт файлов

- `.bworld`: точная исходная версия подготовленного мира, проверяемые ZIP/CRC/manifest/scene hashes. Резервный экспорт повторно проверяет установленную копию. Это не произвольный TXT/FB2 и не сценарный компилятор.
- `.bwsave v2` (`ai_story_bwsave_v2`): JSON UTF-8, <= 2 MiB; проверяемая SHA-256 envelope, идентификатор **точного** архива `world_sha256`, source campaign ID только как метаданные, полный детерминированный checkpoint/event chain. Исходная книга в сохранение не включается. Поддержан CLASSIC / CANON / PROTAGONIST.
- `.bwsave v1` (`ai_story_pilot_bwsave_v1`) — **другая схема** старой M1.6 RPG. Не переименовывать и не выдавать за v2. Оригинальная `CampaignStore/SaveStore` продолжает обслуживать такие слоты.
- Информация в `.bwsave` является пользовательской историей действий и должна передаваться как личные данные; не публиковать сохранения с приватным содержимым.

## 2. Реализованная предварительная проверка

`BookworldCampaignStore.previewPortable(text)` делает без записи:
1. Ограничение файла 2 MiB, JSON object и exact-set ключей.
2. Проверку `schema_version=2`, CLASSIC/CANON/PROTAGONIST, допустимых ID и 64-значного SHA архива.
3. Проверку SHA-256 по канонической сериализации envelope.
4. Проверку **уже установленного** exact BookWorld по SHA, структурной ZIP-целостности и blueprint hash.
5. Полную детерминированную `StoryEngineCoordinator.restore` и длину/ревизию журнала, включая его событие-head и state hash.
6. Возвращает метаданные `sourceCampaignId, worldHash, revision, stateHash, isTerminal` без создания SQLite кампании.

`DeviceWorldLibraryGateway.previewSave` дополнительно отклоняет отличный от выбранного мира hash; production выполняет работу в `Isolate.run`. UI вызывает preview **до** диалога подтверждения и показывает настоящие «Мир / Ходов / Статус / SHA мира / SHA состояния». Отмена не пишет сохранение. `importPortable` **повторно** проводит ту же проверку перед транзакцией, добавляет новую независимую кампанию с новым локальным ID и не перезаписывает старые слоты. Дубликаты импортируются как отдельные слоты, они не объединяются автоматически.

## 3. Автоматическая проверка переносимости (не устройство)

Новые тесты `campaign_manager_test.dart` используют **два разных приватных SQLite каталога**, имитируя телефон и ПК:
- на устройстве A создать 24 хода, разветвить прохождение и пройти 25-й ход;
- записать `.bworld` и `.bwsave v2` в два отдельных UTF-8/byte файла;
- в чистом устройстве B отвергнуть сохранение без соответствующего BookWorld;
- установить точный `.bworld`, выполнить preflight без записи, импортировать копию с **другим ID** и сравнить SHA состояния и 25 событий;
- закрыть/повторно открыть SQLite B, продолжить действие до 26-го хода, подтвердить неизменность 24/25-ходовых оригиналов A;
- повторный импорт исходного файла создаёт независимую копию без изменения первого восстановления; повреждение хеша не создаёт слот.

Flutter gateway-тест подтверждает read-only preflight, exact world SHA, checksum/version rejection и новый слот при импорте. Реальные USB, системное файловое окно, scoped storage, разные версии ОС и носители здесь **не испытывались**.

## 4. Ручной Android↔Windows E2E — процедура и критерии

| Шаг | Действие | Критерий приёмки | Статус |
|---|---|---|---|
| A1 | На Android импортировать подготовленный `.bworld` через единственную «Добавить книгу» | Мир появился в одной библиотеке как игровой пакет; TXT/FB2 не исчезли | SKIP |
| A2 | Создать и пройти 25+ ходов, закрыть приложение принудительно, открыть снова | Совпадают сцена, счётчик, инвентарь, журнал и ограничения | SKIP |
| A3 | Экспортировать `.bworld` и `.bwsave v2`, убедиться через файловый менеджер, что файлы видимы и читаются | Два отдельных файла фактически находятся в выбранном месте; не полагаться только на строку «сохранено» | SKIP |
| W1 | Скопировать оба файла на Windows без изменения байтов. Сначала попробовать импортировать один `.bwsave v2` | Без `.bworld` отказ без удаления/создания кампании | SKIP |
| W2 | На Windows установить **тот же** `.bworld`, выбрать импорт `.bwsave v2`, проверить preview, отменить, повторить и принять | Preview показывает 25+ ходов; отмена не меняет слоты; импорт создаёт новый слот | SKIP |
| W3 | Продолжить 1–3 хода, закрыть/повторно открыть программу, проверить fork; экспортировать обратно на Android | Не меняются прежние слоты и SHA неподвижной ветки; новый ход durable | SKIP |
| X1 | Изменить/обрезать копию `.bwsave`, заменить мир на другой SHA; в Windows изменить язык/кодировку имени файла | Повреждённый файл и другой мир отвергаются, рабочие прохождения доступны | SKIP |
| UX1 | 320dp/200%, Win Tab/Shift+Tab/Enter/Esc/F11, Android TalkBack, Windows Narrator, увеличение системного шрифта | Нет скрытых действий, фокус виден, предупреждения читаются | SKIP |
| R1 | Прервать запись/экспорт, вынуть носитель, моделировать отказ доступа; проверить наличие и восстановление backup перед удалением | Не объявлять сохранение/удаление успешным без воспроизводимого файла; не терять source | SKIP |

Результат ручного QA оформлять отдельно с моделью Android, версией Android, Windows version, хешами двух файлов, итогом каждого шага и логами, без личного содержимого.

## 5. Политика безопасной миграции M1.6 (решение на текущем этапе)

1. **Не проводить автоматическую миграцию** SharedPreferences snapshot/rulesVersion=0/1 в SQLite BookWorld: форматы и сюжетные контракты различаются. Назначить статус «сохранено в прежнем формате», а не «мигрировано».
2. Сохранять `CampaignStore`, `SaveStore`, `GameProgress`, `.bwsave v1` и импорт TXT/FB2 как независимые действующие компоненты. В «Мои прохождения» показывать старые и новые слоты вместе без внутреннего преобразования.
3. Допустить новый формат только при наличии **верифицированного** exact BookWorld и доказанной детерминированной эквивалентности runtime с полной трансляцией всех scene IDs, choices, inventories, flags и `rulesVersion`. Для старого пилота такой эквивалентности **нет**.
4. Если понадобится миграция: (a) инвентаризировать legacy read-only; (b) сделать независимые резервные копии и проверку их восстановления; (c) написать явный мигратор с rollback и двусторонними тестами; (d) только после пользовательского согласия создавать новые слоты **без удаления старых**; (e) физический QA на реальных устройствах. До такого этапа считать миграцию **SKIP/НЕ РЕАЛИЗОВАНО**.
5. Нельзя удалять `ai_story_m1_snapshot_v1`, `ai_story_campaign_v1_*` или изменять `.bwsave v1` в коде новой подсистемы.
