# M1 final — source-anchor чтения без пиксельного смещения

Дата: 2026-11-02. PR #5. Статус: новая реализация и тесты есть, финальный платформенный CI необходимо подтвердить на последнем кодовом SHA.

## Причина
Ранее `BookReaderPage` запоминал только `scrollOffset` в пикселях. После увеличения текста, смены межстрочного интервала, размера окна или поворота телефона такой offset перестаёт означать то же место в книге.

## Реализация
- В `BookReadingState` добавлены необязательные `anchorBlock` (индекс видимого блока) и `anchorFraction` (положение внутри блока 0–1). Существующие `chapter`, `scrollOffset`, `bookmarks` и имя ключа `ai_story_book_state_v1_*` сохранены. Никаких игровых слотов не мигрировали.
- `BookReaderPage` определяет первый абзац на линии просмотра, проходя **только реальные построенные** дочерние элементы ленивого `RenderSliverList`. Никакого полного рендеринга книги и никаких тысяч GlobalKey на каждую строку.
- На повторном открытии (или при изменении font/line height/chrome и системных metrics) целевой абзац становится `CustomScrollView.center`, а предшествующие абзацы остаются доступны прокруткой назад. Восстанавливается относительное положение в абзаце.
- Для прежних записей без anchor оставлен pixel-offset fallback. Повреждённые значения anchor игнорируются, позиция/закладки книги остаются доступны.
- Асинхронные загрузки настроек и позиции координируются: начальная загрузка палитры не может перезаписать старый offset нулём. Смена главы сбрасывает anchor на начало выбранной главы.
- Регрессия: unit-тесты формата, восстановление длинной главы после повторного открытия и смены типографики/ширины, живая смена размеров окна, старые записи pixel-only.

## Гарантии и границы
Это позиция внутри **распарсенного блока текущей версии книги**. Если пользователь заменит сам текст на другое издание, индекс блока может оказаться неверным: нужна будущая привязка к хешу исходной версии и контекстному отрывку в M2.0 source index. Такой переход нельзя делать молча. На физических устройствах Windows и Android, с 20 МБ FB2 и системным экранным считывателем, поведение ещё не подтверждено.

## Решение по старым игровым слотам
Пользователь уточнил: реальных прежних игр не было. Демо-сохранения M1.6 не являются предметом миграции и не требуют дополнительного защитного механизма перед M2. Их старый код остаётся тестовым/демонстрационным, но **не удаляется автоматически** при обновлении. Рабочие новые игровые миры и сохранения используют BookWorld/SQLite/v2.
