# Повторно используемые Dart-пакеты игрового движка

Не отдельный опубликованный проект. Приложение «Живая книга» — один клиент. Архитектура допускает будущее выделение собственного open-source репозитория без переписывания правил.

- `story_core`: проверенная логика мира, события, правила и постоянные ID NPC; никакого Flutter, SQLite или ИИ.
- `story_runtime_adapter`: единая точка работы со сменяемым `story_engine`; публичные `state`, `sceneId`, `sceneText`, `choices`, `events`, `choose`, `checkpoint`.
- `bookworld_format`: проверенный переносимый `.bworld` (v1, v2, v3), не произвольный код.
- `campaign_manager`: транзакционные SQLite-кампании и переносимые `.bwsave`.

## Независимый пример

CI предварительно создаёт `artifacts/bookworld/manor_m17_original_demo.bworld` стандартным компилятором. Затем:

```sh
cd packages/campaign_manager
dart pub get
dart run example/standalone_rpg.dart ../../artifacts/bookworld/manor_m17_original_demo.bworld
```

Пример выполнит проверку мира, игровые действия, изменения знаний и предметов, экспорт/импорт сохранения и воспроизведение после закрытия БД. Flutter и ИИ не используются.

Документация и ограничения: `docs/ENGINE_STANDALONE_OPEN_SOURCE_ARCHITECTURE_RU_2026-11-06.md`. Все пакеты пока `publish_to: none`; внешний репозиторий создаётся только после готовности продукта и согласованной API-стабилизации.

## Автономная игровая часть (2026-11-08)

В составе **семь** независимых Dart-пакетов. Библиотека/читалка
`apps/story_reader` теперь **клиент**, а не владелец RPG-правил.

| Пакет | Граница ответственности |
|---|---|
| `story_core` | Авторитетное состояние, переходы, знания, причинность, память NPC и идентификаторы |
| `story_runtime_adapter` | Проверенная навигация `story_engine` с атомарной синхронизацией `story_core` |
| `bookworld_format` | Проверка и упаковка `.bworld`, подписанные сцены/реплики/эффекты |
| `campaign_manager` | Транзакционная SQLite, повторные действия, `.bwsave` v2 |
| `rpg_gameplay` | **Полная RPG-проекция:** герой, сцены, разрешённые решения, NPC, доверие, социальная память, личные знания, портретная идентичность, предметы/владельцы, журнал из настоящего event replay, ограничения AI/free text и сохранение |
| `story_authoring` | Индексация FB2/источников, подготовка событий, сценариев, NPC/инвентаря, проверка достижимости, причинность, компиляция проверенной `.bworld` — без Flutter |
| `rpg_api` | **Публичная граница клиентов:** версии/контракты `RpgGameApi` и `RpgAuthoringApi`, локальная делегация в тот же движок без повторной логики |

В `apps/story_reader/lib/world_library_gateway.dart` остался исключительно
путь к каталогу данных и запуск isolate. В приложении остались экраны,
чтение, `SharedPreferences`, защищённые ключи, платформенная файловая
система, ввод игрока, согласие на запросы к Z.ai и адаптеры транспорта.
Они не выполняют причинные переходы и не выпускают утверждённые события.

**Выполняемый RPG без Flutter, без Z.ai и без приложения:**

```sh
cd packages/rpg_gameplay
dart pub get
dart analyze
dart test --reporter expanded
dart run example/standalone_gameplay.dart ../../artifacts/bookworld/book_private_rich_items_python.bworld
```

Нужный `.bworld` создаётся штатным проверенным сборщиком в CI;
самостоятельный клиент принимает один уже собранный мир. При локальном
использовании все обычные Dart-зависимости должны быть установлены.

Старый `GameProgress` и пилотный `ai_story_pilot_bwsave_v1` также
живут в `rpg_gameplay` только для совместимости со старыми
прохождениями. Это **не** замена защищённого `.bwsave` v2.

Каждый запуск CI исполняет `tools/ci_check_engine_boundaries.py` —
он запрещает зависимости движка от Flutter, клиента и незаявленных
пакетов. При этом наличие полностью автономных правил ещё **не**
доказывает полный сюжет по любой книге: CANON/ALTER_FATE,
полно-книжная причинность и живой провайдер ИИ продолжают развиваться.

## Flutter — клиент API, не центр движка

С 2026-11-08 единая входная точка клиентов — `package:rpg_api/rpg_api.dart`.
Flutter `DeviceWorldLibraryGateway` вызывает `LocalRpgGameApi`, а операции импорта/индекса изолята — `LocalRpgAuthoringApi`. Внешний клиент может использовать тот же SDK без Flutter. Полный путь авторства ещё переносится; см. `docs/RPG_API_CLIENT_BOUNDARY_RU_2026-11-08.md`.
